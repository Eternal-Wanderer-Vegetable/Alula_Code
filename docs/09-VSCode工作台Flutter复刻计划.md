# 09 · VS Code 工作台 Flutter 复刻计划

> 状态：**计划（未实施）** · 起草：2026-10-26
> 范围：把 `app/`（当前为多标签最小工作台）演进为对标 VS Code 的完整前端工作台。
> 原则服从 [01-目标与总体架构](01-目标与总体架构.md)：**低内存第一**——每个子系统
> 落地时都要过 docs/04 的内存预算护栏，不为像素级复刻牺牲资源目标。

## 0. 复刻范围界定（先说不做什么）

复刻的是 VS Code 的**工作台（workbench）布局与交互模型**，不是它的全部功能面：

| 复刻（V1 范围） | 明确不做 |
|---|---|
| 布局骨架：活动栏/侧栏/编辑器组/面板/状态栏/自定义标题栏 | Web 视图（webview）宿主 UI（Phase 2 才考虑扩展宿主） |
| 编辑器组：多标签、拆分、面包屑、拖放 | Remote/容器/Workspace-as-file 等企业特性 |
| 命令面板 + 键位系统 + 上下文菜单 | 调试器完整 UI（先留活动栏占位） |
| 侧边栏：资源管理器/搜索/Git/大纲 | 扩展市场面板（扩展级兼容属 Phase 2） |
| 面板：终端/问题/输出 | Notebook、Chat 等非编辑器场景 |
| 主题系统：VS Code JSON 主题 + 图标主题加载 | 像素级视觉复刻（结构等价即可） |

功能优先级沿用 docs/03 Phase 1 任务表；本文档只回答「工作台外壳怎么搭」。

## 1. 目标布局（对标 VS Code workbench.html 的八块结构）

```
┌──────────────────────────────────────────────────────────┐
│ ① 自定义标题栏（菜单栏内嵌，可拖动窗口）                    │
├───┬───────────────┬──────────────────────────┬───────────┤
│ ③ │ ② 侧栏         │ ④ 编辑器组区              │ ⑥ 辅助栏   │
│ 活 │ 资源管理器      │  ├ 标签条 + 面包屑         │ (可选,     │
│ 动 │ /搜索/Git/大纲 │  ├ 编辑器（code_forge）    │  V1 可缓)  │
│ 栏 │ (可折叠/可调宽) │  └ 编辑器组可再拆分(网格)  │           │
├───┴───────────────┴──────────────────────────┴───────────┤
│ ⑤ 面板区：终端/问题/输出（可折叠、可拖到编辑器区）           │
├──────────────────────────────────────────────────────────┤
│ ⑦ 状态栏：分支/同步状态 vN/诊断数/行列/编码/EOL/语言        │
└──────────────────────────────────────────────────────────┘
   ⑧ 浮层系统：通知 / 快速输入(命令面板) / 对话框 / 右键菜单 / 悬浮提示
```

## 2. 架构决策（工作台外壳层）

| 决策点 | 选型 | 理由 |
|---|---|---|
| 状态管理 | **Riverpod（codegen 免用，手写 provider）** | 细粒度 rebuild 控制是内存/流畅度前提；避免 setState 全树重建。VS Code 的 ContextKey 语义用只读 provider 表达 |
| 布局系统 | **自研 WorkbenchGrid**（VS Code 同款分级二叉网格：可嵌套 OrientationSplit） | 不引第三方分栏库：拖拽/序列化/像素预算都要自己握 |
| 布局持久化 | `~/.alula/workspace.json`（每工作区哈希区分） | 对齐 VS Code 的 workspace storage 思路，格式自简 |
| 命令系统 | `CommandRegistry`：id → {title, category, run, when}；菜单/键位/面板都引用命令 id | VS Code 的核心抽象，一次建对处处受益 |
| 键位系统 | `KeybindingRegistry`： chords + when 子句（context key 表），可被用户 keybindings.json 覆盖 | Flutter `HardwareKeyboard`/`Shortcuts` 不够表达 when 条件，必须自建分发层 |
| 标题栏/菜单 | `window_manager` 类方案自绘标题栏 + 下拉菜单 | 三平台统一观感；Windows 现阶段原生 runner 改动最小 |
| 树/列表 | 全部基于虚拟化（`ListView.builder` 语义 + 懒加载树节点） | 低内存铁律：文件树万级节点不许全量建 widget |
| 浮层 | Flutter 原生 `Overlay` + 自绘 quick input / 菜单 | 与编辑器浮层统一层级管理 |

依赖增量控制在 3 个包以内（window_manager 一类 + riverpod），其余自研——这是低内存
目标的直接推论，见 docs/04。

## 3. 里程碑分解（W1–W6，插在 docs/03 Phase 1 任务表之内）

### W1 布局骨架（外壳先立起来）
- WorkbenchGrid：水平/垂直嵌套分割、拖拽调宽高、最小尺寸钳制、折叠记忆；
- 五大区挂载：活动栏（图标切换侧栏视图）、侧栏容器、编辑器区（现有工作台迁入）、
  面板区（先放输出占位）、状态栏（现有「已同步 vN」迁入并扩展）；
- 自定义标题栏：窗口拖动/最大化/最小化/关闭，菜单栏第一版（文件/编辑/查看/帮助）；
- 布局持久化：折叠态、各区尺寸、当前视图，重启恢复。
- **验收**：拖动/折叠/重启恢复流畅；空载内存仍 ≤ 200 MiB 基线量级（mem-probe 复测对比
  `docs/baselines/`）。

### W2 编辑器组
- 标签条：溢出滚动、关闭按钮、脏标记、中键关闭、拖动排序、跨组拖动；
- 编辑器组拆分（上下/左右/2×2），同文件多组打开（VS Code 语义）；
- 面包屑（路径段 + 符号大纲接 editor-lang 的 token/符号表）；
- 与 editor-workspace 的会话恢复：重启后恢复打开的标签与未保存缓冲（journal）。
- **验收**：20 标签 + 4 组拆分下开关/切换无掉帧；内存不随标签数线性失控（虚拟化 +
  非活动组裁剪）。

### W3 命令面板 + 键位系统
- CommandRegistry + QuickInput 浮层（模糊匹配、最近使用排序、分类前缀 `>`）；
- KeybindingRegistry：默认键位表（对标 VS Code 常用集）、when 子句（editorFocus/
  sideBarFocus 等最小 context 集）、keybindings.json 覆盖；
- 全局查找文件（Ctrl+P，走 editor-workspace 文件索引）。
- **验收**：无鼠标完成「打开文件→拆分→切侧栏→关面板」全流程；键位冲突有明确解析顺序。

### W4 侧边栏视图
- 资源管理器：懒加载文件树（已有）+ 右键菜单（新建/重命名/删除/在终端打开）+ 拖放打开；
- 搜索视图：ripgrep 子进程流式结果（结果列表虚拟化，点击跳转行）；
- Git 视图：status/stage/commit/diff（CLI 封装，接 docs/03 Git 行）；
- 大纲视图：tree-sitter 符号表（editor-lang 扩展 symbol 查询）。
- **验收**：万文件仓库树滚动流畅；搜索 10 万行工程首结果 < 500ms（流式）。

### W5 面板 + 浮层系统
- 终端：PTY（`flutter_pty` 一类最小依赖）+ 虚拟化终端渲染（先 xterm 级别的最小
  VT100 子集，不自研完整模拟器）；按需创建/销毁，关闭工作区必须回收（内存铁律）；
- 问题面板：消费现有 LSP 诊断流（编辑器内波浪线并行推进）；
- 输出面板：LSP 日志/Git 日志等通道；
- 通知系统：右下角 toast + 通知中心；对话框/右键菜单/悬浮提示统一 Overlay 服务。
- **验收**：终端开合 10 次无内存增长（进程与缓冲都回收）；LSP 强杀后问题面板给出
  明确降级提示（接 docs/03 稳定性条目）。

### W6 主题系统 + 打磨
- VS Code JSON 主题解析器：workbench 颜色 token + 语义/TextMate token 色映射到
  editor-lang token 类型；**直接吃 Open VSX 主题包**（docs/03 DoD 要求）；
- 文件图标主题（最小集 + 可加载 JSON 图标主题）；
- 欢迎页/关于/设置界面（settings.json 只读渲染 + 常用项可视化）；
- 中文 IME 全工作台回归（编辑器/重命名输入/搜索框/终端），UTF-16 用例全绿。
- **验收**：导入任一深色 VS Code 主题即刻生效；IME 硬指标过（docs/03 §2.2）。

## 4. 内存与性能护栏（贯穿 W1–W6，绑 docs/04）

1. 每个里程碑合并前跑 `tools/bench` + `tools/mem-probe`，与上一基线对比，
   **回归 > 5% 必须归因或回滚**（预算意识写进 DoD）；
2. 视图不可见 = 无常驻开销：折叠的侧栏/面板释放渲染树，仅存轻量状态对象；
3. 一切长列表虚拟化；树节点 model 与 widget 分离；
4. 子进程（rg/git/pty/lsp）随视图生命周期启停，关闭工作区进程树必须清空；
5. 流畅度门槛：滚动/拖拽 60fps（devicelab 场景脚本进 `tools/bench`）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| WorkbenchGrid 拖拽+序列化复杂度超估 | W1 只做「二叉分割树」不做自由网格；序列化直接存树 |
| code_forge 选型未过人工复核（feat-002） | W2 前 complete 人工复核；不过则启动自研编辑控件预研（G1 预案） |
| 自绘标题栏与窗口控制的原生差异 | 用成熟 window_manager 包；W1 就在三平台各跑一次冒烟 |
| 终端渲染内存失控 | 限定回滚行数缓冲（如 1000 行）+ 虚拟化；压测脚本先写 |
| 键位系统与 IME 冲突（中文输入态吃键） | context key 增 inputs 感知：IME 组合中不触发全局键位 |

## 6. 与现有代码的衔接

- `app/lib/main.dart` 当前单文件工作台 → W1 起按 `lib/workbench/`（布局）、
  `lib/views/`（侧栏/面板视图）、`lib/commands/`（命令与键位）、`lib/theme/` 重组；
- 现有 bridge/editor 模块不动，继续作为编辑器内核服务层；
- 每阶段产出可运行版本并按 harness 例程登记 `feature_list.json` evidence。
