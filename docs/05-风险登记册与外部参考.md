### 2.3 现成可用的「过渡方案」（项目并行推荐试用）

- **VSCodium**：插件兼容优先时最稳妥（注意 Open VSX 与微软市场差异）；
- **Zed / Wu**：内存与流畅优先、可调整工作流时；
- 对用户当下痛点：先做 VS Code 对照诊断（03§1.1 任务 0-7）定位卡死根因
  （扩展 / GPU / 内存压力三分类），可能存在零开发成本的缓解。

## 3. 许可合规备忘

1. **微软 Visual Studio Marketplace 条款**：其分发的扩展通常仅授权 VS 产品家族使用。
   本项目**只从 Open VSX 或用户合法取得的 VSIX 安装扩展**，不接入微软市场 API。
2. **Code-OSS（MIT）**：可复用/修改/分发，保留版权与许可声明；VS Code 官方产品
   的品牌资源与服务不在此授权内，不可混用。
3. **Helix（MPL-2.0）**：文件级 copyleft——直接复制的文件须保持开源；参考设计、
   重写实现不受限。策略：**读设计，写自己的代码**。
4. **CodeForge / Re-Editor（MIT）、Lapce（Apache-2.0）、DSCode（MIT）**：宽松，
   注意保留声明；引入时在 `docs/third-party-licenses.md` 登记。
5. rust-analyzer（MIT/Apache-2.0)、clangd（Apache-2.0 with LLVM 例外)、
   basedpyright（MIT 系）、Ruff（MIT）：均为服务器进程独立运行，无链接合规风险，
   但**分发安装器/下载器时注明来源与许可**。
