# P03.4.2a：Flutter 有界 EditableText 输入适配器

状态：子切片完成；P03.4 整体仍 in-progress。

## 实现

新增 `RustTextInputField`，将 Flutter `TextField`/`EditableText` 绑定到 P03.4.1 `RustTextInputWindow`。其控制器文本受输入窗口 64 Ki UTF-16 上限约束，超限平台更新会退回最近接受值并通知宿主；Rust 版本失配/FFI 写入错误以错误回调和字段错误状态显式交给宿主。单槽待写值按 Flutter frame 回写；宿主可通过公开 state API 在保存、切换文档前 flush，也可提交或取消 preedit。

该适配器复用 Flutter `EditableText` 的 `TextInputClient` 平台通道；字段布局发生变化时，Flutter 会向平台发送 `TextInput.setEditableSizeAndTransform`，由系统输入法读取编辑框的位置/尺寸以摆放候选 UI。控件仍是独立编辑组件，本切片没有接入 workbench，也没有移除 `OpenDoc.controller` 全文镜像。

## 验证

新增 `app/test/rust_text_input_field_test.dart` 3 项 widget 测试，连同 P03.4.1 输入合同 fixture 覆盖真实 Flutter 测试输入通道和 Rust FFI：

- 获取焦点后注册原生编辑客户端；测试记录到正尺寸及非零全局偏移的 `setEditableSizeAndTransform` 参数；
- 合成 composing `TextEditingValue` 时 Rust 全文不变，平台提交后仅将候选文本作为 UTF-16 TextOps 写入 Rust；活动预编辑取消后恢复最近已提交值；
- 超出窗口上限的模拟平台输入恢复原值，Rust 全文/版本不变，宿主收到 `TextInputWindowLimitException`。

P03.4.1 与 P03.4.2a 当前共 10 项定向 Flutter 测试通过，`flutter analyze --no-pub` 零问题。`setEditableSizeAndTransform` 只证明 Flutter 到平台的编辑框几何通道已发出，不证明 WSL 的实际输入法、Windows/macOS/Linux 原生候选窗位置或 IME 焦点行为正确。没有运行实际系统 IME；产品接线和全量门禁将在 P03.4.2b/c 前后验收。
