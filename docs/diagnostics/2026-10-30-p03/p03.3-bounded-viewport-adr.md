# P03.3 控件文本所有权 ADR 与有界视口原型

日期：2026-10-30

状态：完成；决策适用于后续编辑器实现，原型尚未替换工作台控件。

## 决策

后续产品路径采用 **Rust 持有唯一完整文档文本，Flutter 按可视页读取并绘制有界文本窗口**。编辑输入通过后续短输入窗口和 Delta/IME 合同进入 Rust；绘制控件不能持有第二份完整文档。

| 候选 | 观测 | 决策 |
|---|---|---|
| 现有 `TextField` + `TextEditingController` | 输入法、光标与选择已有成熟 Flutter 行为；控制器仍持有完整字符串，当前工作台也是全文装载。 | 不作为大文档最终文本所有者。现有工作台本阶段未切换。 |
| CodeForge 11.3.0 | 本机缓存源码中的 `CodeForgeController` 实现 `DeltaTextInputClient` 且内部维护完整 Rope；`text` getter 会物化完整 Rope 文本。直接绑定 Rust 文档会形成第二个全文所有者。 | 不直接接入产品文档；仅保留为控件与输入参考。检查位置：本机 Pub 缓存 `code_forge-11.3.0/lib/code_forge/controller.dart` 中 Rope 字段和 `text` getter。 |
| Alula 有界 Rust 视口 | ABI v14 每次从同一 Rust 快照读取一页 UTF-16 行窗口；Flutter 使用虚拟列表、`SelectionArea` 和每视图有界缓存。 | 选为继续实现路径。它是只读原型，尚不是产品编辑器。 |

## ABI v14 与视口原型

- 新增 Rust `TextBuffer::read_lines_utf16`、文档注册表入口与 `alula_doc_read_lines`，Dart `AlulaDoc.readLines` 双侧握手升级到 ABI v14。
- 一次请求最多 256 行、单行窗口最少 2 且最多 65,536 UTF-16 单元；总响应预算不得超过 65,536 UTF-16 单元，并须覆盖请求行数与单行上限的最坏情况。窗口从 Rust Rope 计算；BOM 保留，LF/CRLF 分隔符不进入各行文本，水平起点落在代理对中间时回退到完整标量开头。
- `app/lib/editor/rust_document_viewport.dart` 的只读控件每页取 32 行、每行最多 2,048 UTF-16 单元，每页最多 64 Ki；每个视图最多缓存 3 页，并分别持有 `ScrollController` 与 Flutter selection scope。控件只持有 `AlulaDoc` 句柄、页面元数据和有限页面字符串，不调用 `resync()` 取全文。
- 50,000 行真实 Dart↔Rust FFI widget fixture 同屏创建同一文档的两个视图，分别滚动至 6,400、40,000、49,984 行页；末页可定位到第 49,999 行，鼠标拖选只更新左视图，两个滚动位置独立。Rust fixture 在 10,000 行文档读取尾页；真实 FFI fixture 对 100,000 UTF-16 单行从第 90,000 列读取尾部，单行输出仍有界。
