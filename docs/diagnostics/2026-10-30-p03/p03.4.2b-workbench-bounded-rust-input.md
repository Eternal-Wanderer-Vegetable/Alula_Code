# P03.4.2b：工作台有界 Rust 输入与文档状态

日期：2026-10-30
范围：P03.4.2b2 工作台输入接线、P03.4.2b3 文档命令与持久化接线

## 结果

工作台不再为每个 `OpenDoc` 保存全文 `TextEditingController`、`savedText` 或重复的 `syncText`。Rust `AlulaDoc` 是完整文本和 savepoint 的权威；Flutter 的 `RustTextInputField` 只编辑一个窗口，工作台配置上限为 16,384 UTF-16 单元。窗口以绝对 UTF-16 selection 为中心移动，输入 delta 转成 Rust `TextOp`，并同时产出 undo 所需逆操作。

输入与生命周期已接通：保存、切换标签/编辑组、关闭文档、应用 workspace edit 及销毁工作台前 flush 当前输入；组合态在这些提交边界明确提交。文档字段随窗口重建时保留同一 Flutter controller，避免重置平台文本输入客户端。超大平台粘贴作为一次 Rust 编辑提交，成功后立即用新有界窗口替换 Flutter 值；如果 Rust 版本失配，未提交草稿留在单槽恢复状态，可在窗口无冲突且绝对坐标安全时重试，冲突时保留草稿供复制。

Rust-owned savepoint 驱动 dirty 状态、保存与 journal。撤销历史保存正向和逆向 TextOp 批次，合并输入时保留各批次原始坐标顺序；正反向插入载荷都计入共享历史字符预算。超预算的大型程序化操作继续使用受原有共享预算约束的快照帧。查找/替换、大纲刷新、外部文件比较和 WorkspaceEdit 通过 Rust 文档读取或提交；为这些按需操作和脏 journal 序列化临时物化的全文不会成为每个打开文档常驻的 Flutter 镜像。undo 的兼容快照帧仍由共享字符预算约束。
