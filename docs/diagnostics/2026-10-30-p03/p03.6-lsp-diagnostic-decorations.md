## 实现范围

- LSP `publishDiagnostics` 接收路径保留原有 severity、起点、message、source，并额外保存可选 `endLine`、`endCharacter` 与发布时的可选 `documentVersion`。`alula_diagnostics` C 函数签名与 ABI 版本不变；JSON 新字段为 additive/optional，既有诊断面板字段保持不变。
- Workbench 按 Rust DocumentId 过滤诊断；只在文档版本、bounded input-window 版本及 LSP publication version 三者相等，且输入窗没有 pending/IME 文本时生成装饰。LSP line/character 按 UTF-16 口径映射到 Rust 文档绝对偏移；仅读取当前窗口可见行相关的行起点，并缓存本次转换中重复的行查询。最终 range 继续交由现有 painter 执行绝对范围裁剪和版本校验。
- Error/Warning/Information/Hint 分别使用红/黄/蓝/青色下划线。缺少 LSP 版本或结束位置的旧/不完整诊断仍留在原诊断面板，但不绘制可能过期或无范围的下划线；无效行、空范围、陈旧版本和窗口外范围会被忽略。
- 没有改动 Rust 文本 delta、Flutter TextInputClient、selection/composition、Rust 文档所有权或原生 C ABI。`Diagnostic`/reader loop 图谱命中 CRITICAL，按源码确认新增路径只解析 LSP range/version 并把绝对 range 提交给只读 painter。
