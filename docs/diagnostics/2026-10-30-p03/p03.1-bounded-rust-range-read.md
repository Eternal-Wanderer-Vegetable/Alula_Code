# P03.1 Rust 权威文档有界范围读取

日期：2026-10-30

状态：完成

阶段：P03 / feat-025 编辑器输入与绘制

范围：只增加 UTF-16 范围读取能力与 ABI v12；未替换工作台编辑控件。

## 决策与范围

Rust Rope 继续作为文档数据的权威来源。新增范围读取为 P03 可视区和短输入窗口提供底层传输；本切片没有选择最终绘制控件，也没有证明工作台已摆脱 `TextField` 全文控制器。现有 CodeForge 11.3.0 仅作为 P00.4 输入/绘制候选证据：本机锁定包的 `CodeForgeController` 拥有完整 Rope，`text` getter 会物化整份文档，直接接入不能满足 Rust 唯一文本权威的约束。P03.2 将通过实际可视区原型比较控件，而不把此结论扩大成已完成的编辑器 ADR。

Flutter 官方输入接口通过 `TextInput` 与平台输入插件异步交换 `TextEditingValue`；启用 Delta 模式时需实现 `DeltaTextInputClient`。短窗口实现仍须正确映射 selection/composing 与 Rust UTF-16 绝对位置，不能仅凭范围读 API 宣称 IME 已可用。[Flutter TextInput](https://api.flutter.dev/flutter/services/TextInput-class.html)、[Flutter DeltaTextInputClient](https://api.flutter.dev/flutter/services/DeltaTextInputClient-mixin.html)。

公开候选也留在 P03.2 实测：Re-Editor 声称面向大文本并自行实现布局/绘制，但其公开用法以 `CodeLineEditingController` 为编辑模型；这不证明它可绑定到 Rust 权威文档。[Re-Editor](https://pub.dev/packages/re_editor)。CodeMirror Flutter 0.1.1 的公开说明标为早期移植版，拥有自己的 B-tree 文档状态并以 `EditableText` 为输入基础，不能据此证明它符合本项目的有界窗口合同。[CodeMirror Flutter](https://pub.dev/packages/codemirror_flutter)。

## 实现合同

- ABI 从 v11 升至 v12，Rust/Dart 加载握手同步；新增 `alula_doc_read_range` 与 `AlulaDoc.readRange`。
- Rust 直接从 Rope 取片段，不先调用全文 `TextBuffer::text`；一次请求最多 65,536 UTF-16 单元。
- 响应携带同一快照的版本、文档 UTF-16 总长度、行数、绝对起止偏移、起点行列和文本；Dart 文档句柄同步该快照版本。
- 起始偏移必须是有效 UTF-16 边界。终点若落在代理对内部则收缩一个单元；仅请求一个 UTF-16 单元且起点是补充平面字符时返回完整字符，保证分页继续且不拆标量。
- 保留 BOM 和 CRLF 原文。超长单行可通过后续偏移分页；超过每次请求上限或起点落在代理对中间时返回明确错误。
- 既有 open/apply/resync/save/workspace-edit 路径和写入合同未改动。
