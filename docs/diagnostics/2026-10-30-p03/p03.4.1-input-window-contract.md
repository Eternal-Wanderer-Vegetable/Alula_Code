# P03.4.1：有界 Flutter 输入会话合同

状态：子切片完成；P03.4 整体仍 in-progress。

## 实现选择

新增 `RustTextInputWindow`，作为 P03.3 Rust 有界视口与未来 `EditableText` 输入适配器之间的协议边界。它只从 Rust 读取最多 64 Ki UTF-16 的窗口，在该窗口里计算文本变更；写入 Rust 时给局部 TextOps 偏移加上窗口的绝对 UTF-16 起点。它不读取或保存整篇文档。

IME 组合态保留在 Flutter 侧作为临时 overlay。预编辑值携带 Flutter 窗口内的 selection/composition 和对应的 Rust 替换范围，但不会提前改写 Rust 文档或向文档版本推进。平台提交后，单次将最终增量提交到 Rust；取消时 `cancelComposition()` 返回原已提交输入值。宿主在保存或焦点转移前可调用 `commitComposition()`，保证活动预编辑已有明确提交结果。

输入事件的完整 `TextEditingValue` 使用一槽待写回缓冲；尚未落 Rust 的新值覆盖旧值，不形成无界队列。flush 失败时保留待处理值。超出窗口硬上限的值在排队/写入前拒绝，Rust 版本失配也不推进本地窗口基线。窗口内选区映射到文档绝对 UTF-16 坐标；代理对中间的选区退回代理对起点，组合范围向外扩到完整代理对。活动预编辑的候选位置仍由 Flutter 输入控件的窗口内布局负责，不能把预编辑 selection 误报成 Rust 文档坐标。

现有工作台尚未连接该合同：`workbench_page.dart` 当前的全文 `TextEditingController` 与 `_onDocChanged` 路径未改。P03.4.2 将在独立切片中接入 P03 控件并验证候选窗几何和原生平台行为。

## 验证

真实 Dart↔Rust 动态库 FFI 测试 `app/test/rust_text_input_window_test.dart` 7 项通过，覆盖：

- 中文拼音预编辑不提前改变 Rust 全文，提交后的候选字符串以绝对 UTF-16 TextOps 写入；
- 显式取消和平台恢复到原值均不改变 Rust 文本；
- 代理对边界的输入窗口、窗口内/绝对 selection 与 composition 映射；
- 100 次输入事件最多保留 1 个最新待写值，最终只写一条增量；
- 保存/焦点转移前显式提交活动预编辑；
- 超大粘贴被窗口上限拒绝，Rust 文本/版本不变；
- Rust 版本失配时不改本地窗口基线且保留待处理输入。

当前此证据由 Linux/WSL Flutter test runner 驱动合成的 `TextEditingValue` 和本机构建的 Rust 动态库。它不是 Windows、macOS 或 Linux 原生输入法测试；未验证候选窗屏幕位置、原生 IME 焦点丢失行为、输入控件接入、Release 包或跨帧实际写回延迟。Windows CodeForge 的 P00.4 探针数据不能替代 Alula 产品证据。以上平台门均保留在 P03.4.2/P03.7。
