# P01.1 异步 LSP 请求与版本契约

日期：2026-10-29
状态：完成；实现、针对性 fixture 与整仓门禁均通过。

## 决策

- 先以 `textDocument/completion` 贯通 SRV-02/03/04/05。Rust `LspServer::request_async`
  只注册 pending 并写入 JSON-RPC；`LspPendingRequest::try_recv` 不等待，`cancel` 清除
  pending 并发送 `$/cancelRequest`。既有同步 `request`/`completion` 留给 CLI 与旧调用方。
- C ABI 增加 `alula_completion_start/poll/cancel`，将 ABI 从 v5 提升到 v6，Dart 加载时
  继续做版本握手。start 返回独立请求 ID 与请求开始时的文档版本；poll 状态为
  `pending`、`completed`、`stale`、`timeout`、`cancelled`。缺失 ID 按幂等取消处理。
- FFI 最多保留 32 个未收尾补全请求。编辑、关闭文档、解除该文档的 LSP 挂接或关闭
  工作区都会移除并取消对应请求。结果返回前再次核对 Rust 文档版本。
- Flutter workbench 等待请求期间每 20ms 检查一次；此检查仅在请求活跃期间发生。UI
  只显示仍对应当前文档和版本的结果。关闭/编辑会取消 FFI 请求，`finally` 作为客户端
  兜底重复取消。

## 验证

`crates/editor-core/tests/p01_async_completion.rs` 使用延迟 fake LSP 检查：FFI 发起不等待、
文档编辑取消旧请求、新版本完成回传、32 项上限与第 33 项背压、取消通知及工作区关闭。
`crates/editor-lsp/tests/p00_slow_completion.rs` 保留同步兼容行为验证。

最终门禁：`cargo fmt --all -- --check`、`cargo test --workspace`、
`cargo clippy --workspace --all-targets -- -D warnings`、`bash scripts/build_core.sh`、
`cd app && flutter analyze --no-pub`、`cd app && flutter test --no-pub` 与 `bash init.sh`
均通过；Flutter 测试 122/122。

## 变更影响审查

GitNexus staged 检查覆盖 13 个文件、66 个 symbols、35 条受影响流程，等级为
**CRITICAL**。展开的流程涉及 workspace shutdown 与 pending/cancel/DocRegistry、同步
shutdown 请求、文档关闭，以及 async completion；此结果保留为真实的架构风险，不用
`riskSharedAxes` 抵消。逐符号 impact 对既有 `request`、`alula_completion`、
`alula_doc_apply`、`alula_doc_close` 与 `lsp_shutdown_for_workspace` 为 LOW；
`_requestCompletion`/Dart completion 的 caller 图为 UNKNOWN，源码搜索核实前者只由
completion command 和按钮触发，后者只由 workbench 调用。ABI 搜索核实 Dart v6 与 Rust
v6 的双侧握手，核心/Ffi 工作区测试及新增慢 fake LSP 用例覆盖请求、编辑取消、32 项背压、
关闭和同步兼容。高扇入的 `alula_doc_open` impact 曾报 CRITICAL，本阶段未修改它。

GitNexus 分析自身的 process graph 仍有 231 个候选入口未排名、135 个 callee 被截断、
2 次 walk 到达预算；本次 35 条路径及测试证据是可核实的下界，不宣称整张调用图完整。

## 边界

P01.1 只把 completion 切到异步请求契约。诊断/语法的既有定时刷新、通用 event bus、
命令/上下文引擎、进程监督与资源压力状态属于后续 P01 切片；不在本 ADR 中实现。
