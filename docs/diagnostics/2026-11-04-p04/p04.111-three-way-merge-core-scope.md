Upstream also provides accept-all from either input ([`commands.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts#L516-L548)).

## In scope

- Add a GUI-free Rust `editor-merge` workspace crate with a deterministic, bounded three-way line projection over `base`, `input1`, and `input2`.
- Automatically apply non-overlapping edits from both inputs and identical overlapping edits once.
- Represent divergent overlapping edits as ordered conflict regions carrying base/input1/input2 text. An unresolved region contributes its base text to the initial result, matching the pinned source's reset behavior.
- Resolve one conflict from input1 or input2, accept all unresolved conflicts from either input, and report the unresolved count.
- Preserve complete source slices, including BOM, CRLF/CR, final-newline state, and Unicode. If a configured input, line, work, trace, or conflict bound is reached, return an error with no partial projection.
- Test empty documents, insert/delete/replace, adjacent and overlapping edits, identical edits, multiple conflicts, resolution ordering, emoji, BOM, CRLF/CR, final newline, deterministic output, and all bounds.

## Out of scope for P04.111

- FFI or ABI changes, workbench editor routing, commands/menus/keybindings, four-pane rendering, result-document dirty/save/accept lifecycle, Git conflict discovery, conflict navigation, accept-combination, result-edit tracking, and Multi Diff.
- Do not modify `app/lib/editor/line_diff.dart` or its consumers. `computeLineDiff` impact is CRITICAL (238 symbols, 34 processes, 7 modules); this slice owns an isolated Rust implementation and does not use that Dart symbol.
- Do not mark EDT-19 or `feat-026` complete. Later P04 slices must expose the model through a versioned FFI contract and then implement the workbench interactions and remaining merge behavior.
