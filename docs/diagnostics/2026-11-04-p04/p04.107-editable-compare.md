## Scope and implementation

For the pinned Code-OSS 1.145.0 compare-with-clipboard and compare-with-saved commands, the modified pane now edits the same Rust-authoritative active document. The original side remains a frozen, read-only snapshot: clipboard text is not persisted and the saved side retains the disk contents captured when the preview opened. Closing the preview releases only its view; it does not close the active document.

`SnapshotComparePreview` now accepts an editable modified-view presentation and keeps the original rows non-interactive. Both workbench compare routes bind a `RustTextInputField` through `OpenDoc.viewOf(source)`, so edits continue through the existing TextOp/FFI path. Rust edits synchronize sibling views and retain the existing dirty/savepoint, undo/redo, save and read-back behavior. A bounded debounce recomputes the diff from the Rust document version. When the existing input, row or work budget is exceeded, the preview displays an explicit complete-input fallback while retaining accepted Rust edits; it does not publish a partial diff. Preview close, source close, and route changes invalidate the compare binding to prevent stale writes.
