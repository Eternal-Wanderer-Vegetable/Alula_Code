## Alula baseline and boundary

P04.108 implements Explorer Select for Compare followed by Compare with Selected for one original resource. The Explorer tree currently opens a file on a plain tap and has no general multi-selection; its context menu carries a one-file compare selection. The existing comparison path already freezes an original snapshot and opens the second resource as the editable Rust-backed modified OpenDoc.

This slice adds only the Explorer two-file multi-selection route. Desktop Ctrl-click on Windows/Linux and Cmd-click on macOS toggle file rows in the selection; Shift-click extends a visible tree range. Plain click keeps its current open-file/folder behavior. The right-click menu retains a two-file selection only when the clicked row belongs to it and exposes Compare Selected for exactly two ordinary files. The first resource in the current Explorer tree selection order is original and the second is modified, matching the pinned command's selected-resource order.

The implementation should reuse the established frozen-original/Rust-modified comparison path. It must keep selection bound to the active workspace, reject identical/stale/deleted/unreadable resources, preserve current open-document text for dirty files, reject active IME or version/identity changes atomically, and honor the existing UTF-16 and diff row/work budgets. The menu must not expose Compare Selected for folders, one or more than two selected files, or a row outside the current selection.

Out of scope: Open Editors multi-selection, editor-title multi-selection, a Command Palette entry or new keybinding, three-or-more-resource Multi Diff, merge/conflict actions, SCM stage/unstage, and Rust/FFI/ABI/save-protocol changes.
