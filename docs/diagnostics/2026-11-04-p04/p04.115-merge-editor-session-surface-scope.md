## Included

- When an active `OpenDoc` owns a live merge session, render a merge-specific work area instead of the ordinary single-pane editor body.
- Show frozen input1 and input2 snapshots in read-only, selectable panes. Default layout follows the upstream mixed shape: input1/input2 above the editable result; base is initially hidden and can be shown.
- Provide a column layout with a narrow-width fallback that does not overflow. Keep headers and controls accessible by name.
- Embed the existing `RustTextInputField` as the result pane. It must continue to use the same Rust `OpenDoc`, selection, IME, savepoint, undo history, and split-view updates.
- Keep each `OpenDoc`'s merge surface bound to its session snapshots; closing one split view must not dispose the shared session.
- Add model/widget tests for frozen snapshots, read-only source panes, result edit/save/undo, two-view identity, layout toggle, narrow width, and disposal.

## Excluded

- Creating a session from Git state, parsing conflict markers, SCM discovery, or opening a new merge session from a command/URI resolver. A later slice will provide the entry route.
- Conflict decoration/active conflict navigation, accept/reject buttons, accept-all, combination UI, and final merge acceptance.
- Replacing the Workbench editor architecture with a new generic editor-pane registry.
- Rust/FFI/ABI changes, new result-text caches, or numeric memory optimization.

## Acceptance evidence required

- An attached session displays the exact frozen base/input1/input2 text and a result editor bound to the same Rust document; editing result does not mutate snapshots.
- Source panes reject text input while remaining selectable/copyable. Result edits use the existing Rust and undo path, and a save/read-back changes only the result resource.
- Mixed and column layouts render without overflow; the base pane starts hidden and toggles without losing source/result text. A narrow layout falls back cleanly.
- Two split views show the same Rust result and same frozen inputs; closing one view retains the other and session.
- Full local DoD, PR CI, Linux/Windows platform availability and macOS ARM64 package/launch evidence pass. Do not launch local GUI/Narrator; hosted macOS DnD remains a P15 device gate.
