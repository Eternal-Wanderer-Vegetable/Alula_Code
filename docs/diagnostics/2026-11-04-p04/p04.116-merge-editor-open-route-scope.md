# P04.116 / EDT-19f — Merge Editor resource open route

## Why this slice

P04.114 provides a Rust-backed merge session and P04.115 renders the session when attached to a result `OpenDoc`. The default Workbench still has no internal resource route that attaches such a session. This slice adds the argument-driven `_open.mergeEditor` action used by providers, with strict read-only validation before Workbench state changes.

The fixed Code-OSS 1.145.0 implementation registers `_open.mergeEditor` with four resources (base, input1, input2, result): [mergeEditor `commands.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts#L85-L104). This slice follows that resource contract while adapting to Alula's existing Rust `OpenDoc` and `MergeResultSession` lifecycle.

## Included

- Register the internal `_open.mergeEditor` command with a typed request carrying four absolute local file URIs.
- Resolve frozen base/input1/input2 text from an already-open Rust document when present, otherwise from the current workspace file decoder. Reuse the existing result `OpenDoc` where present.
- Before opening or attaching anything, compute the projection through the existing Rust `AlulaMergeApi` and require the result resource to be readable, clean if already open, and byte-for-byte equivalent at the normalized text level to the projection result.
- After validation, open/focus the existing result resource through the regular Workbench path, attach `MergeResultSession` to that same Rust document, and refresh editor context. Reopening the same resource with the same frozen snapshots focuses the existing session; a conflicting session is rejected.
- Return a visible, bounded error for unsupported URI schemes, missing arguments, unreadable resources, same-resource aliasing, dirty result documents, projection mismatch, and merge input limits. Rejection must not edit, save, or replace any file or document.

## Acceptance evidence required

- Command registration uses upstream id `_open.mergeEditor` and accepts only the typed four-URI request.
- Frozen snapshots reflect current Rust text for already-open inputs and decoded workspace text for closed inputs.
- A compatible existing result opens the Merge Editor surface on the same `OpenDoc` and shared Rust document; no duplicate text owner is created.
- Missing/invalid/non-file resources, aliased result/input paths, mismatching results, dirty result docs, and conflicting pre-existing sessions leave workspace contents and active documents unchanged.
- Reopening the same compatible session is idempotent. Existing P04.115 result edit/save/readback and close lifecycle remain intact.
- Focused Workbench command tests, full local DoD, Harness and GitNexus change detection pass; PR CI and Linux/Windows/macOS ARM64 build/test/launch/package evidence is recorded. Hosted macOS pointer-input limitations remain P15 evidence gaps.

## Explicit exclusions

This route does not create a missing result file, rewrite a Git conflict-marker file, parse markers, discover Git conflicts, add F1 file pickers, or add per-conflict accept/combine/navigation controls. It does not modify Rust/ABI or change MergeResultSession's initial-result contract. These require separate slices. No local GUI/Narrator test or numeric memory optimization is included.
