# P04.108 / EDT-18d：Explorer 单资源两步比较

Date: 2026-11-04  |  Branch: `codex/vscode-parity-p00`  |  Status: implementation, local DoD, PR CI, and hosted platform checks passed

## Implementation

Implemented the pinned Code-OSS 1.145.0 single-resource Explorer flow: `Select for Compare` stores a frozen original snapshot, then `Compare with Selected` opens a second Explorer file as the editable Rust-backed modified document in the existing compare preview. The file-row context menu omits compare actions for directories and hides the second action for the selected canonical path. The command IDs match the pinned upstream contract. No Rust, FFI, ABI, or save protocol changes were made.

When the original is already open, the snapshot comes from its current Rust-authoritative text, including unsaved edits; otherwise the Rust workspace decoder reads the bounded disk file. The modified side resolves to the target file's Rust `OpenDoc`. The route rechecks workspace root, canonical paths, file revision where disk text is used, document identity/version, active view, IME composition, and size/diff budgets. Missing, replaced, outside-workspace, binary, unsupported-encoding, same-file, oversized, stale, or approximate-diff cases reject the whole preview with a visible status. Reading the authoritative document uses the existing bounded range reader because `AlulaDoc.readRange` accepts at most 65,536 UTF-16 units per request. The compare preview also binds the user's active `file.save` shortcut so Ctrl/Cmd+S saves while the modal route remains open.

The slice excludes `compareSelected` multi-resource selection, Open Editors and tabs, apply/revert, three-way/Multi Diff, and ABI changes. Scope and pinned upstream contract are recorded in [p04.108-explorer-compare-scope.md](p04.108-explorer-compare-scope.md).
