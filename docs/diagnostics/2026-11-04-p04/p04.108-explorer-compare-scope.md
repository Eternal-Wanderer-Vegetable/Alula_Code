## Pinned Code-OSS contract

Code-OSS 1.145.0 registers `selectForCompare`, `compareFiles`, and `compareSelected` command IDs. In the Explorer context menu, `Select for Compare` is exposed on a single file; `Compare with Selected` appears after a resource has been marked. `getResourceForCommand` resolves the explicit resource, focused Explorer/Open Editors row, or active editor. ## Alula baseline and boundary

The current Explorer stores `TreeNode` roots in `workbench_page.dart`; `_buildNode` opens a file on one tap and has no selected-resource state or Explorer context menu. `_registerCommands` already registers command-palette commands, and `_showEditableSnapshotCompare` provides the editable Rust-backed modified side from P04.107. Text search found no current `selectForCompare`, `compareSelected`, `compareFiles`, `Select for Compare`, or `Compare with Selected` route in `app/lib` or `app/test`.

P04.108 will add the Explorer single-resource `Select for Compare` → `Compare with Selected` flow only. Selecting an already-open original uses its Rust-authoritative current text; otherwise the Rust workspace decoder reads the file. The original snapshot is frozen when selected. The second Explorer file is opened/resolved as the modified Rust `OpenDoc`; edits continue through the existing FFI path. Workspace root, canonical path, document identity/version, and budgets must be checked before opening the preview. Direct multi-select, Open Editors/selected tabs, apply/revert, three-way/Multi Diff, and ABI changes are excluded.
