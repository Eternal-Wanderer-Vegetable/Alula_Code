## 实现

通知中心工具栏和现有命令面板共用全局「请勿打扰」切换。开启时收起通知中心和已显示的 toast，保留通知条目。之后的信息和警告进入中心，新的错误仍能弹出。用户可手动重开中心。关闭勿扰后，先前抑制的 toast 不会补发。[固定版准入规则](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/common/notifications.ts#L508-L521) · [固定版收起通知](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/notifications/notificationsToasts.ts#L143-L154) · [固定版收起中心](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/notifications/notificationsCenter.ts#L133-L138)

偏好使用 `notifications.doNotDisturbMode` 存入现有会话 journal。旧文件缺少该字段时使用模型默认值，读取时校验布尔类型。正式配置作用域继续由 P07 跟踪。按来源勿扰和显式通知优先级为后续 LAY-18 子项。

## Windows 11 实机对照

在同一 Windows 11 build 26200、125% DPI、深色环境，分别运行固定 Code-OSS `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e` 和 Alula Release。两边各先注入一条信息和一条错误，打开中心并开启勿扰。两个界面都收起中心和原 toast。再注入一条信息、一条警告和一条错误，两边只有新错误弹出。重开中心后五条通知齐全。[Alula 实机截图](p05.111-windows-notification-dnd.png) · [双端观测及构建记录](p05.111-windows-dnd-results.json)

Alula 首次退出前读回 journal 中的 `true`。用该会话文件开启新的 Release 进程并注入同类样本，勿扰恢复，五条均保留在中心模型，两条错误产生 toast。两次退出码均为 0。macOS 实机验收暂缓。
