# P05.124 / feat-176 · LAY-18 Windows 实机通知主操作键位

依赖 P05.123 和 P05.125。普通桌面恢复后，在 Windows 11 build 26200、125% DPI、约 987 × 665 逻辑像素窗口，以真实桌面键鼠消息在两个独立的 Alula Release 夹具验证。每次均使用隔离会话。两个进程退出码均为 0。

## 自定义键位

- 产品 \`9318a5fb7f433a368d678f40854c87f022f6510d\` 的 runner、AOT、夹具哈希与 P05.123 记录的先前 Windows Release 一致。绑定 \`Ctrl+Shift+F8\` 到 \`notification.acceptPrimaryAction\`。
- 无通知焦点时，按键只执行最新条目 2 的首个主操作，条目 1 保留。通知中心旧条目 3 获得焦点后插入新条目 4，第二次按键只执行条目 3 的首个主操作，保留 4 和 1。两个样本的第二个主操作均未调用。[原始记录](p05.124-windows-custom-key.json) · [操作截图](p05.124-windows-custom-key.png)

## Narrator 与默认键位

- 产品 \`0befd12e9a8063f692aaacb13ec4be21b281634b\` 无用户键位覆盖。12 个在基础 Windows 构建目录中镜像的产品源文件经逐字节核对。开始时无 Narrator，原生状态为关闭。按 \`Ctrl+Shift+A\` 后通知 2 和 1 均保留。
- 在同一应用进程启动 Windows Narrator，原生状态读为开启。在无通知焦点和旧条目 3 已获焦两种场景，默认键先后仅执行条目 2 与条目 3 的首个主操作。第二次操作后新条目 4 和条目 1 保留。
- 正常退出本次启动的 Narrator，原生状态读回关闭。新条目 5 显示时再次按默认键，调用记录未增加，5、4、1 均保留。复验结束后查无 Narrator 进程。[原始记录](p05.124-windows-narrator-default-key.json) · [Narrator 开启时的焦点](p05.124-windows-narrator-on-focused.png) · [Narrator 退出后的通知](p05.124-windows-narrator-exited-no-action.png)
