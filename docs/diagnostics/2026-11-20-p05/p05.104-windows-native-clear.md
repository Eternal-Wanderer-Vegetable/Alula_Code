# P05.104 / feat-156 · Windows 清除通知原生验证

Windows 11 专业工作站版 x64，系统版本 `26200.9974`，125% 缩放。Narrator `10.0.26100.9949`，默认输出端点为 Realtek USB 耳机。Windows Release 来自 PR #3 收尾提交 `e6f81ad705d3770cd871bf0e5105d0edb2bc26a7`，其通知提示实现来自 `c2bf107774188446848d651b98eeef2512903ac6`。Flutter 3.47.8，framework `737ba8f885dc774b53b442759999a312c9461e4e`。独立入口只在真实 Alula 工作台启动时注入测试通知并记录模型，清除通过用户界面的 Windows 键鼠输入触发。Release AOT、引擎和 Rust 核心的 SHA-256 随结果登记。[结构化证据](p05.104-windows-native-clear-results.json)

## 实机结果

| 入口 | 实际移除 | Narrator 开启时新增的语音回顾条目 | Narrator 开启时提示音 | Narrator 关闭时提示音 |
| --- | ---: | --- | ---: | ---: |
| 聚焦单条后按 Delete | 1 | 「警报 通知已清除」×2 | 1 | 1 |
| 点击通知中心单条清除 | 1 | 「警报 通知已清除」×2 | 1 | 1 |
| 点击全部清除 | 2 | 「警报 已清除 2 条通知」×2 | 1 | 1 |

两次进程均从四条普通通知和一条活动进度开始。三次操作后只剩活动进度，两次均正常退出。每次清除各观察到一个由 Alula 进程发出的 Win32 `EVENT_SYSTEM_ALERT`。Narrator 的语音回顾在各操作后分别查看，每次新增两条相同播报。独立的首次 Delete 试跑也记录到同样的两条播报。截图只保留本次夹具的语音回顾内容。[Narrator 语音回顾说明](https://support.microsoft.com/en-us/accessibility/windows/narrator/chapter-2-narrator-basics) · [语音回顾截图](p05.104-windows-narrator-recap.png)

系统提示音用默认输出端点的 WASAPI 回环采集，48 kHz 双声道。把本机默认系统提示音 `Windows Background.wav` 第 0.05 至 0.45 秒与回环录音做归一化波形匹配。显式 `MessageBeep(MB_OK)` 校准得到 0.9500，无操作窗口最高 0.0519，判定阈值为 0.60。六次清除均在输入时段匹配到一个提示音，得分 0.8351 至 0.9546。匹配时间与相应的键鼠动作一致。回环证明信号已送到该输出端点，未做耳机外放的声学测量。原始回环 WAV 含端点混音，仓库登记波形指标和哈希。[WASAPI 回环说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)

## 验收结论

- **提示音输出、清除结果及播报文案已核验。** Windows Narrator 的每次语音回顾新增两条相同内容，单次播报标准未通过。回顾中的条数与实际移除数一致。此轮观察记录了应用发出的 Win32 事件与 Narrator 回顾，未隔离 Narrator 音轨测量两条语音的完整播出时长。
- **关闭 Narrator 时静默未通过。** 在无 Narrator 进程的独立试跑中，Flutter 报告语义树已开启，三种有效清除仍各播放一次提示音。本次记录仅证明这一 Windows 会话中语义树状态与 Narrator 开关不同步。
