## 实现与对照

- 通知中心工具栏提供有勾选状态的右下角、左下角和右上角选项。toast 与中心使用相同锚点。两个底部位置分别从状态栏右侧和左端打开中心，右上角从标题栏打开。右上角模式的通知展开箭头指向下面，收起中心箭头指向上面。macOS 系统标题栏模式没有应用内标题行，保留状态栏入口。
- 沿用固定版本的三个 `workbench.action.setNotificationsPosition.*` 命令 ID，Alula 也在现有命令面板提供这三个入口。位置保存到会话 journal，旧会话缺少设置或值无法识别时恢复右下角。正式配置作用域与 `workbench.notifications.button` 设置归 P07。[固定位置命令](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/notifications/notificationsCommands.ts#L361-L429) · [固定铃铛路由](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/notifications/notificationsStatus.ts#L105-L151)
- Windows 初测中，右上角位置可通过坐标点击打开中心，铃铛所在的标题栏却被涂成编辑器行号栏的底色。欢迎页显示正常，打开 Rust 编辑器后复现。像素测试证实 `EditorGutterPainter.paint` 的 `drawColor` 覆盖共享画布。修复将绘制裁切到行号栏范围，并在退出时恢复画布。Windows 新构建中，编辑器、标题栏和侧栏均正常显示，三种位置的实际铃铛点击点均可打开通知中心。
