# P00.4 Windows Alula Rust + rust-analyzer editing: preflight and interruptions

## Successful preflight

The isolated Windows Release app opened a copied `rust-mini` fixture under a temporary `HOME`. Six source comments were entered through the Alula window and verified on disk by marker and SHA-256. The edit window was 30.0 seconds; 40 one-second memory samples were recorded. Peak/stable/final Private Bytes were 653.84/645.64/608.53 MiB. All seven observed process IDs had exited at the 30-second close check, and the temporary fixture and home were removed.

This is a short preflight only. It does not count toward the 30-minute acceptance and its stable memory observation is above the 500 MiB target.

## Formal attempts

Two attempts to start run 1 stopped when Windows foreground ownership changed to the same File Explorer window (HWND 201794, PID 8696). The guard stopped further input and the Alula/mem-probe process trees were terminated.

| Attempt | Approx. elapsed editing | Saved edits | Alula PID | Complete memory report |
|---|---:|---:|---:|---|
| 1 | 291 s | 25 | 8784992 | No |
| 2 | 171 s | 15 | 5510880 | No |

The run durations and edit counts are session observations, not values recovered from a complete raw run report. Both attempts are invalid for acceptance. They do not establish a product failure or a memory result. Their structured record is `p00.4-windows-alula-rust-lsp-edit-interrupted-attempts.json`.

## Script updates

`p00.4-windows-alula-rust-lsp-edit-30m.ps1` now stops its edit timer at the end of the editing window and writes a separate abort JSON record with foreground handles, elapsed time, saved edits, observed process IDs, and an explicit invalid-memory-report flag. The two interrupted runs happened before that abort-record change, so their details are recorded here from the console/session observations.

The required 30-minute scenario remains outstanding. Do not use either interrupted attempt as a repetition.
