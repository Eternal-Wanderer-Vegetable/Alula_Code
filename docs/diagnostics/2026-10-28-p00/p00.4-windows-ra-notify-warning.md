# P00.4 Windows rust-analyzer notify warning attribution

Date: 2026-10-28
Scope: read-only attribution of the two startup warnings observed in the Windows Rust + rust-analyzer samples.

## Findings

- A standalone LSP initialization of rust-analyzer 1.97.1 against the `rust-mini` fixture reproduced the same warning on rust-analyzer stderr, without launching the Alula UI. The correct Windows workspace URI was used (`file:///E:/alula_code/tests/fixtures/rust-mini`). The captured messages were:

  ```text
  WARN notify error: Input watch path is neither a file nor a directory.
  WARN notify error: Input watch path is neither a file nor a directory.
  ```

- In Alula, the Rust LSP process inherits stderr, so this warning is emitted by the language server process. The Dart `WorkspaceWatcher` path catches filesystem watcher errors and does not print this message. This attributes the log source to rust-analyzer; it does not identify which requested watch path failed.
- The upstream [`notify-rs` Windows watcher](https://github.com/notify-rs/notify/blob/main/notify/src/windows.rs) returns this exact error when the requested path has no metadata or is neither a file nor a directory. This is consistent with a missing or invalid watched path, but the concrete path in Alula's run remains unknown. This is an inference from the upstream error implementation, not a confirmed Alula path.
- The same warning text was reported upstream in [rust-analyzer issue #19560](https://github.com/rust-lang/rust-analyzer/issues/19560). The issue page has no reproduction details that identify this workspace's path.
- The rust-analyzer manual documents `RA_LOG` and `RA_LOG_FILE` for server diagnostics ([Logging](https://rust-analyzer.github.io/book/contributing/#logging)). A follow-up attempt to drive `RA_LOG=trace` through the WSL-to-Windows stdio pipe did not complete the handshake; that attempt was stopped and its isolated child was terminated. It provides no additional path-level evidence.

## Limits and next step

No product code or fixture was changed. The warning is not treated as a confirmed product defect or as harmless noise. If it affects an acceptance run, collect rust-analyzer logs through a Windows-native harness or its supported log-file option, then inspect the watcher's structured path/error data before changing workspace-watcher behavior. P00.4 remains blocked on the existing cross-platform, service-access, and complete-product memory gates.
