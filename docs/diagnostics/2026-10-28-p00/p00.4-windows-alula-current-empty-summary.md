# P00.4 Windows current-worktree empty-window sample (2026-10-28)

## Scope

This is an exploratory baseline for the current Windows Release build of `app/`, not a full-product memory acceptance run. The build used HEAD `2235402` plus pre-existing unstaged application changes in the shared worktree. No application source files were changed by this measurement. Windows Flutter is 3.47.8/Dart 3.13.7; Windows Rust/Cargo is 1.97.1.

## Method and result

`tools/mem-probe` Windows Release build launched `app/build/windows/x64/runner/Release/alula_app.exe` for three cold 45-second runs at one-second intervals. Each sample contains 45 readings and the process tree contained only `alula_app.exe`.

| Run | Peak Private Bytes | Stable Private Bytes | Final Private Bytes | Processes |
|---|---:|---:|---:|---:|
| 1 | 202.60 MiB | 188.38 MiB | 188.38 MiB | 1 |
| 2 | 201.72 MiB | 187.46 MiB | 187.46 MiB | 1 |
| 3 | 200.63 MiB | 186.38 MiB | 186.38 MiB | 1 |
| Median | 201.72 MiB | 187.46 MiB | 187.46 MiB | 1 |

The stable range was 186.38–188.38 MiB. The median is near the historical 2026-10-26 `alula-w1-empty`/`alula-w2-empty` stable samples of 186.6/189.8 MiB; the binaries and worktree states are not proven identical, so this is context only, not a regression or improvement claim.

After the last run, a 30-second wait followed by `Get-Process alula_app` returned 0 processes. `mem-probe` also ended each launched process tree after sampling.

## Limitations

- Empty workbench only; no workspace, language server, terminal, browser, Notebook, or scripted editing workload.
- These 45-second runs do not cover the docs/04 startup-to-one-minute, ten-minute idle, thirty-minute editing, and close-plus-thirty-second timeline across three complete product repetitions.
- The Release build contains pre-existing dirty application changes and is not a clean commit-only artifact.
