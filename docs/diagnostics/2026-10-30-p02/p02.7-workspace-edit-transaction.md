# P02.7 跨文档 WorkspaceEdit 事务

## 交付范围

- Rust `DocRegistry` 新增原子多文档事务：先验证全部文档 ID、base version 和 TextOp 范围，再在克隆缓冲区上应用；任一验证失败都不替换 live buffers。成功后一次性提交，并按既有语义向已连接 LSP 发送全文变更。
- FFI ABI 升至 11，Dart bridge 编组文档批次并返回各 Rust 版本。
- Dart 规划器将 LSP UTF-16 行列范围转换成原文偏移；验证 URI、版本、可写状态、行列边界、代理对边界与非重叠编辑。每文档建立一次行索引，按从后向前顺序生成 TextOp，保留 CRLF/LF。
- 工作台事务成功后同步 Rust 版本、controller、selection、dirty/savepoint、syntax 和 journal；每个文档各自获得独立 undo 帧，帧共享 transaction ID，undo/redo 中继续保留该 ID。

## 验证

- `cargo test -p editor-core -p editor-buffer`：30 项通过，含多文档提交、版本/范围失败回滚、重复/空事务和 ABI FFI 往返。
- `flutter test test/workspace_edit_test.dart test/find_replace_undo_test.dart test/core_sync_test.dart`：35 项通过，含 UTF-16/emoji、CRLF/LF、范围校验、ABI 版本和失败原子性。
- `flutter test test/workspace_edit_transaction_test.dart`：工作台级 stale edit 拒绝、双文档同步及分别 undo 通过。
- 完整 `bash init.sh`：退出码 0；Rust workspace tests、Clippy、core 动态库构建、Flutter 163 项全部通过。
- `cargo fmt --check`：通过；`flutter analyze --no-pub`：0 issues。

## GitNexus 与边界

编辑前分析将 `TextBuffer`、`DocRegistry`、`AlulaFfi` 标为 CRITICAL，`DocRegistry.apply` 标为 HIGH；风险已在编辑前记录。实现保留原单文档 API，事务通过 clone/preflight 的新增入口提交，没有修改既有 apply 语义。提交前另登记 staged 和完整工作树 graph change analysis。

该入口目前接受已打开的可写文本文档和文本编辑；资源创建/删除/重命名操作不属于本事务。LSP 服务端主动发起的 `workspace/applyEdit` 接收与响应队列尚未接线，留给 P12 的 LSP 协议阶段；本切片完成并测试了该协议后续可调用的原子工作台执行入口。500 MiB 数值优化按用户优先级留到 P14。
