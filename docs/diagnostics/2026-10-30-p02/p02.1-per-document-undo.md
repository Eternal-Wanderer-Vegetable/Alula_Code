# P02.1 — Per-document undo/redo

Date: 2026-10-30

## Scope

Fix the cross-document history bug in which editing file B caused undo in file A to restore B's snapshot. Each open document now owns its undo and redo stacks, coalescing timestamp, and programmatic-write guard. This slice does not claim the full DOC-04 contract: savepoints, IME composition/undo stops, workspace transactions, and exact caret restoration remain for later P02 slices.

The Rust + rust-analyzer 500 MiB target is paused as an acceptance gate. This change retains a bounded history as a correctness/lifecycle constraint; it does not tune or claim whole-process memory savings.

## Implementation

- `OpenDoc` owns its `UndoStack`, last edit time, and undo/redo write guard. All welcome, restored-session, and file-open constructors receive the workbench's shared `UndoHistoryBudget`.
- Undo/redo command enablement reads the active document. Editing one document no longer coalesces with, or pops, another document's history.
- The shared budget accounts for both undo and redo snapshots across all open documents, enforcing at most 100 frames and 2,000,000 Dart UTF-16 code units. It evicts the oldest frame by creation order. Closing a document or disposing the workbench clears its frames and detaches its stack from the budget.
- A clean external-file reload clears that document's obsolete undo/redo history and suppresses history recording for the programmatic reload.
- `REF-07-UNDO-01` now asserts each file independently restores its own pre-edit text and redoes its own edit. The old P00 run remains historical evidence of the prior bug.
