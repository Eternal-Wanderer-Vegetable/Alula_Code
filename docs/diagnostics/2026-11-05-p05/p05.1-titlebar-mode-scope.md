## 实现与本地验证（2026-11-05）

- `WindowChromeConfiguration` 默认 custom；启动参数 `--native-titlebar` 选择 OS titlebar，`--custom-titlebar` 在两者都出现时优先。Custom workbench titlebar 为 35 logical px。
- Custom 模式的拖动手势仅占标题与空白拖动区；双击切换最大化/还原。菜单与按钮不处在拖动命中区。以注入的 `WindowChromeDriver` 调用最小化、最大化/还原、关闭和 `startDragging`，便于不触碰宿主桌面地验证路由。
- 平台按钮策略：Linux custom 模式绘制窗口按钮，因为当前 `window_manager 0.5.2` 的 GTK hidden 模式会移除 decorations；Windows 与 macOS 保留原生 caption controls/traffic lights。此策略与 VS Code 在 Windows custom titlebar 绘制按钮的行为仍有差异，control-style custom/hidden 选择暂不支持，需后续独立实现与设置入口。
- Native 模式隐藏 Flutter 标题文本和自绘窗口按钮，但保留现有菜单入口为 35px 菜单行；系统关闭监听继续运行并先执行工作区清理。该菜单仍是当前单层 popup，不代表完整 VS Code 菜单树、mnemonic 或 macOS 系统菜单。
- 定向 `title_bar_test.dart` 与 `window_chrome_configuration_test.dart`：9/9 通过，覆盖三平台按钮策略、尺寸、菜单、拖动/双击、窗口操作路由及 native 模式关闭回调。原 W1-3 控件测试显式注入 Linux 配置后通过，避免在 Flutter 测试默认 Android 平台下误断言桌面按钮。

## 范围与验收

实现可注入、可测试的 native/custom titlebar 配置解析；默认 titlebar 为 custom，另提供 native 启动参数。Custom 模式采用 35 logical px 标题栏，并正确保留拖动区域与交互控件命中区；native 模式保留操作系统标题栏，同时继续执行工作区关闭/服务清理。按平台验证双击最大化/还原、最小化、最大化、还原、关闭及优雅退出。上游只允许 Windows/Linux custom titlebar 使用自绘控制按钮；macOS 使用原生交通灯。当前 `window_manager` 插件的 Linux hidden 模式会撤掉 GTK decorations，因此 Alula 在 Linux custom 模式绘制按钮；Windows/macOS 保留原生按钮。显式控制按钮 custom/hidden 选择不在本子项中交付，需要独立 platform-specific 实现和设置入口；P05 不得把该差异标为已解决。
