# P04.59 / EDT-11a：同文档选中文本拖放

日期：2026-11-01
状态：实现及本地门禁完成；Linux/Windows Release CI 通过；因 macOS Release 启动回归与原生拖放交互尚未验收，保持 in-progress。

## 范围

- 编辑器中的非空文本选区可发起原生桌面拖动；payload 仅携带文档 id、Rust 文档版本、绝对 UTF-16 范围、选中文本与一次性 token，最大 65,536 UTF-16 单元。
- 同一 Rust 文档的同视图/分屏视图 drop 支持 move/copy。Windows/Linux 的 Ctrl 与 macOS 的 Option 请求 copy；默认 move。目标落在原选区内、move 到原边界、目标 UTF-16 代理对中间、版本过期、composition 或任一同文档视图存在未提交输入时拒绝。
- 应用前再次从 Rust 读取并逐字符校验源范围，再以版本门控 `applyWith` 提交。一次拖放进入一个 undo frame，恢复选区 caret、分屏 view、dirty、Find、outline、syntax 与保存路径。
- 拖出的标准数据另提供 `text/plain`；若系统最终报告 move，且源文档仍是 payload 版本，则删除源范围并记录可撤销编辑。应用内同文档 drop 先提交目标 edit，token 用于抑制随后 source completion 的重复删除；去重集合上限为 32。
- 仅接受应用内同文档 localData。跨文档编辑器 drop、外部文本/链接/图片 drop provider、`editor.action.pasteAs` 尚未实现，继续留在 EDT-11 后续切片。

## 实现与风险

新增 `text_drag_drop.dart` 负责有界 payload 校验及 UTF-16 同文档操作计划；`editor_native_text_drag_drop.dart` 隔离原生 API 与 Rust/workbench。依赖 `super_drag_and_drop 0.9.1` 与已有 `super_clipboard 0.9.1` 对齐，官方列出 Linux、Windows、macOS 支持；其文档同时将包标为实验阶段，所以组件仅作为桌面 editor adapter，不进入 Rust 核心。首次接入后必须保留 Linux/Windows Release build 与原生 interaction CI；若出现原生构建/进程稳定性回归，应先移除/替换该 adapter，再扩展 Paste As。

固定 Code-OSS 1.145.0-dev 参考 commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`：选区拖动、modifier 切换 move/copy 见 [`dnd.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/dnd/browser/dnd.ts)。Paste As 的 provider 路径是独立后续工作，见 [`copyPasteContribution.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteContribution.ts)。原生包的能力与实验状态见 [super_drag_and_drop 0.9.1](https://pub.dev/packages/super_drag_and_drop)。
