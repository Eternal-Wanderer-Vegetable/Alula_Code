## Reference behavior

The pinned [lines operations contribution](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/linesOperations/browser/linesOperations.ts#L657-L695) registers `editor.action.insertLineBefore` and `editor.action.insertLineAfter`. Their defaults are Ctrl+Shift+Enter / Ctrl+Enter, with CtrlCmd selecting Command on macOS. Both insert a newline at the current logical line boundary and route it through the editor's Enter operation. The corresponding [line insertion implementation](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/cursor/cursorTypeEditOperations.ts#L668-L697) keeps the source cursor on the original first line for insert-before at document start.

## Alula implementation

- Registered the same command IDs, labels and platform chords in the command registry and `KeybindingSet`.
- Resolved selection lines and line boundaries through the Rust document's UTF-16 `positionAt`, `lineOffset` and `lineBoundary` APIs. Inserted the newline and inherited line indentation through a single existing Rust `TextOp` batch; no FFI ABI change.
- Kept the original selection on the source first line for insert-before at offset zero. Other insertions place each cursor in the newly inserted line. Repeated identical insertion targets are coalesced; conflicting targets cancel without editing.
- Reused the existing edit-history, dirty-state, input-window rebase and sibling-view refresh paths. Selection count and undo text remain within the existing limits.

This slice inherits the neighboring line's leading whitespace. It does not yet run all of Code-OSS `EnterOperation` language rules or configurable advanced auto-indent for these commands; that remains a documented parity gap. Other EDT-07 commands (move/copy/delete/join/sort/deduplicate) remain open.
