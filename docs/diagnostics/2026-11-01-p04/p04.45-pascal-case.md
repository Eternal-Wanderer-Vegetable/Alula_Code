# P04.45 / EDT-08e Pascal Case

Date: 2026-11-01. Reference: fixed Code-OSS commit [`4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/linesOperations/browser/linesOperations.ts#L1269-L1298).

## Implementation

- Registered `editor.action.transformToPascalcase` in the command palette with no default keybinding. It uses the existing bounded Rust-authoritative UTF-16 selection/caret planning, multi-selection transaction, document-version and overlap checks, undo budget, selection mapping, undo/redo, dirty state, Find refresh, sibling-view sync, and save path.
- Added `editor_buffer::transform_pascal_case_text`. Dots remain attached to the preceding segment and start a new segment after the dot; `_`, ASCII space, tab, and hyphen split words. Each word uppercases its first UTF-16 unit. A Unicode all-uppercase line causes the suffix to be lowercased, matching the pinned `UpperCaseWordMatcher` rule. Regexes are compiled once and the cache is bounded to two patterns.
- Added NUL-safe JSON FFI `alula_text_transform_pascal_case` and raised the synchronized ABI handshake from v30 to v31. The endpoint uses the existing 8 MiB request and 16 MiB response bounds.

## Difference and boundary

Rust case mapping is locale-independent and Unicode tables may differ from JavaScript `toLocaleUpperCase` / `toLocaleLowerCase` on the host. This remains in the parity difference ledger. The `TargetPlatform` fixtures are automated Flutter tests; they do not establish native OS, IME, screen-reader, DPI, or theme acceptance. P15 remains pending; the Windows Release artifact evidence is in [`P03.7 hosted artifact run 41221325692`](../2026-11-01-p03/p03.7-windows11-hosted-artifact-41221325692.md).
