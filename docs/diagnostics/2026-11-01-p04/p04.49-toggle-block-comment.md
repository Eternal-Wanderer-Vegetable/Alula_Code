# P04.49 / EDT-09b — Toggle Block Comment

Date: 2026-11-01
Reference: VS Code / Code-OSS `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`

## Reference behavior

- `editor.action.blockComment` toggles the configured block markers. Pinned defaults are Alt+Shift+A on Windows/macOS and Ctrl+Shift+A on Linux.
- The command inserts `startToken + "  " + endToken` at a collapsed caret and positions the caret inside the pair. With a selection it surrounds the selected text with spaced markers and selects the inner text.
- When matching markers surround the selection, one following ASCII space on the opening marker and one preceding ASCII space on the closing marker are treated as part of the markers and removed. An intervening end token forces insertion rather than removal.
- The current workbench maps Rust and JavaScript/TypeScript language IDs to `/*` and `*/`. Languages without a configured pair report a safe no-op.

## Implementation

- `editor-buffer` resolves absolute UTF-16 selections and marker edits from one Rust Rope snapshot. Requests are bounded to 10,000 selections, 64 Ki UTF-16 per endpoint line, 2,000,000 cumulative endpoint-line units, and 16 visible ASCII units per token.
- A NUL-safe JSON FFI endpoint returns versioned edits and Code-OSS selection mapping; the Rust/Dart ABI handshake advances to v35. The workbench checks the version, range order, removed text against Rust's authoritative document, selection bounds, and the 2,000,000-character undo budget before applying one TextOps transaction.
- The transaction updates selection, undo/redo, dirty state, Find, sibling views, and save behavior. The empty-caret path puts the caret between the two inserted spaces.

## Limits and differences

- The workbench currently supplies `/*` and `*/` only for Rust and JavaScript/TypeScript IDs; Python and plaintext remain no-op. Other languages and their configurable tokens are not implemented in this slice.
- Endpoint lines longer than 64 Ki UTF-16 or requests scanning more than 2,000,000 UTF-16 units are safely rejected instead of scanning an unbounded line. Distinct overlapping selections are rejected atomically. These bounds and conflicts have not been compared against a native Code-OSS editor.
- This slice does not implement line-comment force-add/remove commands, trailing-whitespace/final-newline cleanup, or indentation conversion. P15 native keyboard, IME, accessibility, DPI, theme, and release gates remain pending.
