# P04.50 / EDT-09c：修剪尾随空格

日期：2026-11-01
固定参考：Code-OSS `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`

## 实现

实现固定版 VS Code 显式命令 `editor.action.trimTrailingWhitespace`，Windows/Linux 默认键位为 `Ctrl+K Ctrl+X`，macOS 为 `Cmd+K Cmd+X`。Code-OSS 的 [linesOperations.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/linesOperations/browser/linesOperations.ts) 为该命令设置平台 chord；[trimTrailingWhitespaceCommand.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/commands/trimTrailingWhitespaceCommand.ts) 确认手动执行会修剪所有行，按跟踪 selection 保留选区；[strings.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/base/common/strings.ts) 将本命令的空白字符限制为 ASCII space 和 tab。auto-save 模式有独立的光标行跳过逻辑，本 slice 未实现 auto-save。

Rust `TextBuffer` 在 Rope 上扫描一次，以版本化绝对 UTF-16 范围返回尾随空格/tab 删除计划。保留 CR、LF、CRLF、BOM、NBSP 和所有非尾随文本；不把整份文本拷贝到 Dart。通过 ABI v36 的 `alula_doc_trim_trailing_whitespace` 暴露 JSON 计划。边界为全文扫描最多 32 Mi UTF-16、最多 10,000 个编辑、累计删除最多 2,000,000 UTF-16，JSON 响应最多 1 MiB；越界时整次命令拒绝并返回错误。

Flutter bridge 验证 ABI、计划版本和范围。工作台先 flush 本地输入，再逐段读取 Rust 权威删除文本并逐字符确认计划只包含 ASCII space/tab，校验文档版本、范围无重叠且未超过撤销预算，然后以单个降序删除事务应用。selection 端点落在已删除区域时映射到范围起点；其他端点减去之前删除长度。事务更新 undo/redo、dirty、Find、输入窗口、分屏和保存状态。

为处理 VS Code 的 chord 序列，新增长度为两段的键位解析、keybindings.json 覆盖/移除、when 条件、显示文本和焦点节点分发。既有 Ctrl/Cmd+K Ctrl/Cmd+D 移动 occurrence 及 macOS Ctrl+K Cmd+Delete 行尾删除也改由同一序列路径分发。

## 限制与差异

- 仅实现显式修剪命令。Code-OSS `files.trimTrailingWhitespace` 保存设置默认为关闭；该设置和 save-time 集成留待后续切片。
- 为控制单次全文件扫描、FFI 输出和撤销内存，超出上述限制的文档会安全拒绝。Code-OSS 对极大文档的资源边界未在原生程序中对照。
- 三平台结果来自 Flutter `TargetPlatform` fixture，不等同于 Windows、Linux DRM 或 macOS 原生键盘/IME/无障碍/发行验证。P15 平台验收仍 pending。
