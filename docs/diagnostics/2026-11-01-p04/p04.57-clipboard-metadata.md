# P04.57 / EDT-10e — Multi-cursor clipboard metadata

## Result

Implemented the small in-process clipboard metadata subset needed to restore the original copied selections during multi-cursor paste. The sidecar retains one recent plain-text value and version-1 metadata, and accepts metadata only while the clipboard text matches exactly. Matching `multiCursorText` chunks are distributed to target selections in document order, including chunks that contain embedded newlines. CRLF and CR inside copied chunks are normalized to the editor's LF document model. Both regular and overtype multi-selection paste use the metadata; external text, stale text, count mismatches, and oversized records use the existing plain-text path.

Retention is bounded to 64 Ki UTF-16 units for the clipboard text, 64 Ki UTF-16 units across copied chunks, and 10,000 selection references. The system clipboard remains interoperable plain text. Rich HTML, the `vscode-editor-data` clipboard MIME type, and other metadata modes remain separate work. `isFromEmptySelection` is retained in the versioned in-process record for parity, but this slice does not add a new paste-on-new-line command path. No Rust or FFI change was needed.
