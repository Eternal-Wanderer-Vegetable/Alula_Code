# P04.52 / EDT-09e：插入末尾换行命令

## 固定上游行为

对照 Code-OSS `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`：[`insertFinalNewLine.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/insertFinalNewLine/browser/insertFinalNewLine.ts) 注册 `editor.action.insertFinalNewLine`，label 为 `Insert Final New Line`，precondition 为可写编辑器，不声明默认快捷键。[`insertFinalNewLineCommand.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/insertFinalNewLine/browser/insertFinalNewLineCommand.ts) 在末行最大列插入 `model.getEOL()`，用 tracked selection 保持编辑器选区，并在命令前后建立 undo stop。实现没有检查 EOF 是否已有 EOL，因此空文档会得到一个 EOL，每次重复调用都会再插入一个。

本 slice 只交付显式编辑器命令；`files.insertFinalNewline`、`files.trimFinalNewlines` 等保存设置是不同的设置行为，留待后续切片。

## 实现

- 工作台命令面板注册 `editor.action.insertFinalNewLine`，无默认快捷键；运行时拒绝只读文档与 IME composition。
- Rust 文档缓冲使用 LF 归一化，命令以一次版本门控的 `TextOp.insert(totalUtf16Length, '\n')` 在全文 EOF 添加一个 UTF-16 单元；既有磁盘 EOL 元数据负责将保存结果写回 LF 或 CRLF。未改 FFI ABI。
- 对旧 EOF 之前的选区保持原 offset；恰在 EOF 的选区随插入右移。操作作为独立 undo frame 记录，更新 Find、dirty 和同文档分屏。
- EOF 光标会落到新行尾，偏移可超过旧输入窗长度。实现先刷新输入窗和分屏、等待一帧，再写入 Flutter 选区，避免旧 `EditableText` controller 在新文本重建前收到越界 selection。
