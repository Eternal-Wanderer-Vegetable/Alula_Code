# P04.32 — Rust double-quote pairing

Date: 2026-11-01. Status: implemented and validated.

## Behavior

- Rust `.rs` files auto-insert the matching `"` outside Tree-sitter `string` tokens and surround a non-empty selection with quotes, matching the pinned Rust language configuration.
- Syntax tokens are refreshed locally for Rust documents whether or not rust-analyzer is attached. Pairing requires a token snapshot at the current Rust document version; an absent, malformed, or stale snapshot falls back to a literal quote. The selection-surround rule remains available because it is a separate `surroundingPairs` rule.
- A typed quote skips only an editor-inserted, still-tracked closer. Backspace removes both quotes only for the tracked pair. The existing Rust UTF-16 TextOps, bounded close-marker storage, document history, split-view synchronization, and save path are reused. No Rust or FFI ABI changed.
- The pinned configuration has no single-quote auto-closing pair. `< >` selection surrounding and block-comment Enter rules remain later slices.

## Fixed source

- [Pinned Code-OSS Rust language configuration](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/extensions/rust/language-configuration.json) defines the double-quote pair with `notIn: ["string"]` and includes double quotes in `surroundingPairs`.
- The implementation uses the existing local Tree-sitter token snapshot; lookup is binary search over sorted UTF-16 token ranges.
