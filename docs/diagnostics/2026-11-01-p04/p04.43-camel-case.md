## 固定版本规则

固定版 `CamelCaseAction` 注册 `editor.action.transformToCamelcase`，没有默认键位。输入中有 CR/LF 时，分隔符为 `[_-]+`；否则为 `[_\s-]+`。首个片段只在行首匹配“Unicode 大写字母 + 非大写字母”时把这两个码点转为 locale lowercase；后续片段只对 `substring(0, 1)` 的一个 UTF-16 code unit 做 locale uppercase，然后拼接并移除分隔符。

源码：[linesOperations.ts（固定 commit，CamelCaseAction）](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/linesOperations/browser/linesOperations.ts#L1270-L1295)。

## 实现

- 工作台新增无默认快捷键的 `editor.action.transformToCamelcase` 命令。复用 P04.41/42 的 Rust 权威 UTF-16 区间、caret 默认词查询、多光标去重、版本/重叠/撤销预算门控、selection 映射与一次 TextOps 提交，沿用 undo/redo、dirty、Find、兄弟视图、保存和输入窗口同步。
- `editor-buffer::transform_camel_case_text` 使用三个固定 `OnceLock` regex pattern，缓存不随输入增长。单行 whitespace class 显式匹配 ECMAScript `\s` 集：避免 Rust `\s` 把 NEL (U+0085) 当分隔符，同时支持 BOM (U+FEFF)、U+2028/U+2029。多行模式只按 `_` 与 `-` 分段；首词支持 CR、LF、CRLF 与 Unicode 行分隔符的行首边界。后续片段按 JavaScript 单 UTF-16 单元语义转换，首码点为 supplementary scalar 时原样保留。
- 新增 `alula_text_transform_camel_case` JSON FFI 及 Dart bridge，Rust/Dart ABI 双侧升至 v29。复用 8 MiB request JSON 与 16 MiB transformed output 上限，JSON 转义保留 NUL。

## 差异和边界

- Rust 标准库大小写映射是 locale-independent；固定版调用 JavaScript `toLocaleLowerCase/toLocaleUpperCase`，系统 locale 特例可能不同，Unicode 数据版本也可能有差异。
- 没有语言专属 `wordPattern` 的差异仍由 P04.41 记录；本命令 caret 继续复用 P04.41 的当前默认词查询。
- TargetPlatform fixture 是 Flutter 合成事件，不等于原生 Windows/macOS/Linux 输入、读屏、IME、DPI/主题或发行验收；这些仍由 P15 处理。使用的 Rust 代码文本是自动化夹具，不构成原生 Linux 窗口保存证据。
