# P04.51 / EDT-09d：缩进转换

## 范围与行为

对照固定 Code-OSS `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e` 的 [indentation.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/indentation/browser/indentation.ts)：

- 注册 `editor.action.indentationToSpaces` 与 `editor.action.indentationToTabs` 命令面板项；两者没有默认快捷键。
- 扫描全文每行的前导空格与制表符。转空格时，一个 tab 按当前 `tabSize` 展开；转 tab 时，连续空格每满一个 `tabSize` 转为一个 tab，余数保留为空格。行尾、CR/LF/CRLF、BOM 与首个非缩进字符之后的内容均保持原样。
- 转换操作同时更新该文档的 transient `insertSpaces` 模式；同文档分屏共享此模式。后续 Tab、行缩进/反缩进、括号内自动缩进读取该模式。当前 `tabSize` 固定为 4；持久化与设置 UI 留 P07。

## 实现

- Rust Rope 规划器按 UTF-16 绝对偏移返回每行替换，校验 `tabSize` 1–32；全文扫描最多 32 Mi UTF-16、10,000 个编辑、2,000,000 UTF-16 删除与插入总载荷。版本化 JSON 响应上限 5 MiB。
- Rust FFI 与 Dart 同步升级 ABI v37。Dart bridge 校验响应版本字段、范围顺序、载荷字符和空白字符集合。
- 工作台再次逐范围读取 Rust 权威文本并逐字符比对，按单次 TextOps 批量提交；选区映射、undo/redo、dirty、Find、双视图同步与保存回读均接通。只读文件和 IME composition 时拒绝操作；no-op 计划仍更新该文档的输入模式。
- 当前入口为命令面板，状态栏缩进选择器尚未接入。超出资源界限时安全拒绝，与 Code-OSS 无界全文扫描的边界行为仍有差异。
