## Reference behavior

- `editor.action.commentLine` is the editor's Toggle Line Comment command. The pinned defaults are `Ctrl+/` on Windows/Linux and `Cmd+/` on macOS.
- The implementation follows the pinned `lineCommentCommand.ts`: preserve indentation, ignore blank rows in a mixed selection, comment an all-whitespace selection at its indentation, and when uncommenting remove the marker plus one following ASCII space. A selection ending at column 1 on the next row excludes that row.
- Rust's pinned language configuration declares `//`; this slice also maps the app's current Python language ID to `#` and its TypeScript/JavaScript ID to `//`.

## Implementation

- `editor-buffer` plans line-comment edits against one Rust Rope snapshot, with all ranges in absolute UTF-16 code units. Requests are bounded to 10,000 selections and affected lines, 16,384 leading-whitespace UTF-16 units per line, and a 16-unit printable ASCII token.
- A NUL-safe JSON FFI endpoint returns the plan and snapshot version; the ABI handshake is v34 on Rust and Dart. The Dart bridge exposes versioned `DocumentLineCommentPlan` edits.
- The workbench checks the returned version and every removed substring against Rust's authoritative text, checks overlap and the 2,000,000-character undo budget, then submits one descending-order TextOps batch. Selection mapping, undo/redo, dirty state, Find refresh, sibling-view synchronization, and normal save behavior use the existing workbench paths.
- Unknown/plaintext languages report that no line token is configured and make no document edit. Currently recognized source languages are Rust, Python, and TypeScript/JavaScript.

## Limits and differences

- Distinct selections that cover a shared logical line are rejected atomically. Exact duplicate ranges are deduplicated. This bounded behavior has not been compared against a native Code-OSS editor for overlapping multi-cursors.
- A file extension without a mapped line token is a safe no-op. Block comments, trailing-whitespace cleanup, final-newline controls, and indentation conversion remain separate EDT-09 work.
- These Flutter platform fixtures do not replace P15 native Windows/Linux/macOS input, IME, accessibility, DPI, theme, and release gates.
