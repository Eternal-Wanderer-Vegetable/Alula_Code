# P04.7 — Home/End 与 smart Home

## 范围

完成 `docs/11-VSCode功能对照矩阵.md` 的 EDT-01 行边界子项：逻辑行 Home/End、Shift 选择，以及第一次 Home 移到首个非空白字符、再次 Home 回到行首的 smart Home 行为。参考版本固定为 Code-OSS 1.145.0-dev commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`；命令/平台键位对照登记于 [`docs/11`](../../11-VSCode功能对照矩阵.md)，官方默认键位表列出 `cursorHome`、`cursorEnd` 及其平台组合（[VS Code Default Keyboard Shortcuts](https://code.visualstudio.com/docs/reference/default-keybindings)）。

## 实现

- `TextBuffer::line_boundary_utf16` 在 Rope 内按绝对 UTF-16 offset 找到当前逻辑行，返回行首、行首缩进后的首个非空白位置、排除 LF/CRLF 的行尾；不将整行或全文转换为 Dart 字符串。
- `DocRegistry`、ABI v22 `alula_doc_line_boundary`、Dart `AlulaDoc.lineBoundary` 同步暴露该查询，并把版本号带回调用端。
- 工作台注册 Home/End 及 Shift 选择命令。Windows/Linux 使用 Home/End；macOS 同时支持 Home/End、Command+左右方向键以及 Ctrl+A/E 行边界别名。
- smart Home 在空白缩进内跳到首个非空白字符，在该字符处再次按下回到行首。End 落在行尾空白之后、换行符之前。选择命令保留 selection base；移动只改变选择，不修改 Rust 文本、文档版本或 dirty 状态。

## 验收

- Rust `editor-buffer`：UTF-16/emoji、代理对中点拒绝、CRLF、空白行、末尾空行，以及 100,000 UTF-16 空格缩进；新增定向测试 2 项通过。
- Rust `editor-core` 真实 FFI：ABI 返回行首/缩进 Home/行尾和 CRLF 下一行偏移；代理对中点返回 `InvalidUtf16Offset`；定向测试 1 项通过。
- Flutter 定向命令、工作台及 FFI 测试：`flutter test test/keybindings_line_boundary_test.dart test/workbench_line_boundary_test.dart test/core_sync_test.dart`，25 项通过。覆盖 Windows/Linux/macOS target-platform、smart Home 来回、Home/End、Shift 锚点、macOS Command aliases、CRLF 文件加载为 LF、20,000 空格长行跨越 16,384 UTF-16 输入窗，以及 Rust 全文/版本不变。
- `bash init.sh` EXIT=0：Rust workspace tests、Clippy `-D warnings`、`build_core`、Flutter 287 项通过。
- `cargo fmt --all -- --check` 通过；`cd app && flutter analyze` 为 0 issues。
