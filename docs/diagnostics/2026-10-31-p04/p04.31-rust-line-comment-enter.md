# P04.31 — Rust line comment continuation on Enter

Date: 2026-10-31. Status: implemented and validated.

## Behavior

In Rust `.rs` files, Enter continues a line comment when the text before the caret matches either pinned Rust `onEnterRule` and non-whitespace text remains to the right. It inserts a new line with the existing line indentation followed by `// `, leaving the right-side text in place. The comment rule runs before the tracked-bracket smart-Enter rule. At end of line, when only whitespace remains, or for a non-collapsed selection, Enter keeps the existing indentation fallback. IME composition remains on Flutter's input path.

The rule checks only the bounded current line through Rust-authoritative UTF-16 offsets. It counts inspected prefix, selection, and suffix against the existing edit budget; if the remaining suffix is too large for that budget, it skips the special rule and preserves ordinary Enter. No Rust or FFI ABI changed.

This implements the Rust line-comment rule only. Block-comment continuation, quote pairing, and syntax-aware exceptions are not included.

## Fixed source

- [Pinned Rust language configuration](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/extensions/rust/language-configuration.json) defines `beforeText` as `^\s*//\s*\S|\s//\s+\S`, `afterText` as `^(?!\s*$)`, and appends `// ` without changing indentation.
- [Pinned `OnEnterSupport`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/languages/supports/onEnter.ts) evaluates regex rules before bracket indentation rules.
- [Pinned Enter edit operation](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/cursor/cursorTypeEditOperations.ts) appends the configured text after the existing line indentation.
