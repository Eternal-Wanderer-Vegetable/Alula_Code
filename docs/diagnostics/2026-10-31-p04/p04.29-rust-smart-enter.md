# P04.29 — Rust auto-paired brace smart Enter

Date: 2026-10-31. Status: implemented and validated.

## Behavior

When the caret is between a Rust `.rs` `{}` pair inserted by Alula's Rust auto-close handling, Enter expands the pair into two lines. The inner line receives four spaces beyond the existing line indentation, the closing brace keeps the original indentation, and the caret lands after the inner indentation. Existing Enter behavior remains for non-Rust files, source-authored brace pairs, selections, and active IME composition.

The implementation reuses the shared, versioned auto-close marker and Rust-authoritative UTF-16 TextOps path. It checks the adjacent two-character pair before expanding, counts that read against the existing edit budget, and records the inner caret offset separately from inserted text length. Undo/redo, sibling views, dirty state, and save use existing workbench paths. No Rust crate or FFI ABI changed.

This slice covers the fixed Code-OSS Rust configuration's empty brace-pair Enter case only. It does not yet add token-aware Enter rules for source-authored pairs, comment continuation, `()` / `[]`, quotes, or configurable `tabSize` / `insertSpaces` settings.

- [Pinned `OnEnterSupport`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/languages/supports/onEnter.ts) returns `IndentOutdent` when the processed text before and after Enter matches an open/close bracket pair.
- [Pinned Enter edit operation](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/cursor/cursorTypeEditOperations.ts) inserts an indented caret line followed by a line at the original indentation for `IndentOutdent`.
