# P04.12 — Mouse triple-click logical-line selection

Date: 2026-10-31. Status: done.

## Behavior

The pinned Code-OSS source routes a third mouse down to `LineSelect`; line selection includes the line terminator when a following line exists and stops at EOF on the last line. References: [`viewController.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/browser/view/viewController.ts) and [`cursorMoveCommands.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/cursor/cursorMoveCommands.ts).

Flutter's Linux default triple-tap selection omitted the LF in the fixture (`[0,13)` instead of `[0,14)`). `RustTextInputField` now recognizes an unmodified primary mouse triple-click on Linux, resolves the clicked document line with Rust `lineBoundary`, and extends the selection over its LF/CRLF terminator using a bounded two-unit `readRange`. Windows and macOS keep Flutter's platform selection. The existing Alt+Click path remains available. No Rust, FFI, ABI, or file contents are changed.

The correction applies when the full selected line fits in the current bounded input window. A line that extends past that 16K UTF-16 window cannot be represented by the current Flutter `TextSelection`; the handler skips the correction for that case. Cross-window line selection remains an editor follow-up.

## Evidence

`app/test/workbench_mouse_triple_click_test.dart` runs nine cases: Windows/Linux/macOS target platforms crossed with an LF-terminated line, a CRLF source file, and a final line without a terminator. The fixtures include an emoji before the click target. Every case checks the selection range and selected text, Flutter/Rust authoritative text, document version, and unchanged source bytes on disk.

The CRLF source fixture is loaded into the current Rust document as LF text; the test records this existing normalization and checks both the normalized editor text and unchanged CRLF disk bytes. It does not claim CRLF-preserving load behavior.
