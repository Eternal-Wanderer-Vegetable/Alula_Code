# P04.4 / EDT-01a — Character cursor movement and selection

Date: 2026-10-31. Status: this sub-slice is complete; P04 / feat-026 remains active.

## Scope

Lock down the workbench's existing Flutter `EditableText` character movement path for
horizontal arrow keys and Shift selection. This slice does not cover word or subword
boundaries, vertical/page movement, line/file boundaries, or smart Home behavior.

## Evidence

`app/test/workbench_cursor_movement_test.dart` runs the workbench against Windows and Linux
Flutter target platforms using the source `a😀b`:

- With the caret at UTF-16 offset 3 (after the supplementary rune), ArrowLeft moves to offset 1
  without placing the caret inside the surrogate pair.
- Shift+ArrowRight extends from the existing anchor at offset 1 to offset 3, selecting the
  complete emoji.
- ArrowLeft at document offset 0 keeps the caret at 0.
- Rust `resync()` still returns the exact source and the Rust document version is unchanged,
  so movement changes only the view selection.

The test sends Flutter key events. It proves behavior through the workbench widget tree, not
physical platform keyboard routing or a Windows 11/Linux DRM desktop session.
