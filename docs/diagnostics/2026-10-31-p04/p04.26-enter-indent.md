# P04.26 — EDT-06b: Enter inherits leading indentation

Date: 2026-10-31
Status: complete; P04 / feat-026 remains in progress.

## Reference and scope

Reference: Code-OSS commit [`4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/cursor/cursorTypeEditOperations.ts#L590-L664), `_enter` fallback. When no language enter rule is returned, the fallback uses the leading whitespace before `selection.start` as the new line's indentation.

Unmodified Enter and NumpadEnter in the focused editor now apply that fallback through Rust `lineBoundary` / bounded `readRange` and existing UTF-16 `TextOp`s. Selection replacement uses the selection start's indentation; every caret in a multi-cursor edit is handled against one document version. The existing 10,000-selection and 2,000,000-unit undo bounds, overlap rejection, dirty/undo/save, sibling-view refresh, and input-method composition guard remain in force. There is no FFI or ABI change.

This slice does not add language-provided enter rules, bracket-aware indentation changes, smart empty-bracket Enter, or bracket/quote pairing. With active composition, Enter is left to the input method.
