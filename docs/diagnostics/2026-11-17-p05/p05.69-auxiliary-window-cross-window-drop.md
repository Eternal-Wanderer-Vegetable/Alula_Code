## 目标与边界

允许用户从主窗口拖动一个 editor tab，并将它释放到当前已打开的 auxiliary editor window。Alula 的 auxiliary 目前只有单文档视图，没有 VS Code 式多文档标签组。本 slice 采用可理解的单窗交换语义：拖入的主窗口文档进入目标 auxiliary；原 auxiliary 文档完整返回主窗口；成功后源主组只移除被拖动的视图。不能静默覆盖或丢弃任一文档。

仅覆盖主窗口到已存在辅助窗的 move。拖到主窗已有 editor group 的行为不变；拖到所有现存窗口外继续创建新 auxiliary window。若坐标/目标窗不可用、请求未确认或文档不能交换，则保留主窗源文档和 aux 目标文档。对不支持全局桌面坐标的 Wayland 保留当前“不可 tear-out”的策略。

辅助窗只通过独立 `alula_auxiliary_window_bounds` 方法上报 bounds：注册后首次上报，在 move/resize 事件中更新，关闭时删除。主窗 registry 复用现有 `maxAuxiliaryFocusWindows`（32）上限，不做轮询。此几何消息不加入 P05.67 活动 window/group focus channel。文档 path/name/text/dirty 只在被确认的拖放事务里发送；不加入常驻文档同步，不同步 selection、undo/redo、savepoint 历史、session 或焦点。不要扩展 FFI ABI 或 Rust crate。

明确排除：auxiliary -> main 或 aux -> aux 的拖放、跨窗口复制 modifier、aux 多文档/tab/group UI、selection/undo 历史跨窗、focus/command 路由、窗口布局持久化及通用窗口管理重构。Compact、always-on-top 与 window/group focus 继续由 P05.66–68 独立处理。

## 实现与验收日志

### 产品实现

- 新增 `auxiliary_window_transfer.dart`：独立 bounds/transfer channel 常量、有限数值校验、32 个 ID 的有界 registry、stale sequence 拒绝和重叠 bounds 歧义拒绝。bounds 只在 auxiliary 注册后、窗口 move/resize/maximize/restore 事件中上报；无轮询。主窗只接受当前登记的 auxiliary ID，关闭和 dead-window 清理时移除 bounds。
- auxiliary 使用 prepare/commit/abort/status 事务接收主窗文档并返回原目标快照。prepare 阶段保留原目标文档并锁住编辑输入；只有明确确认 commit 后主窗才移除源视图并恢复 auxiliary 原文档。失败或状态不明时源文档保留，返回快照保留在主窗，并显示状态提示；commit/status/abort 支持重复查询恢复。close 使用交换后的当前 path/name/text/dirty；成功 commit 后 auxiliary 的 native window title 同步为拖入文档名。
- 主窗拖放 hit-test 命中唯一登记 auxiliary 时执行交换；多个窗口 bounds 重叠、坐标未知、无效或目标不可达时保留源文档；所有窗口外沿用既有创建新 auxiliary 路径。旧 editor 的迟到输入回调在 prepare 阶段及替换后会被丢弃，避免写入已交换文档。
- P05.67 focus snapshot 的 window/group-only payload 未改变；没有 document identity、文本或 selection 加入 focus channel。未改 Rust crate/FFI ABI；不引入常驻轮询或新的常驻缓存。
