## 产品修复

`_openFileByPath` 原来用 `d.path == path` 查找已打开文档。Windows session/测试载荷可包含 `/`，Rust directory listing 返回 `\`；同一文件因字符串不同创建第二份 Rust 文档，预览状态失效、标签路径消歧变长。改为使用已有 `_canonicalPath` 比较绝对路径、分隔符和 Windows 大小写，复用既有共享文档/视图路径。无 Rust/FFI/ABI、存储 schema、目录扫描或新常驻缓存改动。

现有 `preview state is isolated and restored per editor group` 用例在测试节点路径修正后先红（重复 pinned.rs，`Too many elements`），产品修复后通过该阶段，直接覆盖重开原 permanent tab 不应生成第二标签。

## 测试修复

- Explorer 节点定位与 journal 中路径比较使用本机规范路径；继续严格比较完整路径，不使用 basename/后缀规避身份检查。
- Recent History / Welcome 使用规范化的本机绝对路径作为期望；Paste As 比较跨平台等价路径。
- Workspace edit 测试 URI 与工作台约定一致：Windows 盘符小写；Rust 内存文本按 LF 口径比较，磁盘 fixture 可保持 CRLF。
- 合并与跨文档拖放测试显式点击已有 tab，避免 `find.text(...).first` 命中 Explorer 重新打开路径；dirty tab 允许标题后缀，但仍限定 editor tab strip。

所有初次失败日志与中间失败保留。脚本因全局 core.autocrlf 检出 CRLF，以干净 index 内容检出 LF 后使用 Git Bash + `FLUTTER_BIN=/e/flutter/bin/flutter.bat` 运行，bundled Dart SDK 加入 PATH；没有修改仓库脚本内容或降低门禁。
