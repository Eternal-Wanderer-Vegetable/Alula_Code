# P04.93 / EDT-17a: bounded line-diff model

> Status: complete for the line-alignment model. Visual diff editor behavior remains open.

## Scope

The EDT-17 matrix calls for inline/side-by-side presentation, word-level changes, moved blocks, whitespace options, unchanged-region folding, and diff navigation. This first slice adds only the reusable line-alignment model; it does not change the existing Git panel or present a diff UI.

The reference is the pinned Code-OSS `DefaultLinesDiffComputer` at [`4bda7217`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/common/diff/defaultLinesDiffComputer/defaultLinesDiffComputer.ts). It aligns lines by trimmed content when `ignoreTrimWhitespace` is enabled and returns one-based, end-exclusive line ranges. Code-OSS also performs character refinement, small-input dynamic programming, moved-line detection, and view-model updates; those remain later slices.

## Implementation

- Added `computeLineDiff` with a Myers shortest-edit-path alignment and immutable `LineDiffHunk` results.
- Hunk ranges are one-based, end-exclusive; insertions and deletions use an empty range on the unchanged side.
- `ignoreTrimWhitespace` defaults to true and trims only for alignment. Set it false to treat leading/trailing whitespace changes as edits.
- Input and work are bounded before/while allocating: 2,000,000 combined UTF-16 code units, 8,192 lines per side, 2,000,000 Myers frontier-history cells, and 4,000,000 comparison/diagonal operations by default. Exceeding a bound returns one explicit whole-document hunk with an input/work fallback reason; it does not silently omit changes or keep computing.
- Added deterministic tests for insertion, deletion, replacement, separated hunks, repeated lines, whitespace, empty text/final newline, BOM, Emoji, CRLF, bounds, and 300 seeded randomized small input pairs. The randomized check verifies all unchanged alignment gaps and line-range monotonicity.
