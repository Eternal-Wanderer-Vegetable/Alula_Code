# P04.92 / CI-Crash-01: Windows 11 ARM replay of the current Release artifact

> Status: complete for the selected current artifact replay. This is non-reproduction evidence, not a fix or root-cause analysis for the historical crash.

## Question and historical signal

Historical run [`41454766973`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41454766973) replayed the x64 Release artifact from [`41109679662`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41109679662), source `d5319369`. Light and dark sessions posted `WM_CLOSE`, did not time out, and exited with `0xC000041D`; Windows Application Error records point to an access violation in `flutter_windows.dll` at offset `0x1e220`. That is a confirmed old-binary crash. The source-level cause remains unknown.

The follow-up asked whether the current x64 Release build also crashed on Windows 11 ARM and whether the repeated validation failures represented app crashes.

## Current artifact and final result

Replay run [`41627307864`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41627307864) used the exact x64 Release artifact from Platform Availability run [`41618233435`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41618233435): `alula-windows-x64-1129d607e10e28ed9ada90b185c59f8757a26686`, source `1129d607e10e28ed9ada90b185c59f8757a26686`. The hosted runner was Windows 11 Enterprise ARM64, using x64 emulation, at 96 DPI.

Both theme jobs passed, and both recorded the exact appended `view-2` text across all four accessible editor views, saved it, read it back from disk, posted `WM_CLOSE`, and exited gracefully with code 0. There were no Windows Application Error events or crash dumps. The initial replay attempt [`41623366222`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41623366222) and subsequent attempts [`41624838142`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41624838142), [`41625760177`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41625760177), [`41626282817`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41626282817), and [`41626759894`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41626759894) failed exact edit assertions while keyboard/clipboard injection intermittently lost a character. The failing sessions still closed with exit code 0 and had no application fault events or crash dumps. Across retries, the failing theme changed; one theme passed while the other lost one character. This identifies a flaky hosted input route in the validator, not a theme-specific crash. The exact assertions were retained and the final light/dark run passed.

PR CI for validator commit `34f1511` passed all four jobs in [`41627306984`](https://github.com/Eternal-Wanderer-Vegetable/Alula_Code/actions/runs/41627306984): Flutter analyze/tests, Linux and Windows Rust, and harness validation.

## Interpretation

The repeated current-artifact validation failures were harness input failures, and repairing that route improves CI signal quality. The current artifact did not reproduce the historical close crash on this hosted Windows 11 ARM configuration. These facts do not show that the validator change mitigates the old binary's crash or that the source-level crash is fixed. Keep the historical `0xC000041D` as an unresolved defect until a source cause is identified and a targeted fix is verified.

This replay also does not cover native ARM builds, Windows client hardware, Narrator, or manual device validation. Native macOS and Linux DRM/device gates remain separate.
