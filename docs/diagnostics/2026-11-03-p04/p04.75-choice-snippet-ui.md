# P04.75 / EDT-12c2: Choice Placeholder Suggestions and Acceptance

## Scope and compatibility target

Implement the choice list and acceptance behavior for the choice parser/session metadata completed in P04.74. The pinned Code-OSS 1.145.0 source registers an exclusive completion provider for choices, anchors items to the active choice range, and dispatches `jumpToNextSnippetPlaceholder` after accepting an item. Its snippet controller also keeps Shift+Tab bound to previous-placeholder navigation while the suggestion widget is visible.

- [`snippetController2.ts` at `4bda7217`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/snippet/browser/snippetController2.ts)
- [`suggest.ts` at `4bda7217`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/suggest/browser/suggest.ts)
- [`snippet.md` at `4bda7217`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/editor/contrib/snippet/browser/snippet.md)

This slice supplies a bounded, caret-anchored choice list, option preview, click/keyboard acceptance, and navigation semantics. Accepting an option replaces all linked occurrences through the existing Flutter formatter and Rust authoritative input path, then selects the next tabstop. It does not replace the general LSP completion widget. No Rust or FFI ABI changes are planned.

## Acceptance criteria

- Show the option list only while the active snippet tabstop carries choice metadata. Start with option zero highlighted.
- Up/Down cycle the highlighted option without changing document text; clicking an option accepts it. Enter and Tab accept the highlighted option. Shift+Tab continues to select the previous placeholder.
- Acceptance replaces the complete active choice range and its mirrors, updates the session version from the Rust delta, advances to the next placeholder, and remains undoable through the existing Rust history.
- Escape hides the choice list without cancelling the snippet session; a subsequent Escape follows the existing leave-snippet behavior. No choice list is shown at ordinary tabstops.
- Workbench fixtures cover linked choice ranges, manual focus/caret changes, UTF-16 emoji/CRLF positions, save/readback, one-step undo, and all choice key routes.
- Full repository DoD passes before implementation commit; hosted PR CI and Linux/Windows availability are recorded in a separate evidence stage. macOS native interaction remains pending where hosted input routing is unavailable.

## Implementation and local verification

Implemented as commit `58fdd31540c8a3e1054e11dcb9000de2e282d1e1` and pushed to `codex/vscode-parity-p00`; hosted evidence is recorded below and its documentation stage is pending.

- Added `SnippetChoiceSuggestionList`: bounded to 256 logical pixels wide and eight visible rows, with selected-option semantics, mouse preview, and click acceptance.
- `RustTextInputField` now provides an optional caret overlay surface. Its state computes caret geometry after layout and tracks editor scroll, while the popup clamps within the editor viewport and flips above the caret when needed.
- The workbench routes Up/Down to wrap the highlighted option, Enter/Tab to accept, Shift+Tab to previous placeholder navigation, and the first Escape to dismiss the list. A second Escape keeps the pre-existing snippet-session exit behavior.

- Workbench regression fixtures cover Up/Down preview without text mutation, Enter/click/Tab acceptance, linked-range replacement, Shift+Tab while the list is open, two-stage Escape, undo, save/readback, ordinary tabstop hiding, and an emoji prefix with CRLF file save roundtrip (the editor input window uses normalized LF internally).
