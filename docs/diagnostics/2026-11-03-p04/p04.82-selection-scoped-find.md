## Behavior

The find bar now has a Find-in-Selection toggle. Enabling it snapshots all
non-empty editor selections as half-open UTF-16 ranges. A selected trailing
CR, LF, or CRLF line ending is trimmed when the selection ends at the next
line's column 1. Overlapping selections are merged; adjacent selections stay
separate so a match cannot span their boundary. Literal and regex searches,
count/navigation/highlights, current replacement, and replace-all consume the
same scoped match list. Regex work remains in the existing cancellable,
750 ms isolate.

The snapshot is bound to its document ID and version. If the active document
or text version changes, the old range is discarded and Find-in-Selection is
turned off before computing new results. This prevents stale offsets from
being applied to another document or edited text. Ranges returned by both
search paths remain absolute offsets into original UTF-16 text; no Rust or FFI
change was needed.
