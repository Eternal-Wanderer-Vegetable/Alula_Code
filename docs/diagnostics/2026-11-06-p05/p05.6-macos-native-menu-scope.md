## 目标

macOS 使用系统原生菜单栏呈现 Alula 当前已实现且可用的 File、Edit、View 菜单；菜单动作与其他入口共用 `CommandService`、显隐/启用条件、参数及快捷键。应用菜单提供 About、Services、Hide、Hide Others、Show All、Quit；About 复用现有 `help.about`，Quit 复用现有窗口关闭和工作区清理流程。自定义窗口标题栏仍保留应用名/拖动区域，macOS 系统菜单不再重复绘制在窗口客户区。Windows/Linux 的 Flutter 菜单行为保持原样。

## 固定参考与平台 API

- 固定 Code-OSS 的 Electron `menubar.ts` 通过应用级原生菜单安装 macOS menubar，包含应用菜单、Window/Help 等菜单；macOS 应用菜单包含 About、Services、Hide、Hide Others、Show All、Quit。菜单动作携带固定命令 ID 回到 renderer 执行。参考：[菜单构造与 `setApplicationMenu`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/platform/menubar/electron-main/menubar.ts#L2479-L2653)、[命令回传](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/platform/menubar/electron-main/menubar.ts#L3183-L3217)。
- Flutter `PlatformMenuBar` 用宿主平台原生 API 构建菜单、支持递归 `PlatformMenu`、系统提供菜单项和原生快捷键；Flutter API 要求每个应用同一时间仅一个活动 `PlatformMenuBar`，所以此实现只在唯一的 Workbench 标题栏建立一个菜单根。[PlatformMenuBar API](https://api.flutter.dev/flutter/widgets/PlatformMenuBar-class.html)、[系统提供菜单项](https://api.flutter.dev/flutter/widgets/PlatformProvidedMenuItemType.html)、[菜单项选择回调与快捷键](https://api.flutter.dev/flutter/widgets/PlatformMenuItem-class.html)。本地 Flutter SDK 对应实现位于 `/home/vegetable/develop/flutter/packages/flutter/lib/src/widgets/platform_menu_bar.dart`。
- Alula 固定工作台目前只注册 File、Edit、View、Help 四组；File 菜单按 P05.4/P05.5 只包含已实现命令。其他 VS Code 默认菜单/命令尚未实现，本切片不会创建占位项。Alula Help 目前只含 About，因此 macOS 将它放入应用菜单并省去空 Help 顶层菜单，避免 About 重复。

## 范围与边界

- 仅 `TargetPlatform.macOS` 建立单一 `PlatformMenuBar`；把当前可见 `TitleMenuItem` 递归投影到原生菜单，规范化分隔线、子菜单、mnemonic 标记和单键快捷键。命令启用状态随 `CommandService` 更新，隐藏命令从原生菜单移除。

- 不增加 Swift/AppKit/FFI 通道，不修改 Rust ABI、通用命令语义、键位注册表、workspace 生命周期；不补齐尚未实现的 File/Edit/Selection/View/Go/Run/Terminal/Window/Help 菜单命令，不做内存数值优化。macOS hosted 只提供 Intel x64 构建/启动证据；Apple Silicon、原生设备与签名/公证留 P15/发布门。
