# P05.7 / LAY-02a：默认窗口标题与 dirty 状态

日期：2026-11-06。分支 `codex/vscode-parity-p05`，PR #3（draft）。固定参考为 Code-OSS 1.145.0-dev，commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`。

## 范围

复刻 VS Code 默认窗口标题的当前可用部分：活动文档短名称（存在时）、未保存标记、工作区根名称（存在时）和 `Alula Code`。活动文档、工作区、dirty、保存和另存路径变化时，标题栏文本与宿主窗口标题同步更新。分隔符遵循平台默认（macOS ` — `，Linux/Windows ` - `）。

Code-OSS 在 [windowTitle.ts（固定 commit）](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/titlebar/windowTitle.ts#L33-L49) 定义默认模板与平台分隔符；dirty 指示在默认模板中为 `● `，macOS 原生窗口使用系统 dirty indicator。其标题计算从活动编辑器、workspace、profile 变化订阅并写入原生窗口标题，见 [WindowTitle 实现](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/titlebar/windowTitle.ts#L102-L120) 和 [原生标题更新](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/titlebar/windowTitle.ts#L173-L196)。

## 本地实现与回归验证

- 新增纯 Dart `WorkbenchWindowTitle.compose`，按平台分隔符组合活动文件、dirty 标记、workspace、可选 profile 与应用名；空字段不留下多余分隔符。`WorkbenchPage` 只在 widget build 时从现有活动文档和 workspace 状态取值，无轮询/新增缓存。标题条限制宽度并显示 ellipsis，Tooltip 保留全标题；`WindowChromeDriver.setTitle` 在真实窗口标题栏挂载、标题变化或驱动变化时同步。窗口 API 失败只记录 debug 信息，不阻断编辑。
- window_manager 插件暴露 `setTitle`，未提供 macOS `setDocumentEdited`。因此 dirty 使用显式 `● ` 字符并显示在 macOS 标题上；Code-OSS macOS 默认使用系统 dirty dot，这是已知视觉差异，后续若插件提供原生 edited state 可收敛。本实现仍保证三平台都能看出 dirty 状态。
- `workbench_window_title_test.dart` 3/3（空值、workspace/profile、Linux/Windows/macOS 分隔符、dirty/untitled）；`title_bar_test.dart` 15/15（初值与更新向窗口驱动同步）；整个 `widget_test.dart` 26/26，覆盖 `note.txt → 未命名 → dirty → Save As 新名/清洁 → 切回另一个 dirty 文件`。
- `bash init.sh` 全绿：Rust workspace、Clippy、`build_core`、Flutter 1,047/1,047；`cargo fmt --all -- --check`、Flutter analyze 0 issues、Harness 100/100、feature JSON、`git diff --check` 均通过。第一次完整运行仅旧启动断言仍期待标题显示裸 `Alula Code` 失败；更新断言以验证动态标题含应用名后，全工作台测试及第二次完整 DoD 均通过。
