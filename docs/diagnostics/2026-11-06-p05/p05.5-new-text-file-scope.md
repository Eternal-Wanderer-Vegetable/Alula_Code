## 目标

交付 VS Code 默认 File > New Text File：命令面板与标题栏 File 菜单可执行，每次调用在当前 editor group 中新建独立的空白未命名文档；Windows/Linux 使用 Ctrl+N，macOS 使用 Cmd+N。工作台继续通过现有 Rust 文档核心持有新文档，使用现有 session journal 保存/恢复。该切片仅实现这一默认动作，不扩展其他 File 命令。

## 固定参考事实

- 固定版 `fileActions.contribution.ts` 将 New Text File 注册在 Menubar File 的 `1_new` 组、order 1，命令 ID 为 `workbench.action.files.newUntitledFile`，标题 `New Text File`；它位于 File 的 Open 组之前。[fileActions.contribution.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/files/browser/fileActions.contribution.ts#L2967-L2983)
- 固定版 `fileCommands.ts` 对该命令注册 `CtrlCmd+N`，调用编辑器服务创建未命名文档；此 Workbench 是桌面版，不采用 Web 专属替代键位。[fileCommands.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/files/browser/fileCommands.ts#L2855-L2929)
- 固定版将 New Text File 暴露于 File 菜单和 Command Palette；标题栏必须调用同一命令身份，以保持菜单、键位、命令面板共用一个 handler。
- Alula 当前启动时创建 id `1` 的欢迎未命名文档，`_nextDocId` 从 `2` 开始；文件打开通过 `AlulaCore.openDoc` 创建 Rust 文档、构造 `OpenDoc` 并附加到当前 `EditorGroup`。当前 File 菜单尚无新建文本文件动作。

## 范围与边界

- 注册固定 ID `workbench.action.files.newUntitledFile`，通过现有 CommandService 暴露给命令面板与标题栏菜单；设置菜单标签、同一命令 ID 和按平台解析的快捷键提示。
- 在 File 菜单 `1_new` 组将新建项排在 Open Folder 之前；保留 P05.4 的其他项目与 context 显隐行为。
- handler 每次创建一个新的空内容 Rust-backed `AlulaDoc`，使用不冲突的 `_nextDocId`，构造未命名 `OpenDoc` 并追加/激活于当前 editor group；不得替换欢迎页、其他未命名编辑器或其他 group 文档。关闭、保存为路径、dirty、undo、双视图与 journal 恢复沿用既有文档路径。
- Windows/Linux 默认 Ctrl+N，macOS 默认 Cmd+N；用户 `keybindings.json` 移除/重绑仍按现有 `KeybindingSet` 规则生效。
- 回归覆盖菜单排序/快捷键提示、三平台默认键位与用户覆盖、连续两次新建的不同 ID/独立文本、激活当前组、未命名保存为磁盘文件读回、session journal 恢复。
- 不实现 Open File/Workspace/Recent、Save All、Auto Save、Close actions、macOS 原生菜单、其他顶层菜单、Rust/FFI/ABI、工作区窗口生命周期或数值内存优化；不启动本机 GUI/Narrator。
