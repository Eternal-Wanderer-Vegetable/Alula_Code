`in-progress`。这是 LAY-03 的单个子项；本切片只覆盖 Activity Bar 的 Side/Hidden 切换、命令路由与既有布局 JSON 持久化。它不会关闭 LAY-03 或 P05。

## 固定对照

- VS Code / Code-OSS `1.145.0`，固定源码提交 [`4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/activitybar/activitybarPart.ts) 的 `ActivitybarPart`。
- 上游注册 `workbench.action.activityBarLocation.default` 与 `workbench.action.activityBarLocation.hide`，并将 Activity Bar Position 子菜单放入 Menubar Appearance。当前 slice 只实现默认 Side 与 Hidden 两态；Top/Bottom 等定位和 Size 子菜单留给后续原子项。

## 当前实现与拟改动

- `ActivityBar` 作为固定 44px `activity` 叶子由 `WorkbenchGrid` 渲染。`WbSplitLayout.extentsFor` 与 `_NodeView` 已能将 `collapsed` 叶子分配为零宽并不构建子 widget；`WorkbenchLayout.toggleRegion` 当前拒绝固定尺寸叶子。
- 新增目标态布局 API，让固定 `activity` 叶子可被明确隐藏/恢复，保留 44px 固定尺寸和当前 `_sidebarView`。布局 listener 复用现有 `LayoutStore` root JSON 保存/加载，避免另加状态存储。
- 注册固定上游命令 ID `workbench.action.activityBarLocation.hide` 与 `workbench.action.activityBarLocation.default`；在 View > Appearance 下提供 “Activity Bar Position” 子菜单，Side/Hidden 项以布局实际状态呈现 checked。菜单始终可达，以便隐藏后恢复。

## 验收标准

1. WorkbenchLayout 定向测试：默认 fixed activity 可见；执行隐藏后 `collapsed=true`、分割分配为零宽；恢复后仍为原 44px，重复设定同一目标状态不发出伪变更。
2. LayoutStore round-trip 保存/加载隐藏态；恢复显示后固定宽度、当前 primary view 不丢失。
3. Workbench 集成测试覆盖 View > Appearance > Activity Bar Position > Hidden/Side，菜单 checked 状态随命令执行刷新；隐藏后 ActivityBar subtree 消失，恢复后重新出现；其他 sidebar/panel 路由不变。
4. 使用现有布局自动保存路径验证 app remount/restart 后隐藏状态保留；无需启动本机桌面 GUI 或 Narrator。
5. 完成聚焦 Flutter tests、`cargo fmt --check`、`flutter analyze`、本地完整 `bash init.sh`、Harness 和 JSON/diff 检查；更新状态/evidence 后提交、推送，等待 PR CI 与 Linux/Windows/macOS Intel x64 Platform Availability。
6. 提交前执行 GitNexus all-scope 与 compare-to-main change analysis，保存原始风险与覆盖限制。不得把 `UNKNOWN`、零 caller、截断流程或不相关映射称为 clean。
