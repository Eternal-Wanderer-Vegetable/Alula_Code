## 状态

done。本项只覆盖 LAY-03e 的 Activity Bar 四个既有视图项排序；P05、LAY-03 均保持开放。

## 固定对照

固定 VS Code / Code-OSS `1.145.0`，提交 [`4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`](https://github.com/microsoft/vscode/tree/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e)。`ActivitybarPart` 创建垂直 Composite Bar；`PaneCompositeBar` 配置拖放回调，在同一 bar 拖动时调用 `CompositeBar.move(from, to, before)` 并保存 view-container 状态。VS Code 将此排序存在 profile storage 的 `workbench.activity.pinnedViewlets2`。上游实现：[ActivitybarPart](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/activitybar/activitybarPart.ts)、[PaneCompositeBar](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/paneCompositeBar.ts)、[CompositeBar](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/compositeBar.ts)。

## 代码现状与范围

- ActivityBar 当前按 `explorer`, `search`, `outline`, `git` 固定生成 view items；P05.10 已提供按钮/选中语义、键盘焦点与方向键导航，P05.11–P05.13 已覆盖 Side/Top/Bottom/Hidden 与 Default/Compact 大小。
- 本切片允许四个既有 view items 通过 desktop pointer drag/drop 重排。Side 使用垂直前后插入方向，Top/Bottom 使用水平前后插入方向。选择中的 view 按 ID 保持；焦点与键盘遍历顺序跟随新顺序。相同位置 drop 不改状态；Manage 固定在 bar 末端/底端，不参加排序。
- 将 `activityBarOrder` 存为现有 `~/.alula/layout.json` 根 `WbSplit` 元数据；旧 JSON 无该字段时使用当前默认顺序。读入时仅接受四个已知 ID，移除重复/未知值，再按默认顺序补齐缺项。Side/Top/Bottom/Hidden 与 Default/Compact 切换均保留排序。
- 对 Code-OSS profile-scoped `workbench.activity.pinnedViewlets2` 的行为差异：本应用沿用既有全局布局文件，不在此处引入 Profiles/settings 基础设施；profile 隔离仍归 P07。
- 排序更新必须立即反映于 UI，并经现有布局变更通知/保存路径写入文件。不得改变当前 view、Sidebar 折叠状态、Activity Bar 位置/大小、Editor split 树或权重、Panel 状态。
