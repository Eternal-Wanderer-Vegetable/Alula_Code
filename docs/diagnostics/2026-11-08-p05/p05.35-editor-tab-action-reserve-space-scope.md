# P05.35 / feat-087 / LAY-08f — editor tab close-action space reservation

## Fixed baseline and source behavior

- Baseline is Code-OSS 1.145.0. `DEFAULT_EDITOR_PART_OPTIONS.tabActionReserveSpace` is `true` and the option is Boolean-validated in [`editor.ts`](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/editor.ts#L31-L37) and [`editor.ts` validation](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/editor.ts#L121-L130).
- `MultiEditorTabsControl` redraws when `tabActionReserveSpace` changes. The modern UI has fit-tab width handling for reserved and unreserved actions, and freezes a fit tab's width as the pointer enters it: [`multiEditorTabsControl.ts`](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts#L872-L889), [fit-width layout](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts#L1958-L2023).
- The setting is documented as a Modern UI customization: disabling it gives clean inactive tabs more room. Alula has one current tab-strip style, so this slice applies the equivalent action-space behavior to that strip, without implementing the Modern UI pill/connected visual treatments. Reference: [VS Code Modern UI documentation](https://github.com/microsoft/vscode-docs/blob/main/blogs/2026/10/15/modern-ui.md).

## Registered scope

Implement the `workbench.editor.tabActionReserveSpace` equivalent for ordinary, closeable editor tabs in every editor group:

- Default to `true`, preserving P05.34's current 18 px action-and-gap allocation for every ordinary tab.
- Expose an accessible checked toggle in View > Appearance > Editor Tabs; apply it to all groups immediately and store it in the session journal. Older sessions with no field default to `true`.
- When disabled, clean inactive tabs omit the 18 px action-and-gap allocation. Their close control remains available and overlays the tab edge when hover or keyboard focus reveals it. Active or dirty tabs continue to allocate the action slot while Close visibility is enabled, so persistent close/dirty affordances keep their room.
- Preserve left/right action placement, fit/shrink/fixed sizing, wrapping, close-action visibility behavior, focus/semantics, hit targets, drag targets, document order, and editor/document state. Do not modify document text, selection, scroll, Rust state, or layout-tree persistence.
- A disabled Close-visibility setting continues to disable pointer, keyboard activation, and semantics. With reservation disabled, it removes the unused action slot from tab width; with reservation enabled, the default reserved allocation remains.

## Out of scope

- Sticky/pinned tabs, unpin controls, separate pinned rows, and `tabActionUnpinVisibility`.
- Modern UI pill/connected styling, custom action backgrounds, gradients, shoulder geometry, and animation.
- The Settings editor, global/user/workspace configuration, profiles, or precedence. This is a session-scoped workbench control pending P07.
- Other icon, path-disambiguation, overflow, close-menu, drag/drop, or tab-sizing algorithm changes.
- Rust, FFI, ABI, document lifecycle, and editing behavior.
