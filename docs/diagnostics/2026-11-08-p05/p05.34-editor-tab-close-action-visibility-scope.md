Source: [multiEditorTabsControl.ts at 1.145.0](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts#L1598-L1632).
- The pinned stylesheet reveals action glyphs for active, hovered, focused, and dirty tabs; inactive-group actions are dimmed. A hidden close action does not remove a dirty marker. Source: [multieditortabscontrol.css at 1.145.0](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css#L394-L483).

tabActionReserveSpace (default true) and tabActionUnpinVisibility (default true) are separate settings in the same upstream defaults. They are out of this slice. Pinned/sticky unpin behavior, pinned-tab sizing/separate row, Settings UI, and user/workspace configuration precedence also remain separate slices. Alula exposes this slice through the existing session-persisted View > Appearance > Editor Tabs controls; it does not claim that the P07 Settings editor is implemented.

## Scope

Implement workbench.editor.tabActionCloseVisibility-equivalent behavior for ordinary, closeable, unpinned tabs:

1. Default to visible; parse absent or invalid session data as true.
2. Add an accessible checked toggle under View > Appearance > Editor Tabs. It applies immediately to every editor group and persists in the session journal, not the layout JSON.
3. When enabled, show the close glyph on the active, hovered, focused or dirty tab; idle clean tabs render the glyph at zero opacity while keeping the default reserved action slot. Retain the existing dirty marker and action placement for left/right modes.
4. When disabled, hide and disable the close action even for active, hovered, or focused ordinary tabs. Preserve dirty text/marker, document/model identity, middle-click, edit/save behavior, and tab geometry with the default reserved action space. Alula's current keybinding registry has no editor-tab close binding; this slice does not add or remove keyboard mappings (handled by a separate CMD child if registered).
5. Closing a dirty document continues to use the existing close/confirmation path.
