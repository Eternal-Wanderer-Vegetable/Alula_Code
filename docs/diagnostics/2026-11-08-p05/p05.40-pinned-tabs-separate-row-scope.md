# P05.40 / feat-092 / LAY-09c — Pinned tabs on a separate row

## Fixed baseline and upstream behavior

- Baseline: Code-OSS commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- `workbench.editor.pinnedTabsOnSeparateRow` is a boolean with default `false`. In `multiple` tab mode, `EditorTitleControl` chooses `MultiRowEditorControl` when it is enabled; a setting change rebuilds that control. `single`/`none` modes do not use the multi-row control. Sources: [editor.ts defaults and validation](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editor.ts#L1188-L1217), [editorTitleControl.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorTitleControl.ts#L689-L718) and [option update](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorTitleControl.ts#L843-L868).
- `MultiRowEditorControl` creates sticky and unsticky tab controls over filtered views of the same editor group. Sticky tabs render above ordinary tabs; the second bar is shown only when at least one sticky and one ordinary editor exist. Layout height combines both controls; open/close, move, pin, stick/unstick, active state, and option updates route to the appropriate control. Source: [multiRowEditorTabsControl.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/multiRowEditorTabsControl.ts#L653-L724) and [operations/layout](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/multiRowEditorTabsControl.ts#L783-L947).
- The current Alula P05.39 behavior keeps sticky tabs in a contiguous group-local prefix on the default single row. P05.31 and P05.39 explicitly left separate-row behavior out of their scope; this slice follows that dependency.

## Registered scope

- Add a session-backed boolean for `pinnedTabsOnSeparateRow`, default `false` for new and legacy sessions. Expose it as a checked toggle beside the other editor-tab presentation controls under View > Appearance > Editor Tabs. While P07 Settings and configuration precedence are not implemented, this is the accessible Alula control for the option; do not register a false upstream command or claim user/workspace/profile settings support.
- In `multiple` tab mode with the option enabled, render group-local sticky tabs in a top row and ordinary tabs in a second row. Collapse to one row when there are no sticky tabs or no ordinary tabs. With the option disabled, retain the existing shared row. `single` and `none` modes retain their existing visibility behavior; the option value remains saved and applies when multiple tabs are shown again.
- Keep one editor action toolbar, use available width and existing fit/shrink/fixed sizing policies per row, and preserve horizontal scrolling or wrapping independently per row. Switching the option must update the layout immediately and relayout the editor content below it.
- Pin/Unpin moves a tab between rows without changing document/view identity, active focus, dirty state, selection, undo, or Rust document state. Preserve sticky-prefix ordering, per-row drag/reorder limits, active-tab reveal, and tab accessibility labels/actions.
- Persist and restore the boolean through the existing debounced session journal. A journal with no new field restores the default `false` value. The option is application-session state until the P07 settings slice adds user/workspace/profile configuration and precedence.
- No Rust, FFI, ABI, text protocol, pinned-tab sizing, or configurable pinned-close policy changes.
