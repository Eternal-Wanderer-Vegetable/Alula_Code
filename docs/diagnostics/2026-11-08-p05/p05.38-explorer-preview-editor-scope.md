# P05.38 / feat-090 / LAY-09a — Explorer preview editor replacement and pinning

## Fixed baseline and upstream behavior

- Baseline is Code-OSS commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- The pinned [editor defaults](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editor.ts) set `enablePreview: true`, while `enablePreviewFromQuickOpen` and `enablePreviewFromCodeNavigation` are false. This slice therefore covers Explorer single-click preview; the other default open routes remain permanent.
- The pinned [editor group model](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/common/editor/editorGroupModel.ts) replaces the group's existing preview when a new unpinned editor opens. Pinning clears preview state. The pinned [editor group view](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorGroupView.ts) pins an editor when it first becomes dirty.
- The [VS Code user interface guide](https://github.com/microsoft/vscode-docs/blob/main/docs/editing/getting-started/userinterface.md#preview-mode) describes Explorer single-click preview, italic labels, and double-click or editing to keep an editor open.

## Registered scope

- Explorer single-click opens a file as that editor group's sole preview. Reopening the same already-open permanent editor activates it without downgrading it.
- Opening another file as preview closes/replaces only the previous clean preview in that group. A dirty preview is pinned before it can be replaced, preserving its buffer and save state.
- A second Explorer click on the current preview pins it. The first text-changing edit pins it immediately and removes italic preview styling; undoing back to the savepoint does not turn it back into a preview.
- Preview state belongs to the editor group, follows the tab when it is moved, clears on close/replacement, and survives the existing session journal round trip. A dirty restored editor is permanent.
- Only an unpinned preview label is italic. Keep tab selection, sizing, wrapping, icon/action layout, document identity, undo history, Rust-authoritative text, file options, and save/readback behavior unchanged.
- Existing Quick Open, code-navigation, search, compare, merge, untitled, restore, and command opens stay permanent, matching the pinned defaults. No Rust, FFI, ABI, or document schema change.

## Out of scope

- Preview settings and their UI; Quick Open or code-navigation preview behavior; explicit Pin/Unpin commands, menus, icons, and close rules; sticky editors; editor-limit behavior; Open Editors view integration. These need their own LAY/CMD slices.
- General editor-group movement or drag/drop redesign. Moving a preview must preserve its preview state and leave any target-group preview governed by the explicit registered tests, without changing existing movement behavior.

## Definition of done

- Unit tests cover preview-open, same-preview activation/pin, replacement, clean/dirty gating, close, and per-group isolation.
- Widget tests cover Explorer single-click italic preview, replacement by another single-click, repeated-click pin, and first-edit pin. After pinning, opening another file preserves the prior tab and its document identity. Existing permanent files do not become previews.
- Session tests restore a clean preview as preview and a dirty editor as permanent; closing or moving the preview leaves valid group/active-editor state.
- An edit/save/readback fixture includes BOM, CRLF, and non-BMP text. Assert Rust text, UTF-16 selection, dirty/savepoint state, encoding/EOL options, and disk bytes before and after preview replacement/pinning. Assert editing and undo history remain intact.
- Run focused tab/Explorer/session/editor suites, `bash init.sh`, `cargo fmt --all -- --check`, Flutter analyze, Harness validation, JSON validation, and `git diff --check`. On the final product head, require PR CI and Linux x64, Windows x64, and macOS Intel x64 build/test/launch/package. Report hosted macOS native DnD as skipped if its input route remains unavailable.
