## Fixed reference

- Code-OSS 1.145.0 sets `tabActionLocation` to `right` by default and validates the enum as `left` or `right`. Source: [editor.ts defaults](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/editor.ts#L35-L41) and [option validation](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/editor.ts#L130-L162).
- When these tab options change, the editor tab control redraws tabs. Its close action selects a `left`/`right` class from `tabActionLocation`. Source: [multiEditorTabsControl.ts option redraw](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts#L955-L969) and [tab action placement](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts#L1748-L1787).
- The pinned CSS reverses the tab row for left-side actions and adjusts the corresponding edge padding. Source: [multieditortabscontrol.css, left actions](https://github.com/microsoft/vscode/blob/1.145.0/src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css#L312-L320).

## Scope

Implement the ordinary, unpinned editor tab close action location for the fixed Code-OSS 1.145.0 behavior:

1. Add a session-persistent `workbench.editor.tabActionLocation` equivalent with `right` as the default and `left`/`right` values.
2. Offer an accessible mutually exclusive View > Appearance > Editor Tabs > Close Action Position submenu; changes apply immediately to every editor group and restore from the session journal.
3. Put the existing close action before the label on the left and after the label plus optional disk-state marker on the right. Preserve the close target, active document, and Rust editor/input state through toggles and resize.
4. Keep sizing modes and wrapping usable in both positions; tab sizing calculations must continue to include the action width and edge padding.

The close-action visibility setting/hover behavior, reserved-space option, pinned/sticky unpin action, icons, label/path disambiguation, and Settings UI/user-workspace precedence are separate P05/P07 slices. This slice does not change the close button's existing visibility.
