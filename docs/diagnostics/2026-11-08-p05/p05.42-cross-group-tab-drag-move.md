# P05.42 / feat-094 / LAY-10b — Cross-group tab drag move

## Fixed baseline and upstream behavior

- Baseline: Code-OSS 1.145.0 commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- The tab strip registers drag start/enter/leave/end/drop handling and routes a tab-strip drop through its `onDrop` path. Source: [`multiEditorTabsControl.ts`, drag/drop registration](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts#L2945-L3036).
- Moving an editor across groups opens it in the destination first, then closes the source. The moved editor is pinned and sticky state is preserved; text-editor view state is carried into the destination. Copy is a separate `keepCopy` path and is excluded from this slice. Source: [`editorGroupView.ts`, move/copy behavior](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorGroupView.ts#L1280-L1431).

## Current Alula behavior and gap

- `app/lib/workbench/workbench_page.dart` builds every tab with `Draggable<int>` and a `DragTarget<int>`. The target callback closes over the same `EditorGroup` and calls `_moveDoc(g, draggedId, targetId)`, which resolves both IDs only in `g.docs`; this supports same-group reorder only.
- `_moveFocusedEditorToGroup` already moves the focused document through the directional commands. It preserves the document object, sticky membership, focus node, and preview designation; it does not accept the pointer's source tab or insertion position.
- `app/test/editor_tab_wrap_test.dart` covers same-group reorder in wrapped and sticky/separate rows. No cross-group tab pointer-drop test exists. The group direction commands remain separate regression coverage.

## Registered scope

For one tab dragged from a non-empty source group's tab strip onto a tab in a different non-empty group:

- Resolve the source group and document at drag start; resolve the destination group and tab at drop. Ignore stale source/target identities safely.
- Insert before or after the destination tab according to the pointer's position relative to that tab. Activate the moved document and destination group. Keep existing same-group reorder behavior.
- Move the same `OpenDoc` view and preserve Rust-backed text, dirty/savepoint state, undo history, selection/caret, scroll, and editor focus identity. Preserve sticky order; a clean preview becomes a regular pinned tab on cross-group move, matching the fixed upstream behavior.
- If the destination group already has the same document view, activate that existing view and remove the source duplicate. If the move empties a source group while another group remains, remove the empty source region and group. Persist the resulting group/tab order through the existing session/layout save path.
- Preserve the existing directional move commands, middle-click close, and P05.41 dirty-safe close routes.

## Exclusions

- Copy/duplicate by modifier, drop into an empty group, drag to create a new group/window, cross-window transfers, Explorer/file drops, and tab overflow/MRU behavior are separate LAY-10 slices.
- No Rust/FFI/ABI change and no memory-budget retuning.
