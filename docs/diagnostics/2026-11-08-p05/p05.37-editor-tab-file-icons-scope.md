# P05.37 / feat-089 / LAY-08h — default editor-tab file icons

## Fixed baseline and source behavior

- Baseline is Code-OSS commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- In the pinned [editor part defaults](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editor.ts), `showIcons` defaults to `true`; `hasIcons` defaults to `true` with the comment that `vs-seti` is the default icon theme. `getEditorPartOptions` derives `hasIcons` from the active file icon theme. This slice implements the fixed default only; theme selection and configuration are later P07 work.
- The pinned [Seti theme package](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/extensions/theme-seti/package.json) declares the default icon theme identifier `vs-seti` and MIT license. Its [icon definitions](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/extensions/theme-seti/icons/vs-seti-icon-theme.json) include a default file glyph plus filename, extension, and language-id associations. Preserve the required license/attribution for any bundled theme material.
- The Seti theme font is WOFF. [Flutter's custom-font documentation](https://docs.flutter.dev/cookbook/design/fonts) states WOFF/WOFF2 fonts are unsupported on desktop, so use a desktop-supported representation while preserving the upstream license and glyph mappings.

## Registered scope

Render the Code-OSS default file icon next to each visible editor-tab label, using the pinned Seti default associations and fallback:

- `multiple` renders an icon for each visible file-backed tab; `single` renders the active document's icon; `none` renders no tab or icon. Pathless/untitled documents use the Seti generic file icon.
- Resolve special filenames before extensions, including compound extension matches where supplied by the default theme. Use the existing path-derived language ID only where the default theme's language association is needed; do not add a new language detector.
- Include icon width and gap in tab content measurement so fit/shrink/fixed sizing and wrapping remain consistent. Keep file icons decorative: the tab's full derived label remains its tooltip and accessible name.
- Preserve close-action and disk-state icons, editor identity/order, activation, document state, drag/drop hit targets, and session/layout data. The file icon must not intercept clicks or pointer events.
- Bundle only the default file-icon data needed for editor tabs and its licensing notice. No runtime network access or unbounded icon cache.

## Out of scope

- The `workbench.editor.showIcons` setting UI/configuration behavior, file icon theme selection (`workbench.iconTheme`), third-party icon themes, theme installation, and full light/dark/custom theme switching (P07).
- Explorer/file-tree icons and product icons; these belong to their respective LAY/THM slices. Pinned/compact icon-only tabs, preview/pinned/sticky semantics, tab action styling, and label formats beyond the completed default are separate slices.
- Changes to `OpenDoc`, file opening, path canonicalization, language detection, Rust, FFI, ABI, and persisted document/session schemas.

## Definition of done

- A pure icon policy test suite covers Seti special filenames, normal and compound extensions, case handling, existing language-ID fallback, generic/unknown fallback, and untitled/pathless documents. Expected glyph codepoints and colors are checked against the pinned source data.
- Widget tests verify icon presence and spacing in `multiple`/`single`/`none`, multiple editor groups, fit/shrink/fixed sizing and wrapping, tooltip/semantics, and that close/disk icons, click/close/drag routing, document ordering/identity/state, and saved layout data remain unchanged.
- The app packages the licensed icon data and a desktop-compatible font. Run focused editor-tab suites, full `bash init.sh`, `cargo fmt --check`, Flutter analyze, Harness validation, JSON validation, and `git diff --check`. On the final product head, require PR CI and Linux x64, Windows x64, and macOS Intel x64 build/test/launch/package checks. Report macOS native DnD as skipped if its synthetic pointer route remains unavailable.
