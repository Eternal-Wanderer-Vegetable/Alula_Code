# P03.7 shared-document views and editor semantics

Date: 2026-10-31. Status: P03.7 implementation and automated evidence are complete; native platform/device validation remains pending in the external ledger.

## Implementation

- `WorkbenchPage` now keeps document-owned state in one `_SharedOpenDocState` per Rust `DocumentId`: the `AlulaDoc`, undo history, file/savepoint options, dirty/conflict state, and LSP attachment. `OpenDoc.viewOf` retains that model and allocates a new bounded input window, focus key, scroll controller, selection history, fold state, and multi-selection state for each editor view.
- Opening an already-open path in another editor group adds a view of the existing Rust document. Session restore reuses one Rust document for repeated matching IDs. If repeated journal entries disagree, the conflicting text is preserved in an untitled recovery draft and a recovery notice is shown.
- Text input, workspace edits, undo/redo, programmatic replacements, disk reload/revert, and watcher reloads refresh sibling views. Each sibling selection is mapped through the committed UTF-16 operations; its scroll controller remains view-local.
- Closing one view releases only that view. The final view sends LSP `didClose`, releases the Rust document and undo stack, and clears document-level syntax state. Moving a tab between groups releases its old group-specific focus node.
- Editor text fields expose a label containing the file and editor group. Visible fold controls expose localized collapse/expand labels, state, line hints, and semantic tap actions.
- Bounded-window painting and viewport projection now select an attached scroll position safely during a window rebase, when old and new positions can overlap for one frame. Disk-reload scroll restoration clamps and restores each attached position independently.
