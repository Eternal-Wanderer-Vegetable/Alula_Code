# P05.176 / feat-228 · LAY-12 Linux xfwm4 辅助窗关闭

依赖 P05.174、P05.175。Linux WSL Xvfb + xfwm4 在常规 X11 模式关闭辅助窗后，进程以 1 退出。打开、紧凑切换、置顶、取消置顶和恢复在关闭前完成。测试使用 GTK 3.24.41、Flutter 3.47.8 Release 和软件 OpenGL。

## 复现与调整

- 对照组在 GTK 重绘时收到 GLX BadAccess，request 150、minor 26。进程内诊断栈从 gdk_window_begin_draw_frame 到 gdk_gl_context_make_current 与 GLX。X11 同步诊断和两次附加 XID 记录的试验通过，常规模式再次失败。取消 Dart 关闭时的重绘请求仍失败。[复现矩阵与原生栈](p05.176-reproduction-and-trace.json) · [GTK 的 GLX 上下文绑定](https://github.com/GNOME/gtk/blob/3.24.41/gdk/x11/gdkglcontext-x11.c#L1206)
- Linux 关闭路径在交还文档后先隐藏 GTK 辅助窗，随后解除原生关闭保护、释放对应文档并执行关闭。GTK 可在渲染上下文存活时取消映射。隐藏调用失败时继续调用原生关闭。组件测试核对两个平台的调用顺序。
- 最终原生复验使用常规 X11，关闭后在主窗输入 POST-CLOSE。核对单窗仍在线、原脏文本与新输入同时存在、Rust 全文等于 Flutter 镜像、emoji 保留，原测试文件的 UTF-8 BOM、CRLF 和 SHA-256 一致。
