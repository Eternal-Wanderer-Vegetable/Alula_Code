# P05.174 / feat-226 · LAY-12 主窗标签拖入既有辅助窗的原生交换

依赖 P05.69、P05.99。Windows 11 build 26200、125% DPI Release 与 Linux WSL Xvfb Release 运行实际主工作台和辅助引擎。两边都通过系统键鼠选择、编辑、拖放与关闭。夹具的 F6 调用现有新建辅助窗命令。文件包含 emoji，磁盘原始编码为 UTF-8 BOM 与 CRLF。

## 实现与回归

- Rust 文档表由进程内各引擎共享。旧实现的两个辅助窗都打开 ID 1，新窗的 Rust 文档覆盖了旧窗，但旧窗仍显示原文本。主窗现在为启动和交换准备阶段分配独立 ID。窗口关闭或初始化失败时释放已占用的共享核心文档。window/group 焦点协议继续只传焦点元数据。
- Windows 程序调整位置后，事件缓存可能落后于原生边界。主窗在拖放释放时向每个已知辅助窗读取原生边界，最多等待一秒。读取失效或窗口集合变化时保留源文档。窗口重叠时拒绝交换。收到提交确认后，主窗显示本次交换成功。
- Windows 辅助窗此前调用 window_manager 0.5.2 的 destroy，向主窗与辅助窗共用的消息循环投递 WM_QUIT。实机转储在 Flutter view 的 GetEngine 和顶层窗口过程路径解析到访问异常。改用目标窗口的原生关闭消息后，辅助窗关闭，主窗继续运行并接回文档。[三项修复前轨迹](p05.174-before-fixes.json) · [锁定的 window_manager 0.5.2 源码包](https://pub.dev/api/archives/window_manager-0.5.2.tar.gz) · [固定 Flutter 引擎的顶层窗口处理](https://github.com/flutter/flutter/blob/cf636b1dfb818dd6a3ff16e390e93b1a036969c8/engine/src/flutter/shell/platform/windows/flutter_windows.cc)
