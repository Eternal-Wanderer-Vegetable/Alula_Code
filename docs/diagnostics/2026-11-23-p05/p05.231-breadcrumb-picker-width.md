# P05.231 / feat-283 · 面包屑选择器横向展开

选择器宽度跟随窗口，通常从所选段左边展开，右边空间不足时向左移到视口范围内。按固定版取 240 逻辑像素与可用参考宽度除以 4.17 的较大值，并受 Flutter 弹层安全边距约束。[固定版 Code-OSS 锚点与宽度](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts#L676-L705)

旧行为在 2400 逻辑像素宽的控件回归中，所选段从 1519.76 开始，仍有足够右侧空间，菜单行却从 1441.76 开始。修复后，宽窗的菜单从段左边开始，720 逻辑像素窄窗保持 8 像素右边距。

## 验证

- Windows 实机 125% DPI 记录 12 个观测点，含三个动画首帧。Linux 私有 Xvfb + xfwm4 记录 9 个观测点。Windows 976.8、Linux 1200 逻辑像素宽时，位于右半区的所选段均可向右展开。窗口缩至 720 时，两平台的菜单行横向均为 472–712。鼠标和键盘入口都保留段下方间距。三次 Esc 各自恢复所属编辑器焦点，磁盘哈希一致，进程退出码均为 0。
- Windows 首次读取在键盘入口观测到菜单行左边为 102.95。补充夹具记录到该帧动画值为 0，动画完成后为 342.95，与段左边一致。两次构建使用同一产品 tree，夹具和 AOT 分别记录校验和。[原生坐标、动画状态和校验和](p05.231-breadcrumb-picker-width/native.json)
- 窄回归 29/29，专项 313/313。完整 bash init.sh、Rust 格式、核心构建、工作区测试、Clippy 和 Flutter analyze 通过，Flutter 全量 1,826 passed / 2 skipped。菜单和位置入口的编辑前图谱风险均为 LOW，直接调用数分别为 2 和 1。全量与暂存图谱检查均为 LOW，4 个文件和 6 个符号。测试入口由 Flutter 测试运行器调用。
- Linux mem-probe 就绪、右组菜单和左组菜单采样各为 1 个进程，私有内存分别为 234.6、250.3、255.4 MiB。P05.230 同类就绪采样为 231.8 MiB。

P05.230 的 Windows 键盘记录未采集动画状态。其菜单行右边与段左边重合的几何关系在本轮动画首帧复现。横向展开差异由本轮宽窗回归和 P05.230 的右组鼠标观测确认。[P05.230 观测](p05.230-breadcrumb-picker-anchor.md)
