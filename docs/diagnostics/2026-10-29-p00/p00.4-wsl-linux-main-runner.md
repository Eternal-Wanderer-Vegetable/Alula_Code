# P00.4 WSL 主应用 Linux runner follow-up（2026-10-29）

## 范围与变更

为在 WSL 上验证主应用而非仅验证独立 Web Engine Probe，基于 Flutter 3.47.8 生成并纳入源码控制 `app/linux/` runner。根 `.gitignore` 不再忽略该 runner。Linux bundle 的 CMake 安装步骤会把 `app/native/libalula_core.so` 放在可执行文件旁，供 Dart FFI 按平台加载。

修复 `scripts/build_core.sh` 的跨平台产物选择：脚本现在读取 `rustc -vV` 的 host triple，再选择 DLL、dylib 或 SO。此前 Windows 与 WSL 共用 `/mnt/e` 工作树，`target/release` 同时有 Windows DLL 和 Linux SO，旧脚本固定优先复制 DLL，导致 WSL build 找不到 `.so`。

## 验证

- WSL 执行 `bash scripts/build_core.sh` 后，`app/native/libalula_core.so` 与 `target/release/libalula_core.so` 字节一致；Windows Git Bash 执行同一脚本后 DLL 与 Windows target 一致，Linux SO 保留且仍与 Linux target 一致。
- `flutter pub get --offline --enforce-lockfile` 成功生成 Linux 插件构建清单；锁定依赖未更新。
- `app/` 的 `flutter build linux --release --no-pub` 成功，产物为 `app/build/linux/x64/release/bundle/alula_app`，bundle 同目录含 `libalula_core.so`。
- Linux `flutter test --no-pub test/core_sync_test.dart` 执行 FFI 对拍 6 项，全部通过；ABI 握手、增量同步、resync、中文与 emoji 均实际加载 Linux `.so`。
- `cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`app/` 下 `flutter analyze --no-pub` 与根目录 `bash init.sh --fast` 均通过；Flutter 全套 122 项通过，包含上述 6 项 FFI 用例。

## 限制

此项证明主应用 Linux runner 可生成 Release bundle 并加载 Rust 核心，不是 DRM/WPE GBM/DMABUF 或 Linux 输入/视觉等价证据。隔离窗口 smoke 未完成：WSL 缺少 Xvfb，Ubuntu updates 索引对应包返回 404；security 源版本下载超时，未安装成功。此环境为 WSLg，硬件 DRM 验收仍需真实 DRM Linux 主机；docs/04 的产品进程树内存矩阵、cgroup 限额下交互与三轮重复也尚未执行。P00.4 保持 blocked，P01 不启动。
