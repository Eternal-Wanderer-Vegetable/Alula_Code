# P00.4 rust-analyzer per-query LRU configuration audit

Date: 2026-10-29

## Question

Could `rust-analyzer.lru.query.capacities` provide a useful memory experiment after the global `lru.capacity` screen failed to show a durable gain?

## Pinned binary

- Installed extension: `rust-lang.rust-analyzer` 0.3.3089, release tag `2026-10-19`.
- Server output: `rust-analyzer 0.3.3089-standalone (5ec20d044d 2026-10-18)`.
- Local server SHA-256: `6f76533ca854bc2708bfa1caab68240ed5b89e530eafc1ac9865f5a569f5ec1d`.
- The extension's generated settings schema advertises `rust-analyzer.lru.query.capacities` as an object with default `{}`.

## Fixed-revision implementation check

At the exact server revision, `crates/ide-db/src/lib.rs` defines `update_lru_capacities`, but its map parameter is unused and the function body contains only commented-out per-query settings. The source labels this `FIXME(salsa-transition): bring this back; allow changing LRU settings at runtime.` See [the pinned source, lines 231–255](https://github.com/rust-lang/rust-analyzer/blob/5ec20d044d/crates/ide-db/src/lib.rs#L231-L255).

Therefore, the schema key is present but the pinned server does not apply its values to query caches. A memory run using this setting would be a no-op and would not provide valid optimization evidence. No experiment was started, no product configuration was changed, and no capability was disabled.

The global `rust-analyzer.lru.capacity` experiment remains the applicable supported control for this binary; its existing 30-minute capacity-16 run ended at 659.96 MiB stable Private Bytes, 2.03 MiB above the default run3 result and 159.96 MiB above the 500 MiB target. It did not show a durable memory improvement.

## Result

This closes the per-query LRU configuration question for the pinned server without spending another foreground test cycle. P00.4 remains blocked; this audit does not satisfy the Rust+RA memory target or any docs/04 product matrix gate. Evidence is local version/package inspection plus the exact upstream source revision; no runtime behavior is claimed beyond the source implementation.
