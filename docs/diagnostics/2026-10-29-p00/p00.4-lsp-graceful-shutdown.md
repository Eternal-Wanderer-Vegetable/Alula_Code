# P00.4 LSP workspace graceful shutdown follow-up (2026-10-29)

## Change

- Added ABI v5 `alula_lsp_shutdown_workspace(root)` and the Dart `shutdownWorkspace` wrapper.
- Closing a tab sends `textDocument/didClose` while retaining the shared workspace server. Closing the workbench sends `didClose` for attached documents, waits for the LSP `shutdown` response, sends `exit`, and waits up to one second for process exit before force-reaping as a bounded fallback.
- Workbench disposal calls the workspace shutdown path and closes remaining Rust document buffers. Timed-out LSP requests now remove their pending response entry.
- Windows `WM_CLOSE` was bypassing Flutter widget disposal because `window_manager` defaults to allowing close. The app now enables `setPreventClose(true)`, handles `onWindowClose`, runs the workspace shutdown path, and destroys the window after the callback; widget disposal remains a fallback.
- The current worktree also had an unrelated, pre-existing Ctrl+Click definition listener. During validation, its synchronous pointer-down rebuild prevented the P00.3 keyboard undo fixture from receiving Ctrl+Z; deferring that callback restored the fixture. This separate workbench hunk remains with the user's other unstaged workbench changes and is excluded from the LSP commit.
