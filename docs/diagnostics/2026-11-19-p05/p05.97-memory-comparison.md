# P05.97 Linux release memory comparison

## Method

- Built both release bundles with Flutter 3.47.8 / Dart 3.13.7 and the same Rust core (`libalula_core.so` SHA-256 `9ee0c35c82c420a668ba30b7995f55442a63dba65f51c90a60d966ccc39edb99`). The baseline is PR head `14b26c991c075b038af42561bf6a1d6e847d1f40`; candidate runs use the final P05.97 working tree.
- Each run used a separate clean `HOME` with the same valid Alula session shape: one editor group, three untitled documents, no workspace, and identical layout. The baseline and candidate editor-order run used `editorOrder`; the candidate alphabetical run used `alphabetical`, causing the native ICU4X collator to compare the three names.
- `tools/mem-probe watch` sampled one app process for 45 seconds at 1-second intervals. “Private” is Linux `Private_Clean + Private_Dirty`; final PSS and working set are reported separately from the last process sample. Stable values are the median of the final 40% of samples.

## Results

| Release | Stable Private | Final PSS | Final working set | Evidence |
|---|---:|---:|---:|---|
| PR head, editor order | 214.92 MiB | 233.19 MiB | 292.62 MiB | `p05.97-memory-base-3docs-linux.json` |
| Candidate, editor order | 212.11 MiB | 230.31 MiB | 289.41 MiB | `p05.97-memory-editor-order-3docs-linux.json` |
| Candidate, alphabetical | 212.16 MiB | 230.43 MiB | 289.84 MiB | `p05.97-memory-alphabetical-3docs-linux.json` |

Activating alphabetical mode added about 0.05 MiB Private / 0.12 MiB PSS relative to the same candidate with editor order. The candidate bundle adds a 1,711,488-byte `libicu4x.so`; total bundle size was 35.89 MiB versus 34.21 MiB for the baseline. The baseline and candidate editor-order run did not invoke the collator.

These are short Linux desktop measurements with three untitled documents, not the full memory matrix in `docs/04`. Windows/macOS runtime memory has not been measured. An earlier unpaired comparison was discarded because its launch state was not controlled; it is not part of the evidence.
