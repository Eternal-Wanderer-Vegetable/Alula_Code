# P05.97 / feat-149: Open Editors alphabetical sort

## Scope

Implement the missing `alphabetical` Open Editors sort policy. Sort editor names separately inside each visible editor group. In `fullPath` mode, sort resource-less editors by name while leaving resource buckets and group layout order intact. Persist the selected policy through the existing session field. Do not reorder editor tabs, change MRU/active/preview/sticky state, or change document/view identities.

## Fixed reference

Code-OSS 1.145.0 at `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`:

- `src/vs/workbench/contrib/files/browser/views/openEditorsView.ts`: alphabetical order calls `compareFileNamesDefault(first.editor.getName(), second.editor.getName())` within each editor group. In full-path mode, two editors without a resource are compared by the same name comparator; resource-backed editors keep the existing path policy.
- `src/vs/base/common/comparers.ts`: the default name comparator uses the system-locale `Intl.Collator` with `numeric: true`; when two distinct names compare equal, the shorter UTF-16 string sorts first.

Sources: [pinned Open Editors implementation](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/files/browser/views/openEditorsView.ts), [pinned filename comparator](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/base/common/comparers.ts).

## Implementation and remaining comparison limits

- Uses the Dart team's `intl4x` ICU4X collation API with system locale and numeric collation, initialized as one bounded process-wide comparator on first name comparison. The package is marked preview; this remains a maintenance/compatibility limitation.
- `intl4x` intentionally falls back to Dart code-unit comparison inside the Dart test runner. Default tests inject a deterministic comparator for policy/stability checks. CI also runs an explicit `--dart-define=intl4x.brittle_i18n_testing=true` smoke so the native ICU4X implementation is exercised on Linux and Windows.
- Native runtime vectors cover natural numbers, leading zeroes, case, accents, canonical forms, punctuation and the shorter-UTF-16 tie rule. They matched the host Code-OSS/Node `Intl.Collator` golden order locally. This is representative coverage, not exhaustive ICU/CLDR data-version parity.
- No Rust, FFI/ABI, document text, selection, auxiliary-window, or LAY-12b focus-channel changes are in scope.
