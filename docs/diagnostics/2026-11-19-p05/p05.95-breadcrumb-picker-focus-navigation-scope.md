# P05.95 / feat-147 — Breadcrumb picker focus navigation scope

## Scope

Implement Code-OSS `breadcrumbs.focusNextWithPicker` and `breadcrumbs.focusPreviousWithPicker` behavior while a Breadcrumb directory or symbol picker is open and its list owns keyboard focus. Use Ctrl+Right/Left on Windows/Linux and Alt+Right/Left on macOS. The picker remains open as the focused Breadcrumb segment moves; movement uses the existing clamped segment navigation, so it does not wrap at either end.

Outside the picker route, existing `breadcrumbs.focusNext` and `breadcrumbs.focusPrevious` behavior remains unchanged. Arrow navigation, Enter selection, Escape restoration, and ordinary picker selection continue to belong to the picker while its route is open. Use a Breadcrumb-specific picker context; the existing `listFocus` key represents Explorer tree focus and must not be reused for the popup menu.

No Rust, FFI, document text, auxiliary-window focus-sync, picker contents, or menu selection behavior changes are in scope.

## Acceptance

- Register both pinned command IDs and keep them enabled only while a Breadcrumb picker route is active, its list owns keyboard focus, and Breadcrumb navigation is active.
- Resolve Ctrl+Right/Left to the WithPicker commands on Windows/Linux and Alt+Right/Left on macOS while the picker is active; preserve the existing focusNext/focusPrevious command outside the picker.
- Invoking either command moves the focused segment within the existing non-wrapping bounds and leaves the picker route open.
- Normal arrow-based picker navigation and Enter/Escape behavior remain unchanged; the picker context clears after selection, Escape, outside dismissal, and resource invalidation.
- Add focused keybinding and real Workbench tests, then pass the repository local DoD, exact-SHA PR CI, and available Linux/Windows Platform Availability checks. macOS device interaction remains deferred under the existing no-device policy.

## Implementation and local verification

`KeybindingSet` now exposes the two pinned command IDs with mutually exclusive contexts: ordinary focus navigation is disabled while the picker route is open, and WithPicker navigation additionally requires `breadcrumbsPickerFocused`. Windows/Linux use Ctrl+Right/Left; macOS uses Alt+Right/Left. The dedicated picker context is separate from Explorer's `listFocus`.

`WorkbenchPage` publishes separate route-open and picker-list-focus context values. A temporary `FocusManager` listener compares the primary focus context's `ModalRoute` by identity with the picker route; a covering dialog therefore disables the WithPicker commands. The initial route/focus check is coalesced to one post-frame callback, avoiding command-context updates during menu-item build. The listener and both context values are cleared in picker `finally` cleanup, and the listener is also removed if the workbench is disposed. The popup Focus handler resolves the current `KeybindingSet` with live command context and dispatches only the two WithPicker commands; bare arrows still go to the menu. Modifier-only key events are ignored before chord conversion. Both actions reuse the existing clamped breadcrumb segment movement.

Focused tests cover platform bindings and context precedence, a real folder picker route with next/previous segment movement while staying open, command enablement outside/inside the picker, focus loss under a dialog, and cleanup on Escape, selection, outside dismissal, and resource invalidation. Existing picker side-open, reveal, overflow, and keybinding collision regressions remain green.
