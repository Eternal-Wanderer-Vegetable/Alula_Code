# P00.4 实验 3：官方服务端点与客户端注册前提

状态：端点与产品配置审查完成；官方 Marketplace/微软扩展授权形成明确外部阻塞。
没有登录账户、创建 OAuth 应用、创建隧道或向服务写入数据。

## 结论

- 固定源码 `microsoft/vscode@4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`
  的 `product.json` 是 Code-OSS 配置：没有 `auth`、`configurationSync.store`、
  `extensionsGallery` 或 `tunnelApplicationConfig`。现有运行证据标识为
  Code - OSS Dev，不能将它当作微软正式发行版的服务身份。
- 本机另有 Microsoft VS Code 1.142.0 Stable。其安装版 `product.json` 包含
  `auth.clientId`/登录与回调 URL、Sync stable/Insiders 服务 URL、Marketplace
  gallery/CDN 配置、tunnel application 配置和 `accessSKUs`/`accessScopes`。
  值未复制进证据，也未输出 client ID。该安装版与固定 1.145.0 开发源码版本不同，
  只能说明正式发行物会注入产品身份和端点，不是同版本运行对照。
- 官方网络文档将 `vscode-sync.trafficmanager.net` 与
  `vscode-sync-insiders.trafficmanager.net` 列为 Settings Sync 服务；正式产品配置还
  指向 `vscode.dev` 登录回调和 Microsoft identity endpoints。官方文档明确 Settings
  Sync 使用专用服务且不支持自定义后端，因此自建同步只能登记为替代，不能称官方互通。
- Remote Tunnels 通过 Microsoft dev tunnels；官方文档要求 host/client 使用同一
  Microsoft 或 GitHub 账号，并在首次启动时接受 VS Code Server license terms。创建隧道
  是远端状态变更，本实验没有创建或登记隧道。
- 微软 VS Code FAQ 明确 Visual Studio Marketplace 只供 Visual Studio 产品家族使用；
  基于 Code-OSS 的替代产品/分支不获准访问 Marketplace。微软扩展也不授权在该产品家族
  之外使用。这是当前复刻计划的硬阻塞，Open VSX 或自建 gallery 可以作为替代路线单独
  验收，但不能标为 Marketplace 官方 1:1。
- 通用 OAuth 应用注册不等于取得 VS Code first-party client 身份、Sync 服务权限或
  Marketplace 使用许可。Microsoft Entra 注册需应用 client ID、受支持账户类型及正确
  redirect URI；GitHub native public client 不能安全保管 client secret（除非使用
  device flow）。本实验不代用户注册应用，也不假定自有 client 可使用微软服务。

## 配置差异与端点台账

来源 SHA-256 与字段审查见 `p00.4-services-evidence.json`。只记录非凭据端点及配置字段名：

| 能力 | 正式产品配置/官方文档 | P00 Code-OSS 固定源码 | 结果 |
|---|---|---|---|
| Microsoft/GitHub 登录 | `login.microsoftonline.com`、`vscode-redirect.azurewebsites.net`；配置 client ID、登录/令牌/回调字段 | 无 `auth` 配置 | 没有正式发行版 client 身份；需自有 OAuth 注册，不能继承微软身份 |
| Settings Sync | `vscode-sync.trafficmanager.net`、`vscode-sync-insiders.trafficmanager.net`；专用 Sync store 与 provider 配置 | 无 `configurationSync.store` | 需用户登录和服务端认可；官方文档不支持自定义后端 |
| Marketplace | `marketplace.visualstudio.com/_apis/public/gallery`、`*.vscode-unpkg.net`、`main.vscode-cdn.net` | 无 `extensionsGallery` | 官方政策明确禁止 Code-OSS fork 客户端访问 |
| Remote Tunnels | Microsoft dev tunnels；`global.rel.tunnels.api.visualstudio.com`、`vscode.dev` | 仅 OSS tunnel 命名，无 `tunnelApplicationConfig` | 需同一账号、正式应用配置与 server license；未创建真实隧道 |

一次无凭据 `HEAD https://vscode-sync.trafficmanager.net/` 在本环境 TLS 校验通过，
但流量解析至 `198.18.0.52` 并返回 404。该地址属于执行环境网络路径，故只记作网络层
观察，不能视为 Sync API 响应、账户验证或服务访问授权。没有请求 Marketplace API，
因为官方政策已明确禁止 Alula/Code-OSS fork 客户端访问；也没有对 Tunnel API 做写入请求。

## 继续路线与阻塞

- P13 前需由 Microsoft 许可/发行渠道明确 Alula 是否可属于 Marketplace 允许的产品家族，
  或接受“Marketplace 以外的替代 gallery”作为不等价能力；当前官方文档给出的答案是
  fork 不允许访问，不能绕过此限制。
- 如要验证 Sync、Microsoft 登录或 Remote Tunnels 的真实端到端互通，需要各自受支持的
  client registration/redirect URI、正式发行配置和测试账号；本环境没有这些凭据。
- GitHub 登录可以独立使用自有 OAuth 应用进行后续实验，但它不能解除 Marketplace 许可
  或证明 Microsoft Sync/Entra identity 互通。
- 这些阻塞不影响不依赖外部账号的 P01–P12 工作；如要严格遵循当前 docs/03 的依赖，
  P00 仍保持未完成，P00.4 不得标为无阻塞 done。

## 2026-10-28 官方服务政策复核

从官方 VS Code 文档重新核对：Marketplace 仍限 Visual Studio 产品家族，基于 Code-OSS 的 fork 不获准访问；Settings Sync 使用专用服务且不支持自定义后端。没有调用 Marketplace、登录账户或写入任何服务。现有 blocker 与官方当前说明一致，仍需要明确的微软产品身份/服务授权路径；替代 gallery/sync 仍属于不等价能力。
