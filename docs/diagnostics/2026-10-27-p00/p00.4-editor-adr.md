# P00.4 实验 1：编辑器 IME / 增量输入 / 多光标 / 视口

状态：实验完成。CodeForge 11.3.0 保留为 P03 候选；本 ADR 不批准直接替换产品编辑器，也不代表 P03 验收。

## 范围与环境

在独立 Flutter Windows 探针中运行 pub.dev 的 code_forge 11.3.0，没有修改
app/ 产品工作台或 Rust 文档模型。环境为 Windows 11 build 26200 x64、
Flutter 3.47.8 / Dart 3.13.7、1280×720 窗口。Windows 输入法列表提供
zh-Hans-CN Microsoft Pinyin
(0804:{81D4E9C9-1D3B-41BC-9E6C-4B40BF79E35E}{FA550B04-5AD7-411F-A5AC-CA038EC515D7})。

## 观察结果

- 真机 Pinyin：nihao 在提交前显示 composition 状态和 Windows 候选列表；按空格选中首候选后，文档出现“你好”。第二个 composition zhongguo 用 Esc 取消后没有写入正文。切到拼音输入法的 Latin 模式后，键入 xyz 可见逐字更新。
- Flutter text-input composition characterization：组合态显示 ni，权威文档文本仍是 seed；提交“你好”后只形成一个 undo stop，撤销恢复为 seed。
- Delta 多光标 characterization：把一个 X insertion delta 送入实际启用的 DeltaTextInputClient 路径，主光标和三个次光标得到 aX|bX|cX|dX；一次 undo 恢复原文。Flutter 的 TestTextInput.updateEditingValue 走旧式整值更新，不适合验证多光标 delta 路径，因此测试直接调用 DeltaTextInputClient 的 insertion callback。
- 10,000 行探针文档共 258,889 Dart UTF-16 code units。widget 测试建立 3 个次光标并把视口滚到 83,700 / 167,400 px；探针运行页也能在 10,000 行文档中接收实际键入。
- 真机输入窗口采样累计帧的最大 FrameTiming.totalSpan 为 52.0 ms，4,681 帧中 2 帧超过 16 ms；混合拼音输入期间观测到的最大 key-down→controller notification 间隔为 428.8 ms。它们是 Debug 探针的整段累计值，不是独立输入延迟基准或 Release 性能结论。

自动检查：探针 flutter analyze 无问题；flutter test 4 项通过。可重放命令见 tools/editor-ime-probe/README.md；命令退出码与测试观察值见
p00.4-editor-evidence.json。

## 决策

继续把 CodeForge 作为 P03 的候选绘制/输入组件进行跨平台与架构适配验证。P03 仍由 Rust DocumentModel 负责权威全文、UTF-16 偏移、保存和恢复；Flutter 侧必须通过有界可见区/输入窗口适配层接入，不能把 CodeForge 自己的全文 rope 当成第二个权威文档。多视图同步、Rust 往返一致性、增量同步背压和大文件内存都未在本实验验证。

实验支持 CodeForge 的 Windows IME composition、Delta 插入、多光标编辑及 10k 行视口继续进入候选，但不足以定最终编辑器架构。P03 开工前仍要在 Windows/macOS/Linux 验证 IME 与无障碍，补齐 Emoji/ZWJ/组合字符/CRLF/BOM、列选、长行、真实万行键入和多视图对拍，并用 mem-probe 测内存。
