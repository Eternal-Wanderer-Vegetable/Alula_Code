# P00.4 Linux Flutter/WPE 2.52.6 source-build evidence

Recorded: 2026-10-28. This supplements the Debian WPE 2.54.2 and Trixie 2.48.3
build failures in `p00.4-linux-wpe-evidence.json`. It is a local source build
and Xvfb experiment, not a GitHub Actions run or a production packaging result.

## WPE source build

- Official release: [WPE WebKit 2.52.6](https://wpewebkit.org/release/wpewebkit-2.52.6.html)
- Archive: `wpewebkit-2.52.6.tar.xz`
- SHA-256: `b2bafef2751625b7fdf530f230ff0f542ff0eeba3590c3a989d931b2a55c858e`
- Container: Debian GNU/Linux 12 Bookworm, based on the locally cached
  `python:3.12.14-slim-bookworm` image; this is not the Debian sid CI image.
- Build tools: GCC 12.2.0, CMake 3.25.1, Ninja 1.11.1.
- Install prefix: `/work/install` in the temporary container.

The source tar omitted `Tools/glib/dependencies/apt`; the matching helper was
downloaded from the `wpewebkit-2.52.6` upstream tag. The source dependency helper
installed the build prerequisites in the disposable container. Configuration:

```bash
cmake -S /work/source -B /work/build -GNinja \
  -DPORT=WPE -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=/work/install \
  -DENABLE_WPE_PLATFORM=ON \
  -DENABLE_WPE_PLATFORM_HEADLESS=ON \
  -DENABLE_WPE_LEGACY_API=OFF \
  -DENABLE_DOCUMENTATION=OFF \
  -DENABLE_MINIBROWSER=OFF \
  -DUSE_LIBBACKTRACE=OFF \
  -DBWRAP_EXECUTABLE=/usr/bin/bwrap \
  -DDBUS_PROXY_EXECUTABLE=/usr/bin/xdg-dbus-proxy
ninja -C /work/build -j8
ninja -C /work/build install
```

`ENABLE_MHTML=ON`, `ENABLE_WPE_PLATFORM=ON`, and
`ENABLE_WPE_PLATFORM_HEADLESS=ON` were confirmed in `CMakeCache.txt`. The
Release build completed 9,421 Ninja steps and install exited 0. GCC 12 emitted
22 warnings from WebCore/CSSValue and libstdc++ (`15 -Wrestrict`,
`7 -Wuse-after-free`); there were no build errors. Full configure output and
compressed build/install logs are in `p00.4-linux-wpe-2.52.6-run/`.

## Flutter probe build

Environment: Flutter 3.47.8 (framework `737ba8f885`), Dart 3.13.7, Clang 14.0.6,
GTK 3.24.38, libwpe 1.14.0, epoxy 1.5.10, and libsecret 0.20.5. The three WPE
pkg-config modules all reported 2.52.6. `flutter pub get`, `flutter analyze`,
`flutter test` (one test), and `flutter build linux --release` all exited 0.

The install prefix required `PKG_CONFIG_PATH=/work/install/lib/pkgconfig`,
`LD_LIBRARY_PATH=/work/install/lib:/work/install/lib/x86_64-linux-gnu`, and
`LDFLAGS=-L/work/install/lib`. This Clang 14 image rejected the plugin's
`-Wno-deprecated-literal-operator` as an unknown warning under `-Werror`, so
`CXXFLAGS=-Wno-unknown-warning-option` was used only for this temporary build.
This suppresses that toolchain-option diagnostic; it does not change plugin or
application source. Flutter package resolution used `pub.flutter-io.cn` because
`pub.dev` returned HTTP 403 from this container. Cargo used the Tsinghua sparse
registry mirror.

Rust `mem-probe` was built on Linux with Rust/Cargo 1.90.0:

```bash
cargo +1.90.0 build --locked --release -p mem-probe
```

No Rust source or lockfile was changed.

## Xvfb replay

Replay command:

```bash
tools/web-engine-probe/scripts/run-web-smoke-linux.sh \
  tools/web-engine-probe/build/linux/x64/release/bundle/web_engine_probe \
  docs/diagnostics/2026-10-27-p00/p00.4-linux-wpe-2.52.6-run
```

The script uses Xvfb and software GL. The first container's default seccomp
profile blocked `bwrap` from creating a user namespace. With the WebKit sandbox
disabled, page DOM checks passed but the plugin screenshot was empty when WebKit
used the GBM/DMA-BUF path without a CPU pixel buffer. The successful baseline
run set both:

```text
WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1
WEBKIT_DMABUF_RENDERER_DISABLE_GBM=1
```

The WPE child then used the software buffer path. That baseline run's
initial-page and MHTML reload screenshots show `WEB_ENGINE_PROBE_OK`; the MHTML
is 2,587 bytes and contains `MIME-Version: 1.0` and the page marker.
`mhtml.sha256`, JSON, PNG, `probe.log`, and `mem-probe` snapshots are preserved
in the baseline run directory. The page JSON records CDP and Inspector support
as `false`.

### Default-sandbox follow-up

A follow-up container used `--cap-add SYS_ADMIN --security-opt
seccomp=unconfined` instead of `--privileged`. The probe itself ran as the
unprivileged UID 1000 account; `unshare --user --map-root-user true` exited 0.
`WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS` was unset, GBM stayed disabled, and
the process-tree snapshots contained two `bwrap` children plus
`WPEWebProcess`. The smoke run exited 0 through initial load, MHTML reload,
destroy and the 30-second sample. This verifies that the WebKit sandbox launcher
can run in this local container when Docker permits user namespaces; it does
not validate the default Docker seccomp profile, a GitHub hosted runner, or
production host security settings.

The original default-sandbox capture had the DOM marker but its 1280×572 RGBA
PNG was fully transparent: all 732,160 pixels were `(0, 0, 0, 0)`. The pinned
Linux plugin's `takeScreenshot()` copies its current pixel buffer and does not
wait for a WPE frame callback. The DOM marker therefore did not prove that a
painted frame had reached the buffer when the screenshot was requested.

The isolated probe now checks the screenshot before its JavaScript DOM queries
and retries up to 30 times at 100 ms intervals until it finds a pixel matching
the page heading's blue color. Flutter analyze, test and Linux Release build
passed. Three fresh default-sandbox replays then completed initial load, MHTML
save/reload, view destruction and the 30-second sample. Two preliminary
alpha-check captures rendered the full page on attempt 1 (94 ms and 97 ms).
The final probe version captures before DOM queries and requires the heading's
blue pixel; it retried once and captured the page on attempt 2 (199 ms). All
three final initial PNGs were 1280×572 with 470 distinct colors, including the
page background and heading; each MHTML capture also passed. The old unpolled
transparent capture is retained as
evidence of the race. The bounded probe wait makes the screenshot evidence
reliable for these runs; it is not a product-code fix or a guarantee for other
hosts. Full logs, screenshots, MHTML and memory samples are in
`p00.4-linux-wpe-2.52.6-default-sandbox-run/` and the three
`p00.4-linux-wpe-2.52.6-frame-poll-run*` directories.

One short memory round (Linux process-tree Private / Working Set / PSS):

| Phase | Processes | Private MiB | Working Set MiB | PSS MiB |
|---|---:|---:|---:|---:|
| Before WebView | 2 | 176.9 | 290.7 | 230.9 |
| WebView open | 3 | 282.5 | 553.9 | 384.8 |
| MHTML reloaded | 3 | 289.5 | 564.4 | 392.5 |
| WebView destroyed | 2 | 219.8 | 342.3 | 278.2 |
| Destroyed 30 seconds | 2 | 219.3 | 341.8 | 277.7 |

At the 30-second sample `WPEWebProcess` had exited, while `WPENetworkProcess`
remained. Private memory was 42.4 MiB above this probe's pre-WebView sample.
Each software-rendered round is a single exploratory sample and does not satisfy
docs/04's three-run and 1/10/30-minute product memory protocol. The follow-up
exercised WebKit sandboxing only with Docker `SYS_ADMIN` and seccomp unconfined;
the GBM hardware path remains unverified. macOS, Linux CDP, Linux Inspector,
Microsoft service authorization, and full-product behavior remain open; P00.4
and P00 stay blocked, so P01 remains not-started.
