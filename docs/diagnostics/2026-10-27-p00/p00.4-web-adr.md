# P00.4 实验 2：Web 引擎、DevTools/CDP、MHTML 与按需内存

状态：Windows 子实验通过；macOS 与 Linux 子实验未验证。此 ADR 不批准
P12 产品架构，也不能作为三平台验收。

## 目标与范围

用独立 Flutter Windows Release 探针验证一个平台 WebView 是否能按需创建、运行
DevTools/CDP 命令、导出并重新打开 MHTML，且销毁后回收 WebView 子进程。探针未加入
Alula app/ 或改变 Rust 核心。

## 结论

- Windows 11 上的 WebView2 与 `flutter_inappwebview 6.1.5` 可用：探针实际调用
  `Page.captureSnapshot(format=mhtml)`，落盘后在同一个 WebView2 中打开归档并还原页面；
  `Page.captureScreenshot` 导出的初始页与 MHTML 重载 PNG 都能看到
  `WEB_ENGINE_PROBE_OK` 标记。
- 单次 Windows Release 采样中，无 WebView 时进程树为 1 个进程 / 198.1 MiB；WebView
  已加载时为 7 个进程 / 369.3 MiB；MHTML 重载阶段为 7 个进程 / 404.1 MiB。销毁
  WebView 后采样回到 1 个进程 / 211.0 MiB；30 秒后为 1 个进程 / 203.9 MiB。WebView
  生命周期阶段比空探针高约 171–206 MiB，不能外推为完整编辑器成本。
- 不把一个 WebKit API 当作 WebView2/CDP 的等价实现：Apple `WKWebView` 提供
  `createWebArchiveData`（Web Archive）和 Safari Web Inspector；本实验没有证据证明
  它能提供同一 CDP/MHTML 合同。Linux 的 WebKitGTK/WPE 有自己的 Web Inspector 协议；
  所选 stable `flutter_inappwebview 6.1.5` 平台清单不含 Linux，WPE Linux 实现是单独包。
- 因此当前证据只证明 Windows 可行。P12 开工前仍需决定是否维护平台适配层，或评估
  在三平台分发统一 Chromium 内核的打包、许可、安全更新和内存代价；在该决定和真机
  对拍前，跨平台浏览器/DevTools 能力保持 open。

## Windows 可重放证据

环境：Windows 11 10.0.26200 x64、Flutter 3.47.8 / Dart 3.13.7、Visual Studio
Community 2026、Evergreen WebView2 Runtime 155.0.4283.62。Release 构建在当前机器使用
NuGet CLI 与 WebView2 NuGet 依赖，并通过临时编译宏
`_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS` 绕过上游插件在新 MSVC 下的
`<experimental/coroutine>` 弃用错误；这属于探针构建条件，不是产品解决方案。

从 Windows Git Bash 重放：

```bash
cd /e/alula_code/tools/web-engine-probe
PUB_HOSTED_URL=https://pub.flutter-io.cn /e/_alula_tools/flutter-win-wrapper.sh analyze
PUB_HOSTED_URL=https://pub.flutter-io.cn /e/_alula_tools/flutter-win-wrapper.sh test
PATH=/e/alula_code/tools/web-engine-probe:$PATH \
  PUB_HOSTED_URL=https://pub.flutter-io.cn \
  CL=/D_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS \
  /e/_alula_tools/flutter-win-wrapper.sh build windows --release
```

单次自动化周期通过 `scripts/run-web-smoke.ps1` 运行，先后采样无 WebView、WebView
挂载、MHTML 重载、销毁、销毁 30 秒后。测试和原始数据：

- `p00.4-web-before.json`：1 进程，198.1 MiB。
- `p00.4-web-open.json`：7 进程，369.3 MiB。
- `p00.4-web-mhtml-open.json`：7 进程，404.1 MiB。
- `p00.4-web-destroyed.json`：1 进程，211.0 MiB。
- `p00.4-web-destroyed-30s.json`：1 进程，203.9 MiB。
- `p00.4-web-open.png`、`p00.4-web-mhtml-opened.png`：通过 WebView2 CDP 页面截图接口
  导出的初始页与归档重载页。
- `p00.4-web-exported.mhtml`：1,438 bytes；含 MIME-Version 与页面标记；SHA-256
  `75ba8fede21f7f8853ecb72e8f4db4962aacee04cadb0f90a0118c61dfb99c3b`。
- `tools/web-engine-probe/`：最小程序、阶段标记驱动的 Windows smoke 脚本、锁定的
  Flutter 插件版本。

探针 `flutter analyze` 零问题，`flutter test` 1 项通过，Windows Release 构建成功。
`mem-probe` 以进程树 Private Bytes 统计；数据为一次短时 exploratory 采样，未按
docs/04 的三轮及 1/10/30 分钟采样协议进行，也不是 Alula 完整工作台的内存结果。

## 未验证 / 风险

- 无 macOS 设备；没有运行 WKWebView、归档重载、Safari Web Inspector 或进程内存测试。
- WSL 环境没有 Linux GUI、Flutter Linux runner、WebKitGTK/WPE SDK 或 Linux 插件；没有
  运行 WPE WebView、Inspector 协议、MHTML 读写或进程回收测试。未用 Windows 结果代替。
- 仅验证小型离线 HTML + data URI，不含跨源认证、cookie、媒体、下载、恶意网页隔离、
  DevTools 会话生命周期、CDP 事件订阅、剪贴板与编辑器集成。
- 单轮生命周期采样不覆盖重复导航、并发多个视图、1/10/30 分钟空闲、关闭工作区或
  完整应用基线差值；不能据此批准常驻内存预算。
- 上游 `flutter_inappwebview` stable 6.1.5 在本机 VS 2026 下构建需要额外条件；
  应先解决跨平台插件维护/编译和统一调试合同，再考虑产品依赖。
