# P00.4 实验 2：Web 引擎、DevTools/CDP、MHTML 与按需内存

状态：Windows Flutter/WebView2 子实验通过，并已用当前 `6.2.0-beta.3` 探针复跑兼容性；
Linux WebKitGTK 原生 GTK 引擎检查通过；Flutter Linux/WPE 已在官方 WPE 2.52.6 源码构建上
通过 Release 构建与 Xvfb MHTML/截图/销毁回放，但依赖隔离容器中关闭 WebKit sandbox、禁用
GBM 的软件渲染条件。Debian sid WPE 2.54.2 仍因设置 API 不匹配而不能编译，Trixie WPE
2.48.3 的 FDO 回退也因缺少 WebKit API 而失败。所选插件的 Linux CDP API 不支持；
Linux WPE 2.52.6 Remote Web Inspector HTTP target discovery 与 `Main.html` 返回 200 已实测，
但未执行 Inspector 命令会话，不能视为完整 DevTools 或 CDP 支持。macOS 子实验未验证。
此 ADR 不批准 P12 产品架构，也不能作为三平台验收。

## 目标与范围

用独立 Flutter Windows Release 探针验证一个平台 WebView 是否能按需创建、运行
DevTools/CDP 命令、导出并重新打开 MHTML，且销毁后回收 WebView 子进程。探针未加入
Alula app/ 或改变 Rust 核心。

## 结论

- Windows 11 上的 WebView2 与 `flutter_inappwebview 6.1.5` 可用：探针实际调用
  `Page.captureSnapshot(format=mhtml)`，落盘后在同一个 WebView2 中打开归档并还原页面；
  `Page.captureScreenshot` 导出的初始页与 MHTML 重载 PNG 都能看到
  `WEB_ENGINE_PROBE_OK` 标记。
- 单次 Windows Release 采样中，无 WebView 时进程树为 1 个进程 / 198.1 MiB；WebView
  已加载时为 7 个进程 / 369.3 MiB；MHTML 重载阶段为 7 个进程 / 404.1 MiB。销毁
  WebView 后采样回到 1 个进程 / 211.0 MiB；30 秒后为 1 个进程 / 203.9 MiB。WebView
  生命周期阶段比空探针高约 171–206 MiB，不能外推为完整编辑器成本。
- 不把一个 WebKit API 当作 WebView2/CDP 的等价实现：Apple `WKWebView` 提供
  `createWebArchiveData`（Web Archive）和 Safari Web Inspector；本实验没有证据证明
  它能提供同一 CDP/MHTML 合同。Linux 原生 WebKitGTK 检查证明其可用自身 API 保存/重载
  MHTML、截取页面和打开 Web Inspector，但没有证明它兼容 Chrome CDP，也没有验证 Flutter
  嵌入。所选 stable `flutter_inappwebview 6.1.5` 平台清单不含 Linux；上游 Linux WPE
  实现属于单独包。
- 因此当前证据证明 Windows Flutter/WebView2 可行，以及 Linux WebKitGTK 与 source-built
  WPE 在离线页面、MHTML 和截图上具备部分等价能力。WPE 试验未覆盖默认 sandbox、硬件
  加速或 CDP。P12 开工前仍需决定是否维护平台适配层，或评估
  在三平台分发统一 Chromium 内核的打包、许可、安全更新和内存代价；在该决定和真机
  对拍前，跨平台浏览器/DevTools 能力保持 open。

## 未验证 / 风险

- 无 macOS 设备；没有运行 WKWebView、归档重载、Safari Web Inspector 或进程内存测试。
- Flutter Linux/WPE 只在隔离 Xvfb 容器中的离线 fixture 跑过；这不覆盖桌面窗口事件、
  输入法、硬件加速、默认 sandbox 或 UI 集成对拍。WPE Remote Web Inspector HTTP target discovery
  与前端资源已在 sandbox-disabled 探针中验证，但没有 Inspector 命令会话；插件 CDP API 标记为不支持。
- 仅验证小型离线 HTML + data URI，不含跨源认证、cookie、媒体、下载、恶意网页隔离、
  DevTools 会话生命周期、CDP 事件订阅、剪贴板与编辑器集成。
- 单轮生命周期采样不覆盖重复导航、并发多个视图、1/10/30 分钟空闲、关闭工作区或
  完整应用基线差值；不能据此批准常驻内存预算。
- 上游 `flutter_inappwebview` stable 6.1.5 在本机 VS 2026 下构建需要额外条件；
  应先解决跨平台插件维护/编译和统一调试合同，再考虑产品依赖。

## 2026-10-28 WSLg EGL / GBM follow-up

WSLg 宿主有 `/dev/dxg` 与 DRM render node。用 surfaceless EGL 建立 GLES pbuffer，并设置
`GALLIUM_DRIVER=d3d12` 后，Mesa 报告 renderer 为 `D3D12 (AMD Radeon(TM) Graphics)`，EGL
context 创建成功。这证明 WSLg 可用 D3D12 硬件渲染，不证明 Flutter/WPE 实际使用该路径。

另在临时 Debian Bookworm 容器中把 `/dev/dri/renderD128` 传入并安装 `libgbm1`；节点可打开，
但 `gbm_create_device` 返回 null。该最小容器没有 WPE runtime，也缺少 Mesa DRI driver 文件，
日志显示 `vgem`、`zink`、`kms_swrast`、`swrast` 无法加载，因此结果对 WPE GBM/DMABUF 是
不确定的。没有修改既有 WPE 容器或产品代码。GBM 路径仍是 P00.4 未完成项。完整记录：
`p00.4-wslg-egl-evidence.json`。

随后从既有 WPE 2.52.6 构建容器快照启动一次性诊断容器，映射 `/dev/dxg`、`/dev/dri/card0`
与 `renderD128`，设置 `GALLIUM_DRIVER=d3d12`，并保持软件 GL、sandbox-disable 与
GBM-disable 变量均 unset。Xvfb `:99` 下 Flutter 无法创建 EGL context，WPEWebProcess
随后 crash，90 秒内没有到达 `initial-loaded`。相同容器连接 WSLg X11 `:0` 成功，但 EGL
初始化返回 `EGL_NOT_INITIALIZED (0x3001)`。现有日志显示这是 pinned Debian 12 Mesa 与
WSLg/X11 的 EGL 集成失败；没有取得 GBM buffer 或 WPE frame，不能判断 WPE 功能本身是否
支持硬件路径。临时容器和镜像已删除，原 WPE 容器保持不变。日志位于
`p00.4-linux-wpe-wslg-d3d12-run/`；P00.4 硬件 GBM 仍未完成。

补充检查同一 WPE 容器的 Wayland EGL：以 UID 1000、render supplementary group 992 运行，映射
`/dev/dxg`、`/dev/dri/renderD128`、WSLg Wayland socket 和宿主 D3D12 runtime libraries。
`wl_display_connect` 成功，但 Debian 12 Mesa 的 `eglInitialize` 返回
`EGL_NOT_INITIALIZED (0x3001)`，没有 GLES2 config，因此没有启动 Flutter/WPE 应用。这说明
当前容器与 WSLg Wayland EGL 组合仍不能建渲染上下文，不能作为 WPE GBM 支持或不支持的判定。
输出见 `p00.4-linux-wpe-wslg-d3d12-run/wayland-egl.log`。

最后在该 WPE 镜像中直接打开 `/dev/dri/renderD128` 并调用 `gbm_create_device`：render node
可打开，但 GBM device 返回 null，Mesa loader 报告无法取得 DRM device information，并尝试
加载不存在的 `vgem_dri.so`。没有分配 GBM buffer。宿主 DRM card 的 driver 标记为
`faux_driver`，所以该结果说明当前 WSLg render node 不能给这个容器提供 GBM device；它不

`p00.4-linux-wpe-wslg-d3d12-run/gbm-device.log`。
