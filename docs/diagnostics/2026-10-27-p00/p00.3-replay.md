## 可复放命令

从仓库根目录先构建原生核心，再分别运行 Flutter 与 Rust 夹具：

```bash
bash scripts/build_core.sh
cd app
flutter test test/p00_risk_fixtures_test.dart --reporter expanded
cd ..
cargo test -p editor-core --test p00_workspace_close -- --nocapture
cargo test -p editor-lsp --test p00_slow_completion -- --nocapture
```

夹具在成功复现当前行为时输出 `P00.3_FIXTURE=<json>`。这些断言用于固定现状，
不是目标行为；修复对应问题后应把它们改成正确行为验收，而不是接受旧输出。

| Case | 操作 | 当前源码推导的观测 |
|---|---|---|
| `parity-ref-07-undo-01` | 先编辑 `Cargo.toml`，再编辑 `src/main.rs`，分别切回文档撤销 | 工作台只有一份撤销栈；每个快照没有文档 ID，撤销会把另一个文件的快照写入当前文档 |
| `parity-ref-07-recovery-01` | 在脏文件中接受 2,000,001 个 UTF-16 单元，journal 落盘后重启工作台 | `_encodeSession` 对大于 2,000,000 单元的文档不序列化正文；恢复时重新读取磁盘内容 |
| `parity-ref-07-close-process-01` | 启动 workspace LSP、挂接文档、关闭全部文档并观察子进程 | `alula_doc_close` 断开文档，工作区服务器 map 仍持有进程引用 |
| `parity-ref-07-slow-completion-01` | 用 1,200 ms fake provider 返回补全并测调用耗时 | LSP 客户端同步等待响应；Dart 当前通过同步 FFI 调用它 |
