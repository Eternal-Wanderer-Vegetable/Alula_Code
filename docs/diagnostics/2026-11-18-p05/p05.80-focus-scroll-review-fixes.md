# P05.80 — row Enter focus and unchanged-refresh scrolling

This continues the active P05.80 SCM navigation slice. Read-only review found two defects beyond the previously corrected test timing issue:

1. Enter from a row reached by focus traversal requests focus on the list container before `_showGitDiff` snapshots the current primary focus. The deferred container-focus request then changes that focus while Git diff is pending, so the completion guard declines the intended diff focus transfer. The existing integration originally began with container focus and did not exercise this path.
2. `didUpdateWidget` always scheduled focus reveal while SCM had focus, even when entries and the focused row's position were unchanged. After manual scrolling, an unrelated workbench rebuild or watcher-driven Git refresh scrolled back to that row. A red regression observed offset480 becoming24.

Both regressions failed before the production correction. `_open` now preserves an already-focused SCM descendant instead of moving focus internally. Keyboard arrows still explicitly request list focus. Update reveal is now conditional on the focused row's pixel offset changing; section-header geometry is included, and removal still clears focus/selection by identity. The calculation is shared with ordinary keyboard reveal. No new persistent state, timer, cache or polling is added.
