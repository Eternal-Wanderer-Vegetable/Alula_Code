# P01.4 事件驱动工作区生命周期

日期：2026-10-30

## 交付范围

- `WorkspaceWatcher` 用 generation 标记每次 start/stop。stop 立即使回调失效、取消未到期防抖 timer、解除订阅并等待 cancel 完成；停止后队列里的旧事件不能触发 UI 回调。
- 工作台将 watcher 切换串行化。workspace root 变更时先停止旧 watcher，再按当前 root 创建新 watcher；迟到的旧 root 回调会被丢弃。dispose 会使代次失效并安排 watcher 停止。
- 语法快照不再由 800ms 循环遍历所有 LSP 文档生成。文档打开、编辑或 attach 时，只为对应文档安排 80ms 防抖刷新；关闭文档、切换工作区和退出时取消 timer，并移除已关闭文档的语法状态。
- 诊断快照仍使用轻量 800ms 轮询，但只查询已 attach 的非 untitled 文档；没有此类文档时 timer 会停止。轮询不触发文件解析。

- `diagnostics` 的符号/字段解析有歧义；本阶段没有修改 Rust 诊断协议或 LSP 读线程，只改变工作台的快照读取和语法刷新调度。

## 验收边界

- watcher 单测覆盖 stop 后不回调、取消已排队 debounce、重复 start/stop 后单订阅及递归子目录事件；既有 widget suite 覆盖外部修改自动重载。
- 本阶段没有真实 Windows/macOS 长会话，也没有自动化真实 LSP 服务下连续切换多个 workspace root 的 UI 端到端测试。根目录代次和订阅串行化由实现审查与 watcher 单测覆盖，不能据此声称所有桌面 watcher 后端均完成跨平台验证。
- 诊断快照在 LSP 文档打开期间仍轻量轮询；本次移除的是 800ms 全文档语法查询/解析。无已 attach 文档时不会保留该轮询。
- 没有按 500 MiB 数值门限验收或调参。该目标按用户优先级调整暂停，P14 重新定标；本阶段仍要求 watcher、服务和计时器在生命周期结束时回收。
