# P05.372 主窗关闭前收尾已打开的辅助窗

主窗关闭复用 P05.180 文档移交。主窗用原生窗口列表确认辅助窗退出，写入当前会话，再调用既有的语言服务器清理和主窗关闭。如果移交或会话写入失败，保留主窗和可编辑内容。

Linux 辅助引擎先回送移交确认，再退出。复验曾观察到 GTK 任务运行器清理时的锁冲突和 GLX BadAccess。在辅助窗退出前取消主窗 GTK 界面的映射。移交失败时恢复主窗可见。

## 原生验收

- 基线启用与真实入口一致的主窗关闭拦截。Windows 在干净和未保存编辑两种场景均以 0xC000041D 退出。Linux 主窗关闭后仍有辅助窗可见，进程超过 9 秒未退出。原文件保持不变。
- 同一产品树在 Windows 和 Linux 各两次正常退出，四轮退出码为 0，原生窗口清单清空。干净文件路径保留在主窗会话。未保存的 Emoji 正文写入会话 journal，磁盘原件的 BOM、CRLF 和 SHA-256 一致。
- 两端同路径移交冲突各复验一次。进程和两个窗口继续存活，辅助窗正文和 UTF-16 选区保留，拒收提示可见。Linux 主窗恢复可见。验证后夹具终止各自的隔离实例。
- Windows 在未激活的独立 WinSta0 桌面向指定的测试主窗发送 WM_SYSCOMMAND 和 SC_CLOSE。实际输入桌面未切换，夹具未发送键鼠输入。Linux 使用隔离 Xvfb、Xfwm4 和 Alt+F4。[原生回执与构建哈希](p05.372-main-close-with-auxiliary/native.json)。
