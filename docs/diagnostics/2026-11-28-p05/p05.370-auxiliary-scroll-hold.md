# P05.370 辅助窗口 Hold 锁定滚动键位

辅助窗从主工作台使用的配置路径加载键位。编辑器焦点中的 Hold 临时反转共享锁定。主窗以窗口身份和消息顺序管理临时状态，任何键释放、原生失焦和辅助窗关闭都会结束该窗的 Hold。裸 Alt 无默认绑定，Hold 不出现在辅助窗命令面板。[固定版本 Hold 行为](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/scrollLocking/browser/scrollLocking.ts#L210-L232)。

## 原生验收

- Linux 基线 `2dde4d5aea2284ebca02c2b376e4952e7c483de0` 中，辅助窗按住已配置的 F8 时，主辅状态栏保持未锁定。完成后分别以 F8 和 Ctrl+K F8 复验。原生配置的条件为 `editorTextFocus && isAuxiliaryWindow && !quickInputVisible`，每次采用独立配置。
- Windows 125% 和 Linux Xvfb + Xfwm4 的两种键位各通过 19 项，共四轮。Windows 持有时的滚轮同步位移为 160 逻辑像素，Linux 为 106。反向 Hold 期间主窗位置保留，释放、失焦和关闭恢复会话中的锁定。两个 BOM、CRLF、Emoji 文档的字节 SHA-256 一致，四轮应用退出码均为 0。
- Windows 演练中曾观察到前台切换及裸 Alt 结束后焦点变化。夹具分开验证 Alt 与 Hold，并在实际发键前检查编辑器焦点。组合键重跑增加了隔离窗口的前台确认，避免延迟的激活请求打断滚动。产品构建保持同一版本。[原生状态、位移和构建哈希](p05.370-auxiliary-scroll-hold/native.json)。

## X11 共享键位复现

同一 F8 同时对主窗和辅助窗生效时，保持 F8 按下并激活主窗。辅助窗收到失焦，主窗随后收到一条 `synthesized=false` 的 F8 KeyDown 以及后续重复事件，重新进入 Hold。该复现继续由 P05.371 跟踪，LAY-15 行仍在验收中。[焦点与重复键回执](p05.370-auxiliary-scroll-hold/native.json)。
