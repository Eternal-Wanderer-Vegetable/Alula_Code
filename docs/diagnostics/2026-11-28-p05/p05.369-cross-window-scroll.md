# P05.369 主辅窗口横纵滚动锁定

## 实现

主工作台按各可见编辑器的起点计算横纵相对位移，再通过窗口通道发送给辅助窗。轴的目标位置按各文档当前滚动范围限位。窗口加入、关闭或可见编辑器变化时更新起点。有效锁定和起点各有版本，应用跟随位移时阻止回传。每个方向只保留一条待发记录，旧版本和源窗口迟到的回执会被丢弃。辅助窗的自定义 Hold 键位由后续 LAY-15 验收覆盖。[固定版相对位移](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/scrollLocking/browser/scrollLocking.ts#L66-L154)。[可见编辑器](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/services/editor/browser/editorService.ts#L492-L494)。[分窗口编辑器组](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorParts.ts#L718-L742)。

## 原生验收

- 基线 `008e53955b6a115c95c135266e334671fb9ca0ff` 中主窗在锁定时滚动 106 逻辑像素，辅助窗仍停在 159。完成后 Linux 对应检查中辅助窗到达 265，与计算值一致。
- Windows 125% 和 Linux Xvfb + Xfwm4 各通过 18 项。以实际滚轮检查两个相反方向的跨窗位移，第二个辅助窗同时带动主窗和第一个辅助窗，短文档达到边界后能够回转，关闭锁定后各窗独立。三个 BOM、CRLF、Emoji 文档的字节哈希在两端保持一致，应用正常退出。
- Linux 首轮切换前台时触发了视口重定位，两个起点测成相同位置。夹具改为等待原生焦点稳定后再读滚轮前的位置。Windows 初轮窗口激活受限，随后窄窗夹具未成功选择长文档，中断后关闭主窗出现退出码 `3221226525`。重新激活隔离窗口并放宽主窗后，同一发布构建完成全部检查，按序关闭两扇辅助窗和主窗，退出码为 0。[原生坐标、原始回执哈希和构建哈希](p05.369-cross-window-scroll/native.json)。
