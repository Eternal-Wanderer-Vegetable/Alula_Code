# P05.371 切窗后抑制 Hold 键自动重触发

## 根因和修复

Windows 与 Linux X11 的基线均复现了共享 Hold 键位切窗后重触发。辅助窗失焦后，主窗将首个重复输入报告为 KeyDownEvent，synthesized 为 false，随后报告 KeyRepeatEvent。常驻开关保持开启，两个窗口再次进入临时反转。

Windows 使用按键消息的 previous-state 位。Linux 使用 XI2 的重复位、扫描码和时间戳，并将原生子窗口事件匹配到所属顶层窗口。通过核验的新按下才进入 Hold。任何键释放、原生失焦或窗口关闭均取消当前或待定的 Hold。命令分发和会话开关沿用既有行为。

## 原生验收

- Windows 125% 和 Linux Xvfb + Xfwm4 使用条件 editorTextFocus && !quickInputVisible。F8、Ctrl+K F8 各通过 17 项。两种常驻状态下分别复验主窗到辅助窗与辅助窗到主窗。原键保持按下时恢复常驻状态，松开后重新按下可再次反转。
- Linux 组合键夹具在接收窗输入前缀后，让仍保持按下的 F8 恢复产生 XI2 重复消息。归一化前，重复事件的子窗口 XID 与查询的顶层窗口 XID 不符。Windows 保持按下状态并重放同一扫描码。四轮均正常退出，两个含 BOM、CRLF 和 Emoji 的文档字节哈希一致。[原生前后对照和构建哈希](p05.371-cross-window-hold-repeat/native.json)。
- Windows 实测树为 416a558d3ee548d975d5c3904da20580c650a189。最终产品与该树仅有 Linux runner 的 XID 归一化差异。Windows runner、Dart、Rust、打包 AOT 和原生库哈希均已复核。
- 原生实现以固定数组保存最近 128 条按下元数据。Linux 进程树 mem-probe 每个检查点采集三次，私有内存中位数为 main-open 232.5 MiB、both-windows-open-unlocked 356.4 MiB、closing-auxiliary-preserves-durable-toggle 385.9 MiB。仓库历史值为空工作区的 Windows Private Bytes 189.9 MiB，平台、采样口径和负载不同。[历史基线](../../baselines/2026-10-26/alula-w2-empty.md)。
