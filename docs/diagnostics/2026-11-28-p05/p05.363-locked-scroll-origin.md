# P05.363 同窗纵向锁定滚动位移

## 实现

固定 Code OSS 1.145.0 的内置 SyncScroll 对各可见编辑视图记录起始位置，并将来源视图相对起点的位移加到目标视图起点。可见视图变化时重新取起点，同一文档的并排视图也各有位置。本子项对齐同窗纵向 Toggle，覆盖边界裁剪和回转。原 P05.52 的上游说明已根据固定源码校正。横向、固定版 Hold 和跨窗仍按 LAY-15 追踪。[固定版本滚动实现](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/scrollLocking/browser/scrollLocking.ts#L66-L150)。

## Windows 实机与 Linux Xvfb

- 产品 `ea4aa75f2bb0e111f102b8c169f0e8c570a892a3`，树 `9b5e331e9bec0047972f37109b82c7a6ab7753ba`。Windows 125% 缩放和 Linux Xvfb + xfwm4 各通过 16 项。实际滚轮先设不同起点，开启后维持两个位置。Windows 起点 240/80，滚轮后 320/160。Linux 起点 159/53，滚轮后 212/106。反向由另一组驱动，短文档越界时夹紧并以原起点计算回转。组件测试验证来源回到原位置时目标也精确回到自己的起点。
- 同一 Rust 文档拆成两个编辑视图后，三个视图一起接收位移。合并后余下视图按新起点同步，解除锁定后滚轮只移动当前视图。两端文本逐字符和文件哈希一致，应用正常退出。Linux 首轮将滚轮定位在未裁剪文本矩形中部，拆分场景未观察到滚动。夹具改为靠近可见正文左侧，复用同一构建通过。原生键位使用隔离配置。[原生滚动位置和构建哈希](p05.363-locked-scroll-origin/native.json)。
- Linux `mem-probe` 在开启前、同步中及关闭后记录一个 Alula 进程，Private 分别 243.95、240.36、236.92 MiB。仓库历史 Windows W2 空窗稳定 Private 为 189.85 MiB。此次 Linux 样本打开两个文本文件，阶段日志与两种环境的基线均见原生记录。
