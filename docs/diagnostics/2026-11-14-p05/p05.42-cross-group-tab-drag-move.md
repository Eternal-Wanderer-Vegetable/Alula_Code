# P05.42 / feat-094 / LAY-10b — 跨编辑器组标签拖放移动（实现与验收）

日期：2026-11-14。分支 `codex/vscode-parity-p05`（PR #3），基线 `5558e5e`。

## 实现范围（与登记切片一致）

- `app/lib/workbench/workbench_page.dart`：
  - 新增 `_tabDragSourceRegion`：`Draggable.onDragStarted` 记录源组 region，`onDragEnd`/`onDraggableCanceled` 清空。文档 id 是共享文档标识（同文档多视图同 id，`OpenDoc.id` 委托 `_shared.id`），仅凭 drop 时的 id 无法消歧源组，必须以拖动开始时的 region 解析。
  - `_buildTab` 的 `DragTarget<int>` 由 `Builder` 包裹以在 drop 时捕获目标标签的 `RenderBox`：`onAcceptWithDetails` 用 `details.offset`（`pointerDragAnchorStrategy` 下即指针全局位置）与标签中点比较得出 before/after。同组或源组无法解析时保持原 `_moveDoc` 路径不变（同组中点落点的既有语义不受影响）。
  - `onWillAcceptWithDetails` 放宽为 `details.data != d.id || _tabDragSourceRegion != g.region`：此前同文档 id 的跨组 drop 会被旧守卫拒绝，无法触达"激活既有视图"分支。
  - 新增 `_moveDocAcrossGroups(source, target, draggedId, targetTabId, {insertAfter})`：校验源/目标仍持有对应文档（陈旧身份静默忽略）；移动同一个 `OpenDoc` 视图对象（Rust 文本、脏标/存档点、撤销历史、选区、滚动随对象保留）；焦点节点按 `_focusKeyFor` 键迁移（与 `_moveFocusedEditorToGroup` 相同的模式）；插入位置按目标组 sticky 划分边界 clamp（sticky 落 0..stickyCount，普通落 stickyCount..length）；激活被移动文档与目标组并迁移 `_focusedRegion`；源组激活回退 `_mostRecentDocument`；干净预览不再作为目标组预览（对齐上游 moveEditor 的 pinned 行为，区别于方向移动命令保留 preview 的既有行为，后者保持不变）；目标组已有同文档视图时激活既有视图并用 `_closeDocNow` 移除源组重复视图；源组清空且组数 >1 时经 `_layout.removeRegion` 摘除源组（失败给出状态提示）；`_scheduleStateSave` 走既有会话/布局保存路径。
- 无 Rust/FFI/ABI 改动；无内存常驻结构新增（仅一个可空 String 字段，拖动结束即清空）。

## 测试（先红后绿）

新增 `app/test/editor_tab_cross_group_move_test.dart`，6 个 focused widget tests，全部先红后绿：

1. 双向跨组拖动 + 指针左右半区决定前后插入 + 双侧激活态 + 组内排序回归 + 会话恢复（卸载重挂后组/标签次序与活动标签一致）。
2. 目标组已显示同一文档：丢到同 id 标签与不同标签均激活既有视图、移除源组重复视图、不重复插入；由此清空的源组被摘除。
3. 源组仅剩最后一个标签时移动清空源组并摘除其 region。
4. 脏文档移动保留同一 RustTextInputFieldState/inputWindow/focusNode/scrollController/text controller、文本、选区、滚动偏移、焦点与脏标，且撤销历史随文档（移动后 Ctrl+Z 仍可撤销）。
5. sticky 标签并入目标组 sticky 前缀；普通标签被 clamp 在 sticky 划分之后；sticky 归属随移动迁移。
6. 干净预览跨组移动后变为普通标签（目标与源组 preview 均清空、斜体消失）。
