# P05.44 / feat-096 / LAY-10d — 拖入组区域（追加/合并）

## 固定基线与上游行为

- 基线：Code-OSS 1.145.0 commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`。
- 落点目标覆盖整个组视图（不止标签）：[`editorDropTarget.ts` handleDrop](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorDropTarget.ts#L252-L345)——`splitDirection` 未定义时 `targetGroup = this.groupView`，编辑器移入/复制入该既有组；`sourceGroup === targetGroup` 时直接返回（同组区域落点无操作）；落点后 `targetGroup.focus()`。
- 复制修饰键与 Singleton 回退：[`editorDropTarget.ts` isCopyOperation](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/editorDropTarget.ts#L374-L380)（Windows/Linux Ctrl、macOS Alt；untitled 回退移动）。
- 移动/复制进入既有组按 `moveEditors`/`copyEditors` 无 index → 追加到组末尾并激活（`editorGroupView.ts` moveEditor/doOpenEditor 既有同文档时激活既有视图；copy 走 `editor.copy()`）。
- 拆分落点（边缘区域建新组）与 Alt(Win/Linux)/Shift(macOS) 的 splitOnDragAndDrop 反转是独立子项，本切片不实现（整组区域在本切片内表现为单一合并区）。

## 当前 Alula 行为与缺口

- P05.42–P05.43 之后，标签拖放只在标签的 `DragTarget<int>` 上生效；拖到组的标签条空白区、面包屑或编辑器正文区域无任何落点行为。上游整组区域都是落点目标（中心区=追加/合并）。
- `_buildEditorArea(g)` 是组面板（标签条+面包屑+编辑器正文）的构建点，可包裹组级 `DragTarget<int>`；内层标签 DragTarget 命中优先，其余位置落到组级。
- `_moveDocAcrossGroups`/`_copyDocAcrossGroups` 目前要求非空 `targetTabId`；扩展为可空以支持"追加到组末尾"语义。

## 登记范围

- 组级 `DragTarget<int>` 包裹 `_buildEditorArea` 的组面板（key `editor-drop-area-<region>`）：落在标签之外的组区域（标签条空白、面包屑、编辑器正文）时，把被拖文档移入该组末尾并激活（对齐上游无 index 的 moveEditor + `targetGroup.focus()`）。
- 复制修饰键（Windows/Linux Ctrl、macOS Alt）+ 文件文档 → 复制为新视图追加到组末尾；未命名文档回退移动；目标组已显示同文档时按既有语义激活既有视图（移动关闭源视图、复制仅激活）。
- 同组区域落点无操作；源组解析失败/文档已不在源组时静默忽略（沿用 P05.42 的陈旧身份处理）。
- 持久化走既有 `_scheduleStateSave` 等路径；无 Rust/FFI 改动。
