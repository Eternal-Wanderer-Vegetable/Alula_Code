# P05.49 / feat-101 / LAY-12a — 浮动辅助窗口：基础设施与移入新窗（拆分登记）

## 拆分说明

LAY-12（浮动辅助窗口）按基础设施体量拆为两个切片：
- **P05.49 / LAY-12a（本切片）**：`desktop_multi_window` 依赖、辅助窗口入口与生命周期、
  标签上下文「在新窗口打开」/命令 `workbench.action.moveEditorToNewWindow`、文档在新窗口
  按 path 重开（未命名文档经 journal 文本传递）、源组移除联动与关闭恢复入口。
- **LAY-12b（后续切片）**：组/焦点双向同步、compact/pin-top 形态、移回主窗、关闭恢复
  一致性、跨窗口拖拽。

## 固定基线与上游行为

- 基线：Code-OSS 1.145.0 commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`。
- 上游：`auxiliaryWindow` 支持（src/vs/workbench/browser/parts/editor/auxiliaryEditorPart.ts
  与 auxiliaryWindowService）。1.145 的编辑器右键含 Move to Auxiliary Window；拖出窗口边界
  也可创建辅助窗口。文档在新窗口以共享 input 打开（同一进程）；Alula 的 Rust FFI core 为
  每进程一份，**无法跨进程共享文档句柄**——新窗口按 path 从磁盘重开（干净文档语义一致），
  未命名/脏文本经辅助窗口启动参数传递 journal 文本（savepoint/撤销历史不跨进程，差异登记）。

## 基础设施评估（实现前提）

1. 新依赖 `desktop_multi_window`（Windows/macOS/Linux 三端插件；Windows runner 需注册
   plugin）。启动入口 `main(List args)` 按 `--alula-auxiliary-window=<id>` 分流：主入口走
   现有 windowManager 初始化；辅助入口创建辅助 WorkbenchPage（无 activity bar/侧栏的精简
   编辑器布局，对齐上游 auxiliary window 的 minimal chrome）。
2. 窗口状态：desktop_multi_window 的 WindowController 持有窗口 id；移回/关闭经主窗口与
   辅助窗口间的事件通道广播（关闭辅助窗口 → 主窗口恢复该文档视图）。
3. 主窗侧：上下文菜单项「在新窗口打开」与命令注册；执行时从源组 `_closeDocNow`（干净）
   或提取 journal 文本（脏/未命名）后移除视图，并把 path/text 传给新窗口。

## 登记范围（LAY-12a）

- 依赖与窗口分流入口；辅助窗口精简布局（标签条 + 编辑器 + 关闭/移回按钮占位）。
- 「在新窗口打开」上下文菜单项与命令；执行后源组移除该视图（脏文档文本经启动参数传递）。
- 新窗口按 path 重开文档（磁盘干净态）；未命名/脏文本以 journal 文本呈现为脏文档。
- 主窗口关闭恢复：辅助窗口关闭时其当前文档（若主窗口未打开）回主窗口打开。
- 会话/布局持久化不动（辅助窗口为瞬态，主窗口会话不含辅助窗口状态——与上游
  auxiliary window 不入主 workbench recovery 的行为一致）。

## 排除（LAY-12b）

组/焦点跨窗同步、compact/pin-top、移回命令闭环、跨窗口拖拽、窗口状态持久化。
