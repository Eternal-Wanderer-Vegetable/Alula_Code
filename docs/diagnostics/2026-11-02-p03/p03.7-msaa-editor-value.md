## CI failure and root cause

- Platform runs `41454766999`, `41456756543`, and `41458740387` repeatedly failed the Windows accessibility assertion. The latest pre-fix run still passed Release build/launch, the P03.7 interaction suite, native drag/drop, and clipboard; only the accessibility step failed.
- The captured editor node was focused (`State=3145732`, so `State & 4 != 0`) but exposed an empty MSAA `Value`, while the captured client showed the welcome text. Its lifecycle metadata recorded `WM_CLOSE`, `closeTimedOut=false`, `gracefulClose=true`, and `exitCode=0` (artifact `13148109083`, run `41458740387`). This was an accessibility data defect, not an app crash or failed focus request.
- A headless Flutter widget test reproduced the same empty semantics value before the fix. `RustTextInputField` supplied the editor label and `textField` flag but did not explicitly expose the current bounded input window as the semantics value.
- `RustTextInputFieldState.build` now supplies `value: editingValue.text` to the editor `Semantics` node. The new widget regression test checks the label and the Chinese welcome text value.
