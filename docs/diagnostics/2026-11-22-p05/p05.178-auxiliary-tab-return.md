# P05.178 / feat-230 · 辅助窗标签拖回主窗已有组

依赖 P05.69、P05.174、P05.177，均已完成。普通辅助窗的活动文本标签可拖到主窗已有编辑器组。组正文追加到末尾，标签左半侧或右半侧决定插入位置，已有固定标签保留在前。接收后激活目标组及文档，源辅助窗在原生拖放结束后关闭。窗口外或非编辑器落点、取消和拒绝保留源窗及内容。

- Windows 用限制在两个隔离 Alula 窗口内的原生鼠标夹具执行拖放，以 UIA 和应用内测量验证。桌面控制的一次拖动受源窗口边界所限，早期移动采样未完成拖放。最终复验选区分别为 `[19, 18]` 和 `[20, 19]`，目标编辑器继续写入后正文为 `Compact example 😀890`。
- Linux 早期夹具使用 `--clearmodifiers` 时提前释放按住的鼠标键。修正为按住鼠标期间直接发送 Escape，实测取消路径保留源窗。另一轮早期回拖结束时出现 GLX BadAccess，现让原生拖放结束并等一帧后再按 P05.176 的顺序隐藏并关闭辅助窗。最终正文路径另外通过两轮 GLES 与一轮默认 GLX 复验。Linux 夹具在结果核对后主动清理其进程，记录退出码 −15。
- 所有取样中的 Rust 与 Flutter 文本逐字符一致。文件包含 UTF-8 BOM、CRLF 和 emoji，磁盘文件 SHA-256 保持 `669535bddcebbaa3439dfb8a47de514f54242d3320c5f83094b11c3cb12690ca`。Windows 和 Linux 具体验证轨迹、原生构建树及 AOT 校验值见[原生证据](p05.178-auxiliary-tab-return/native.json)。
