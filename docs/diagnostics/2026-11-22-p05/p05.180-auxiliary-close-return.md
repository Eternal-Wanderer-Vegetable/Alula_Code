# P05.180 / feat-232 · 辅助窗关闭前确认文档已移交

依赖 P05.176 的原生关闭生命周期和 P05.178 的跨窗接收。活动标签关闭槽、应用顶栏关闭和系统关闭共用一次移交。主窗确认接收当前版本的脏文档后，源窗释放 Rust 文档并关闭。通道不可达、冲突拒收或确认超时会保留源窗、脏正文、选区和编辑入口。

## 固定版本核对与实现

固定 Code-OSS 1.145.0（`4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`）在辅助窗正常关闭时先处置无需确认的编辑器，再把需确认的文档合并到主窗，合并失败时保留辅助窗。Alula 的改动覆盖单文档辅助窗的未保存交接。干净的具名文件继续按现有路径从磁盘重开。[固定版源码](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/editor/auxiliaryEditorPart.ts#L444-L467)

- 旧路径在主窗通道抛错后仍销毁辅助窗。Linux 和 Windows 组件夹具均复现，分别记录隐藏与销毁、直接关闭。
- 新路径在等待前同步采集正文、文档版本和 UTF-16 选区。待确认期间阻止另一次关闭。超时后使用相同序号重试一次，两个请求都超时则恢复源窗，已经超时的回复不能关闭下一次请求的窗口。
- 主窗在工作台接收并确认内容后，移除该源窗的拖放边界。它对同一序号和仍可用的接收副本返回已有确认。当较早的主窗副本已关闭而源窗仍在，旧确认会失效，源窗可重新发送新快照。两份不同版本的同路径文档仍走冲突保护。组件夹具覆盖迟到确认、重放、重新接收和旧边界拒收。
