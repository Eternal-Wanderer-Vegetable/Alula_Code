## 目标与边界

为主窗口与辅助编辑器窗口维护同一份“当前活动编辑器 part”元数据：窗口获得/失去原生焦点，或其本地活动组/文档发生变化时，主窗口协调器更新活动 owner，并向存活的辅助窗口广播最新快照。快照只包含 `windowId`、窗口内 group 标识、document identity 与单调递增 revision；辅助窗口的单编辑器组使用按窗口命名空间隔离的标识。

本 slice 只同步焦点 owner 与组/文档身份元数据。**不传文档全文、dirty/savepoint、selection/caret、undo/LSP 状态或 session 数据**；不提供同文档多窗实时编辑，也不改变现有本地命令对 `_active` 的选择。关闭一个辅助窗口时清理它的 owner 条目；若它是当前活动 owner，选择仍存活的最近活动 part，缺省回主窗口当前活动组。

明确排除：跨进程文档/selection 同步、命令路由到另一窗口、compact mode、always-on-top（P05.66 已单独交付）、移回主窗命令闭环、辅助窗间传输、跨窗口拖拽、窗口状态持久化，以及通用窗口管理重构。

## 实现与 GitNexus 影响

- 新增 `AuxiliaryFocusContextRegistry` 作为主窗口的 owner/MRU authority。事件包含 protocol、窗口 ID、窗口内序号、group/document identity 与 focus 状态；协调器拒绝重复或旧序号，只在活动身份改变时递增 snapshot revision。snapshot serializer 严格只输出 `windowId`、`groupId`、`documentId`、`revision`。
- 主窗口先安装 method handler，再完成 channel-ready 信号并允许创建辅助窗口。创建 payload 显式携带 `mainWindowId`，辅助窗口先注册接收 snapshot 的 handler，再向该主窗口发送 registration，避免 `getAll()` 竞态。辅助窗口收到 snapshot 时只接受更高 revision；主窗口按本地 command context 变化及 focus/blur 事件更新本地 owner 元数据，并向已注册存活辅助窗口广播 snapshot。现有本地命令仍路由到该 engine 的 `_active`。
- 辅助 owner 最多 32 个；创建中的窗口也计入上限。`onWindowsChanged` 事件和既有 close 通道清理关闭 owner，当前 owner 关闭后按最后真实活动顺序回退到仍存活 owner，否则回主窗口。window listeners 在 dispose 移除；没有 polling/timer。
- `AuxiliaryWindowPayload` 仍含既有文档启动/恢复/移回流程所用的 path/name/text/dirty 字段；这是原有文本恢复协议。新增 focus metadata event 和 snapshot 均不含文本、dirty/savepoint、selection/caret 或 session。
- `workbench_page.dart` 超过 GitNexus 默认 512 KiB 上限且被跳过；`_WorkbenchPageState` 与其私有 method exact impact 为 UNKNOWN/未索引。源码调用点复核确认 `_groups`、`_focusedRegion`、`_active`、`_syncCommandContext` 及 handler/move 流程均来自该 state object，UNKNOWN 不作为无影响证明。
- 本轮最新索引：12,735 nodes、32,757 edges、395 clusters、434 flows。`AuxiliaryFocusContextEvent` exact upstream LOW（4 direct、1 process、1 module）；`AuxiliaryWindowPayload` LOW（1 direct、0 resolved processes）。相同 exact target 重复查询会不稳定：`AuxiliaryFocusContextRegistry` 在 LOW（2 direct）与 CRITICAL（2 direct、140 processes、20 modules）间变化；`AuxiliaryEditorApp` 在 LOW、CRITICAL（4 direct、142 processes、20 modules）及 UNKNOWN 间变化。输出中有大量明显不相关的测试/跨语言路径；保留观测到的 CRITICAL/UNKNOWN，不用 LOW 结果覆盖，也不据此推断不存在影响。
- `_WorkbenchPageState` 与 `_WorkbenchPageState.initState` 精确目标无法解析/UNKNOWN；`workbench_page.dart` 超默认 512 KiB 被跳过。源码调用点确认主窗 `initState` 注册 `windowManager.addListener(this)`、`dispose` 移除 listener；新增集成断言检查 listener 注册/注销及原生 focus event 将 owner 切回主窗。

## N.2 验收条件

1. 固定上游 active-part/group 生命周期映射；焦点 owner 快照必须有 window/group/document identity 与 revision，消息 payload 不含全文、dirty、selection 或 session。
2. main → auxiliary 与 auxiliary → main 两个方向都更新全局活动快照；连续窗口切换按最新 revision 决胜，重复/过期消息不回滚状态。
3. 辅助窗口关闭会从 MRU/owner registry 移除，当前 owner 关闭时退回最近存活窗口；多辅助窗口之间不串台。
4. 测试主窗多组、多活动辅助窗、切换次序、重复/乱序消息、关闭当前/非当前 owner、平台焦点 API 失败；以 dirty CRLF + emoji 文档断言全文、selection、dirty/savepoint、payload/session 不变。
5. 新增窗口/监听器在对应 engine 生命周期内注册，dispose/close 后清理；禁止 polling/timer 与常驻无界事件缓存。窗口 ID 与 owner map 均有明确上限/清理路径。
6. 原生 focus/blur hosted behavior 仅在有真实 OS 自动化证据时称为通过；widget method-channel 测试不等于系统焦点证明。当前 Platform Availability 未声明会操作双窗焦点，需要 scope closeout 单独注明。
