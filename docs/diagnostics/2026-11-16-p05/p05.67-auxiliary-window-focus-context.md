# P05.67 / feat-119 / LAY-12b2：辅助窗口活动组与焦点上下文同步

日期：2026-11-16  
状态：按用户选择收窄为 window/group 元数据后，本地 N.2 与 hosted closeout 完成。原生 OS 双窗口焦点仍未实测，不计为已验证。
父项：P05 / `feat-027`；前置 P05.66（`feat-118`）、P05.49（`feat-101`）。

## 目标与边界

为主窗口与辅助编辑器窗口维护同一份“当前活动 editor part/group”元数据：窗口获得/失去原生焦点，或其活动组发生变化时，主窗口协调器更新活动 owner，并向存活的辅助窗口广播最新快照。快照只包含活动 `windowId`、窗口内 `groupId` 与单调递增 revision；辅助窗口的单编辑器组使用按窗口命名空间隔离的标识。用户在本地验证前选择只同步活动窗口/组标识，因此取消最初方案中的 document identity 字段。

本 slice 只同步焦点 owner 与活动 window/group 标识。**focus event/snapshot 不含文档标识、文档全文、dirty/savepoint、selection/caret、undo/LSP 状态或 session 数据**；不提供同文档多窗实时编辑，也不改变现有本地命令对 `_active` 的选择。既有 `AuxiliaryWindowPayload` 的 path/name/text/dirty 仍用于文档移窗、启动和关闭恢复，不属于 focus protocol。关闭一个辅助窗口时清理它的 owner 条目；若它是当前活动 owner，选择仍存活的最近活动 part，缺省回主窗口当前活动组。

明确排除：跨进程文档/selection 同步、命令路由到另一窗口、compact mode、always-on-top（P05.66 已单独交付）、移回主窗命令闭环、辅助窗间传输、跨窗口拖拽、窗口状态持久化，以及通用窗口管理重构。

## 实现与 GitNexus 影响

- 新增 `AuxiliaryFocusContextRegistry` 作为主窗口的 owner/MRU authority。事件包含 protocol、窗口 ID、窗口内序号、group ID 与 focus 状态；协调器拒绝重复或旧序号，只在活动 window/group 改变时递增 snapshot revision。event serializer 只输出 `protocol`、`type`、`windowId`、`sequence`、`groupId`、`focused`；snapshot serializer 只输出 `windowId`、`groupId`、`revision`。
- 主窗口先安装 method handler，再完成 channel-ready 信号并允许创建辅助窗口。创建 payload 显式携带 `mainWindowId`，辅助窗口先注册接收 snapshot 的 handler，再向该主窗口发送 registration，避免 `getAll()` 竞态。辅助窗口收到 snapshot 时只接受更高 revision；主窗口按本地活动组与 focus/blur 事件更新 owner 元数据，并向已注册存活辅助窗口广播 snapshot。现有本地命令仍路由到该 engine 的 `_active`。
- 辅助 owner 最多 32 个；创建中的窗口也计入上限。`onWindowsChanged` 事件和既有 close 通道清理关闭 owner，当前 owner 关闭后按最后真实活动顺序回退到仍存活 owner，否则回主窗口。window listeners 在 dispose 移除；没有 polling/timer。
- `AuxiliaryWindowPayload` 仍含既有文档启动/恢复/移回流程所用的 path/name/text/dirty 字段；这是原有文本恢复协议。focus metadata event/snapshot 均不含 document identity、文本、dirty/savepoint、selection/caret 或 session。
- `workbench_page.dart` 超过 GitNexus 默认 512 KiB 上限且被跳过；`_WorkbenchPageState` 与其私有 method exact impact 为 UNKNOWN/未索引。源码调用点复核确认 `_groups`、`_focusedRegion`、`_active`、`_syncCommandContext` 及 handler/move 流程均来自该 state object，UNKNOWN 不作为无影响证明。
- `bb0aa87` 初版 document-identity 协议的索引为 12,735 nodes、32,757 edges、395 clusters、434 flows。该轮 `AuxiliaryFocusContextEvent` exact upstream LOW、payload LOW；重复 exact 查询对 registry/app 曾在 LOW、CRITICAL、UNKNOWN 间波动（历史 CRITICAL 曾分别报告 140/142 processes）。保留这些历史 CRITICAL/UNKNOWN，不用新 LOW 结果覆盖。

## N.2 验收条件

1. 固定上游 active-part/group 生命周期映射；焦点 owner 快照只含活动 window ID、group ID 与 revision，event 另含必要的序号/focus 状态；focus protocol 不含 document identity、全文、dirty、selection 或 session。
2. main → auxiliary 与 auxiliary → main 两个方向都更新全局活动快照；连续窗口切换按最新 revision 决胜，重复/过期消息不回滚状态。
3. 辅助窗口关闭会从 MRU/owner registry 移除，当前 owner 关闭时退回最近存活窗口；多辅助窗口之间不串台。
4. 测试主窗多组、多活动辅助窗、切换次序、重复/乱序消息、关闭当前/非当前 owner、平台焦点 API 失败；以 dirty CRLF + emoji 文档断言全文、selection、dirty/savepoint、payload/session 不变。
5. 新增窗口/监听器在对应 engine 生命周期内注册，dispose/close 后清理；禁止 polling/timer 与常驻无界事件缓存。窗口 ID 与 owner map 均有明确上限/清理路径。
6. 原生 focus/blur hosted behavior 仅在有真实 OS 自动化证据时称为通过；widget method-channel 测试不等于系统焦点证明。当前 Platform Availability 未声明会操作双窗焦点，需要 scope closeout 单独注明。
7. 通过 `cargo fmt --check`、`bash scripts/build_core.sh`、`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、`cd app && flutter analyze`、`cd app && flutter test`、`bash init.sh`；本 slice 不改性能路径，无需 mem-probe。
8. 完成后同步 docs/03、feature_list、progress、handoff；提交前运行全 scope 与 compare-main GitNexus detect-changes，保留 UNKNOWN/HIGH/CRITICAL 与截断限制。PR #3 必须保持 OPEN/DRAFT，不合并。
