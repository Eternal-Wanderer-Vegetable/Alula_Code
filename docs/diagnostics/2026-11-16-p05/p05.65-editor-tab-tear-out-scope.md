## 范围

- 拖动一个 editor tab，并在当前主窗口外释放时，按既有 `AuxiliaryWindowPayload` 与 `_moveEditorToNewWindow` 路径创建一个新的辅助窗口并移动被拖视图。
- 新窗口创建失败、无效载荷或窗口坐标不可判定时，源文档保持打开，既有 dirty 文本/undo/selection/state 不被丢弃；成功创建后只摘除源组中的该 view 并沿用 session 保存路径。
- 只有确实落在当前主窗口边界之外且未被已有 editor/group/body drop target 接收的释放才能 tear out。窗口内部的空白落点/取消、标签落点、组区落点和 split 落点继续走当前逻辑；同一次 drag 最多创建一个窗口。

## 实现与坐标映射

- `Draggable.onDragEnd` 先清理 tab drag state；只有 `details.wasAccepted == false` 才异步检查释放位置。Flutter `DraggableDetails.offset` 是当前 Flutter view 坐标，不拿它当桌面坐标。新策略先取 `windowManager.getBounds()`，再取 `screenRetriever.getCursorScreenPoint()`；两个原生 API 都以当前引擎 DPR 转换到逻辑屏幕坐标，因此原生窗口标题栏也处于判定矩形内。矩形缺失、空/非有限坐标或插件调用失败均不移动源文档。
- Windows 两个插件都将 `GetWindowRect` / `GetCursorPos` 的物理坐标按同一引擎 DPR 转换；Linux X11 插件返回 GTK screen logical coordinates。GTK Wayland 不提供全局窗口坐标，`gtk_window_get_position` 会返回 `(0, 0)`，所以在 `WAYLAND_DISPLAY` / `GDK_BACKEND` 指示 Wayland 时保守禁用自动 tear-out，用户仍可用既有 Move to New Window 命令；依据：[GTK `Gtk.Window.get_position`](https://docs.gtk.org/gtk3/method.Window.get_position.html)。`screen_retriever` 0.2.2 的 macOS 实现以最低显示器上沿为 cursor Y 原点，而 `window_manager` 以主显示器上沿为 bounds 原点；`EditorTabTearOutPolicy.alignMacOSCursorWithWindowBounds` 用 `getAllDisplays` 的可见区几何恢复偏移，无有效显示器几何时按未知位置保留源文档。包含负坐标、四边、DPR 缩放和 macOS 主屏下方副屏用例。
- `details.wasAccepted` 覆盖已有 tab/group/body/split target；对未接收释放，只在屏幕指针严格落于窗口矩形外时复用 `_moveEditorToNewWindow(group, doc)`。该方法继续负责 flush、`AuxiliaryWindowPayload`、新窗 show、创建失败保留源 view、成功关闭源 view与 session 保存；调用只在本次 drag 的 `onDragEnd` 中触发一次。新的直接 `screen_retriever` 依赖和 Flutter 生成的 Linux/macOS/Windows registrant 更新随代码提交。
- `app/test/editor_tab_tear_out_test.dart` 共 12 项：Linux X11/Wayland 坐标能力、窗口内/外边缘、负坐标、DPR、无效几何、macOS 垂直显示器对齐；widget 覆盖 dirty 文档 payload、唯一创建、已接收 editor drop、标题栏内未接收释放、窗口创建失败、pointer 坐标失败。聚焦套件 12/12 通过。
