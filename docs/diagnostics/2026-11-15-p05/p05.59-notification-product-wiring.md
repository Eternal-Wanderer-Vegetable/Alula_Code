# P05.59 / feat-111 / LAY-18c — 通知产品接线（会话 journal 写入失败、文档保存失败）

## 拆分说明

docs/11 LAY-18 验收面要求通知能力与真实工作台状态一致，而不是只有孤立组件。P05.57 交付
通知基础设施（toast/中心/DND），P05.58 交付进度与 banner；本切片把通知接到两个已有、
可确定性触发的产品失败路径：**会话 journal 写入失败**与**文档保存失败**。

## 登记范围

- 会话 journal 写入失败：`_scheduleStateSave` 保存失败且从「正常」跃迁到「失败」时，
  通过 `NotificationCenter.notify` 发 warning 通知（source `工作台`），动作「重试保存
  会话」重新触发 `_scheduleStateSave`；同一失败streak 内不重复发（跃迁去重），恢复后
  再次失败才重新通知。
- 文档保存失败：`_saveDocToPath` 捕获 `AlulaException` 且 `(documentId, code)` 跃迁为
  新失败时发 error 通知（source `文件`），动作「另存为…」调用 `_saveAsDoc(doc)`；
  同一文档同一错误码不重复发，成功保存后清除该文档的失败记录。
- 既有 UI 保持不变：`journal-save-error-banner`、状态栏详情、`external-save-as` 对话框
  全部保留（P02 回归不变）。
- 不新增命令；通知动作复用现有保存/另存为入口。

## 实现

- 会话 journal：`_scheduleStateSave` 的定时器回调在 `save()` 返回 false 时设置
  `_journalSaveError`（保持既有 in-group 横幅）并调用 `_notifyJournalSaveFailure()`；
  后者用 `_journalFailureNotified` 做失败 streak 去重，发一条
  `WorkbenchNotificationSeverity.warning`（source `工作台`）通知，动作「重试保存会话」
  重新触发 `_scheduleStateSave`；保存恢复后重置去重标记（下次失败会重新通知）。
- 文档保存：`_saveDocToPath` 的 `on AlulaException` 分支在既有 `setState`（状态栏 +
  `DiskDocumentState.readOnly`）之后调用 `_notifySaveFailure(doc, e)`；按
  `documentId:code` 记录已通知集合，同一文档同一错误码不重复；通知为 error
  （source `文件`），动作「另存为…」调用既有 `_saveAsDoc(doc)`；保存成功时
  `_clearSaveFailureNotification(doc)` 清除该文档的所有失败记录。
- 既有 UI 不变：`journal-save-error-banner`、`journal-recovery-banner`、状态栏详情、
  `external-save-as` 横幅与另存为对话框全部保留，P02 只读保存回归未受影响。
