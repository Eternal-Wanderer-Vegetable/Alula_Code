# 诊断报告：2026-10-25 白屏现象（2026-10-26 复查后已修正结论）

## 现象（2026-10-25）

MVP 构建与测试全部通过后做 GUI 冒烟：`alula_app.exe` 正常启动、进程存活、
`alula_core.dll` 确认加载（模块枚举验证），但 GDI 截屏（CopyFromScreen /
PrintWindow）中**客户区渲染为纯白**。

## 当日排查（排除项仍然有效）

| 实验 | 结果 |
|---|---|
| `flutter analyze` + `flutter test`（14 项，含真实 DLL 集成） | 全绿 |
| Impeller-GL（3.47 默认）/ Skia-GL（runner 传 `set_impeller_switch(Disabled)`）/ 软件渲染 / ANGLE 平台覆盖（d3d11on12、d3d9） | 全部截屏为白 |
| Debug 与 Release 两种构建 | 均白 |
| 置顶窗口枚举 | 无窗口遮挡，白屏区即应用客户区 |
| **未经修改的官方 Flutter 模板应用（对照组）** | **同样白** |
| **WPF 探针（独立呈现栈）** | **同样白** |

## 2026-10-26 复查（修正结论）

次日以**完全相同的方式**（直接启动 Release exe + GDI 截屏）重新验证：

1. 应用渲染**完全正常**：暗色主题、工具栏、编辑区初始内容全部正确
   （像素采样 `#14161A`/`#1B1E24` 与设计值精确一致，见 `today_gdi.png`）；
2. 交互闭环验证通过：模拟点击聚焦 + SendKeys 键入后，状态栏显示
   **「已同步 v10（1 op，33 µs）」**、右下角「ABI v1 · 同步 8 次」
   （见 `fullscreen_after_typing.png` / `interactive_sync.png`）——
   键盘输入 → diff 增量 → FFI → Rust 应用 → 版本回执全链路在真实 GUI 中工作；
3. 意外收获：键入文本经过系统中文输入法（"alula" 被转为「阿噜啦」），
   IME 路径的增量同步同样正常。

## 最终结论

1. **应用本身从未存在渲染缺陷**——昨日白屏现象在次日以相同方法复验不再出现，
   且当日交互验证完整通过。
2. 昨日的白屏是**当时系统整体的暂时性呈现状态异常**：独立框架（Flutter 全后端、
   WPF）与官方模板同时受影响，说明问题在系统图形栈层面而非应用层；
   具体诱因无法事后定位（当晚至次日之间系统状态恢复，可能为驱动重置/重启等）。
   **初版报告将其归因于「模型推理负载」属于未经证实的推测**——经用户指正，
   排查期间并未运行模型，该归因不成立，予以撤回。
3. 保留的工程价值（已纳入风险登记册 R12 与设计要求）：
   - 呈现层故障期间应用进程稳定、缓冲区无损——「渲染失败不阻断编辑与保存」
     的架构原则得到一次真实演练；
   - 后续应增加「呈现异常检测 + 明确提示」与软件渲染后备
     （注意 Flutter 3.47 中 `--enable-software-rendering` 与 Impeller 互斥，
     需同时 `--no-enable-impeller`）；
   - 自动化 GUI 测试注意 Win11 24H2+ 的 GDI 截屏坐标受 DPI 虚拟化影响，
     需按物理像素处理（本次截屏区域偏移即由此导致）。
