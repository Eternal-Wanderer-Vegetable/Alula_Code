## Reference behavior

The pinned `src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts` defines `mergeEditor.acceptAllCombination`, category Merge Editor, title “Accept All Combination”, and `f1: true`. It iterates modified base ranges inside one observable transaction. It skips unrecognized state, any state already including Input 1, state already including Input 2 only when `mergeEditor.shouldUseAppendInsteadOfAccept` is true, and ranges where `canBeCombined` is false. The pinned default for that configuration is false. Eligible ranges set both inputs with smart combination enabled. The model determines a smart candidate by sorting edits against the common base, returning no combination when edits overlap or cannot be mapped safely.

Alula already has a bounded stateless v40 candidate FFI and a Rust-backed result document. This slice connects that candidate API to one active MergeResultSession action. The MergeProjection exposes conflict ranges only; non-conflicting changes are already present in its initial result and need no additional operation. Combination is applied only to conflicts with a non-null candidate.

## Acceptance criteria

- Register exact action id `mergeEditor.acceptAllCombination`, title and Merge Editor category in the Command Palette/F1 action registry; expose it only while a current Merge Editor session is active.
- For each conflict in the current projection, skip a prior combination and any resolution already including Input 1. With the pinned default append setting (false), an Input 2-only resolution may be replaced by the smart candidate. A null candidate leaves that conflict's prior result/state unchanged.
- Compute candidates into local temporary state first. If any bounded FFI call fails (including the per-candidate 2 MiB planner input/work limits), apply none of the candidates and preserve exact Rust text, versions, selection, undo history, dirty/savepoint and view contents.
- If one or more candidates exist, produce one session edit plan and apply all replacements through the existing single Rust `TextOp` / undo path. Mark combination conflicts as resolved, update all subsequent UTF-16 conflict ranges, and preserve the combined result through undo/redo reconciliation and save/discard state.
- Already-combined state behaves as both inputs included: active side-accept commands do not replace it. Existing side-accept-all commands preserve a combination already accepted.
- No candidate is a no-op. Externally changed/stale ranges reject the action before any FFI candidate work or document mutation.
- Tests cover multiple compatible and incompatible conflicts, existing Input 1 and Input 2 states, repeat invocation, non-BMP/CRLF/BOM or zero-width conflict ranges, bounded FFI failure with no partial application, undo/redo, split synchronization, dirty/savepoint and save/read-back, and active-session Command Palette availability.
