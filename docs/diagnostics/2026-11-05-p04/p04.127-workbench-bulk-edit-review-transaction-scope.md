# P04.127 / EDT-20e — Workbench Bulk Edit review through the atomic transaction

**State:** Scope registered; implementation pending.
**Feature:** `feat-052`, dependent on `feat-051` (and P02.7 transaction contract).
**Reference:** Code-OSS 1.145.0, commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.

## Purpose

P04.123–P04.126 provide a bounded, selectable Bulk Edit review route, but it is not connected to the Workbench's existing version-checked, atomic multi-document application path. This child adds the Workbench integration entry: freeze the currently open document snapshots, show the review route, and pass only the selected edit through the existing Workbench/Rust transaction callback.

The source review confirmed that `WorkbenchPage.applyWorkspaceEdit` already plans against open-document snapshots, checks each planned before-text, sends all document operations in one `AlulaCore.applyWorkspaceEdit` FFI transaction, and updates each document's undo history, version, views, dirty state, and syntax after success. P04.127 composes that existing path; it does not replace its transaction contract.

## Scope and contract

- Add `reviewWorkspaceEdit(WorkspaceEdit edit)` to the Workbench state as the integration entry for a text-only review. Flush pending input composition as the existing apply path requires, then freeze versioned snapshots of the currently open documents and open `showBulkEditPreview`.
- Route Apply to the existing Workbench `applyWorkspaceEdit` method with exactly the immutable selected `WorkspaceEdit`. The Rust FFI transaction remains the single all-document commit point; do not mutate document text, undo, dirty state, or disk before Apply.
- Close the review only after the transaction returns success. Planning/version/permission/FFI failures leave the route open and must not apply a partial subset. Discard and Escape never call the transaction.
- Preserve current per-document undo/redo, version updates, sibling-view refresh, dirty/savepoint, syntax refresh, and save behavior. Keep selection, snapshot, and transaction URI/version order stable.
- Do not add a Code Action, refactor, rename, command-palette item, menu, or other WorkspaceEdit producer in this child. Exact repository search currently finds no production producer; the new entry is the integration seam for a later producer slice. Do not add file create/delete/rename operations, Rust/FFI/ABI changes, or numeric memory optimization.

## Definition of done

Focused Workbench widget tests must drive the real review route and transaction with two temporary workspace documents and multiple edits per document:

1. Review displays the expected resources and selected edits. Deselecting one edit and applying sends only the chosen edits, through one atomic multi-document transaction; Rust-authoritative text and versions match the projected result, and the unselected edit is unchanged.
2. Both changed documents become dirty. Each document retains its own undo/redo entry; undo/redo restores the correct per-document text. Save each document and verify disk readback.
3. Discard/Escape leaves text, versions, undo, dirty state, and disk unchanged and never calls Apply.
4. If an open document changes after review opens, Apply fails closed, the route remains visible, and none of the requested batch is partially applied. The independently induced intervening edit remains intact.
5. Cover stale version, UTF-16/emoji/CRLF and immutable source input as applicable to the route and planner.
