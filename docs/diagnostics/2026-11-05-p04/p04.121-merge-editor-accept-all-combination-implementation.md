## Implementation

- Registered `mergeEditor.acceptAllCombination` in the existing F1/Command Palette action registry with the pinned title and Merge Editor category. It is visible and enabled only in the active, non-stale Merge Editor context.
- `MergeResultSession.planAcceptAllCombinations()` asks ABI v40 for each eligible conflict, skips Input 1 and already-combined conflicts, leaves null candidates unchanged, and stages all successful candidates before constructing one edit plan. A candidate error throws before any plan or Rust document mutation.
- Combined conflict text is overlaid onto the existing Rust projection with UTF-16 range shifts and represented by session-only metadata; the Rust ABI and wire format are unchanged. The plan uses the existing single Rust `TextOp`/undo route. Undo/redo reconciliation, saved-result/discard state, split views, conflict navigation and side-accept actions preserve or recognize combined conflicts.
- Repeated smart-combination history is bounded to 32 snapshots and at most 8 Mi UTF-16 code units of retained candidate text, while preserving the initial unresolved and current snapshots. Active session input remains subject to its existing 8 MiB UTF-8 cap. This is a bounded-state safeguard, not the deferred numeric memory-optimization phase.
