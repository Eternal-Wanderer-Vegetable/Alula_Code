## Implementation

- Added the stateless Rust C JSON export `alula_merge_combination_candidate_json`; it accepts `base`, `input1`, and `input2`, delegates to `editor_merge::combine_conflict`, and retains no session or document state.
- Bumped the Rust ABI and Dart handshake from v39 to v40. Dart binds the new C symbol, immediately consumes/frees the returned C string through the existing `_takeJson` path, and exposes `AlulaMergeApi.combinationCandidate` as `String?`.
- A successful envelope has `ok: true` and `candidateText` as a complete string or null. Parse, input-byte, trace, work, and response serialization failures use an error envelope; no error response includes a candidate.
- Enforced a 16 MiB JSON request cap, the planner's default 2 MiB combined UTF-8 input / 1,000,000 trace-cell / 2,000,000 work-operation limits, and a 32 MiB serialized response cap. `BoundedJsonWriter` discards the entire candidate response if serialization exceeds the cap.
- Existing `MergeProjection` JSON, document/session state, conflict resolution, undo/save, Workbench UI/actions, and telemetry were not changed. Accept All Combination remains a later slice.

The 32 MiB response cap cannot be reached through a valid current planner request because the complete candidate is bounded by 2 MiB of combined input. The Rust unit test therefore exercises the exact production response serializer with a one-byte test limit and verifies a complete `ResponseTooLarge` envelope without candidate text. The exported endpoint exercises malformed JSON, unknown fields, request-size, decoded-input, candidate, and no-candidate behavior through the real ABI.
