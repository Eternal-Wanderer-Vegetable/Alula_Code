## Scope and implementation

This slice implements the pinned Code-OSS Merge Editor actions merge.acceptAllInput1 and merge.acceptAllInput2. Each action is available from its corresponding Input 1/Input 2 toolbar and F1 action only while a live Merge Editor session is active and current conflicts exist.

Selecting a side calls MergeResultSession.planAcceptAll(side), then applies the result through the existing _applyMergeResultPlan transaction path. The accepted whole-result change is one Rust TextOp/undo unit and uses the existing split-view synchronization, dirty/savepoint, and save behavior. Disposed sessions, stale projections/ranges, and zero-conflict sessions fail closed or expose disabled actions. This commit does not change Rust, FFI/ABI, or the initial result contract.

The fixed upstream reference is [Code-OSS 1.145.0 commands.ts](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts).

## Coverage

Focused tests cover both side actions, multiple conflicts, replacing a mixed set of earlier per-conflict choices, stale/zero-conflict disabled states, and action visibility after session close. The Workbench round trip uses BOM, emoji, and CRLF content; it verifies one-step undo/redo, synchronized split views, save, and disk/Rust workspace read-back.

Explicit exclusions remain Accept All Combination/smart merge, Complete Merge, Git conflict-marker discovery, Rust/ABI changes, numeric memory optimization, Apple Silicon execution, and native macOS DnD acceptance.
