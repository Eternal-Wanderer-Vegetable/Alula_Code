Alula now has bounded immutable selection and projection models, but no visual Multi Diff viewer or production caller for either model. The existing `SnapshotComparePreview` shows one read-only or editable comparison in a Dialog; it does not navigate several resources and does not provide the upstream transient editor surface. `applyWorkspaceEdit` in the skipped Workbench source is currently `@visibleForTesting`; there is no production Code Action/Bulk Edit route to supply a transaction.

## Scope and contract

Add a new read-only Flutter Multi Diff surface that accepts one validated `BulkEditMultiDiffProjection` and has a public route helper so a later product flow can open it. The surface must:

- Render the frozen resources in projection order in a single-selection resource navigator. Show a stable resource label and the number of selected text edits. Opening a resource switches the main view to that resource's before/after diff; the first resource is selected initially.
- Render the complete `DiffViewModelResult` as paired original/modified line rows, including line numbers, inserted/deleted/modified/unchanged row kinds, and the existing inline word ranges. Keep the source texts read-only and do not create document controllers or edit buffers.
- Use lazy row construction and the projection's existing hard aggregate limits. Do not copy the full set of diff rows into a second unbounded cache. Provide keyboard resource navigation, Escape/close behavior, stable semantics labels, and a responsive narrow layout.
- Preserve resource URI/document identity/version as display metadata. The route is transient and owns no workspace document, file, LSP, or Rust handle.
- Return/close the route without changing the projection, WorkspaceEdit, source snapshots, document text, selections, dirty state, undo history, disk, or workbench document tabs.

This child is the visual component and route API only. It does not implement edit-level checkboxes or selection mutation, a production Code Action/Bulk Edit producer, a Workbench command/menu entry, Apply/Discard controls, application of the WorkspaceEdit, rollback, dirty/undo/save behavior, file create/delete/rename, or Rust/FFI/ABI. Those are later EDT-20 children. Do not claim that the end-to-end Code-OSS Bulk Edit flow is wired or that P04 is complete from this UI component.

## Definition of done

Focused widget tests must open the public route with at least two resources and verify initial ordering, resource switching, diff row kinds and line numbers, inline ranges, keyboard navigation, Escape/close, semantics, narrow layout, and that close leaves all projection inputs unchanged. Include Unicode and CRLF rows, deleted-only/inserted-only resources, empty resource changes where allowed by the projection, and a near-row-budget fixture without eagerly building the whole visible list. No test may start a native window or accessibility reader.

Run the registered local DoD (`cargo fmt --all -- --check`, `bash scripts/build_core.sh`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `flutter analyze`, `flutter test`, and `bash init.sh`) plus PR CI and hosted Linux/Windows/macOS x64 build/launch/package checks.
