The next fixed Code-OSS merge action, Accept All Combination, combines independently edited subranges only when the two sides can be applied to one common base without overlap.

Pinned Code-OSS 1.145.0 source at commit 4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e:

- [commands.ts AcceptAllCombination](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts#L585-L618) scans modified base ranges, skips ineligible/unrecognized/already-Input-1 cases, and accepts both sides only when canBeCombined is true. The default shouldUseAppendInsteadOfAccept value is false.
- [modifiedBaseRange.ts combination eligibility and candidate construction](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/contrib/mergeEditor/browser/model/modifiedBaseRange.ts#L24-L170) orders subrange edits in base coordinates, breaks equal-start ties by input order, and returns no candidate on overlap or invalid range-boundary reconstruction.

## Included

This scope adds one GUI-free helper to crates/editor-merge that accepts a base fragment and both corresponding input fragments and returns either a complete combined candidate or no candidate. It does not mutate a MergeProjection, conflict resolution, document, or Workbench session.

The planner operates only on Unicode scalar boundaries, retains the original UTF-8 text including BOM and line endings, and uses explicit byte, diff-trace, and work limits. It merges only non-overlapping edits relative to the same base. Same-position insertions follow the pinned Input 1 then Input 2 ordering. Overlapping edits, backward ordering, or candidates that cannot be reconstructed inside the original range return no candidate; concatenation and silently selecting one side are forbidden. A resource limit returns a typed CombinationError and never a partial candidate.

## Acceptance evidence required

- Compatible edits on one line and across lines combine to the complete expected text.
- Overlapping replacement/deletion ranges do not combine; no partial projection or fallback-to-a-side result is returned.
- Empty input, unchanged side, duplicate edits, insertion/deletion boundaries, same-position insertions, and final-newline cases have explicit tests.
- BOM, emoji/surrogate pairs, CRLF/CR/LF, and no-final-newline inputs preserve exact bytes; no candidate can split a Unicode scalar.
- Each byte/work/trace cap has a deterministic boundary and over-limit test. Calling the helper leaves all inputs unchanged.
