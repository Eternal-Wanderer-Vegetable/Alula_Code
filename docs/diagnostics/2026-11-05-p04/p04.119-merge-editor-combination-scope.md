## Included

This scope adds one GUI-free helper to crates/editor-merge that accepts a base fragment and both corresponding input fragments and returns either a complete combined candidate or no candidate. It does not mutate a MergeProjection, conflict resolution, document, or Workbench session.

The planner operates only on Unicode scalar boundaries, retains the original UTF-8 text including BOM and line endings, and uses explicit byte, diff-trace, and work limits. It merges only non-overlapping edits relative to the same base. Same-position insertions follow the pinned Input 1 then Input 2 ordering. Overlapping edits, backward ordering, or candidates that cannot be reconstructed inside the original range return no candidate; concatenation and silently selecting one side are forbidden. A resource limit returns a typed MergeError and never a partial candidate.

## Acceptance evidence required

- Compatible edits on one line and across lines combine to the complete expected text.
- Overlapping replacement/deletion ranges do not combine; no partial projection or fallback-to-a-side result is returned.
- Empty input, unchanged side, duplicate edits, insertion/deletion boundaries, same-position insertions, and final-newline cases have explicit tests.
- BOM, emoji/surrogate pairs, CRLF/CR/LF, and no-final-newline inputs preserve exact bytes; no candidate can split a Unicode scalar.
- Each byte/work/trace cap has a deterministic boundary and over-limit test. Calling the helper leaves all inputs unchanged.
- Run focused editor-merge tests, full N.2 local gates, cargo fmt, clippy, core build, Flutter analyze/tests as required by the scope gate, GitNexus staged/all-scope review, PR CI, and record evidence before marking done.

## Explicit exclusions

This is only the pure Rust candidate-planning layer. It does not extend MergeConflict/Projection wire shapes, call the helper from MergeProjection, add a new FFI function or request field, bump the ABI version, modify Dart resolution types/session state, add the mergeEditor.acceptAllCombination F1 action or toolbar UI, implement shouldUseAppendInsteadOfAccept configuration, add telemetry, or change current text. These are separate follow-on slices after this planner is complete.
