# P05.25 / LAY-05d: Panel Maximize and Restore

Status: completed and verified at product commit `c456374` (format-noise cleanup `1188cdf`). This bounded slice does not close LAY-05 or P05.

## Fixed upstream

- Code-OSS `1.145.0-dev`, commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- [`panelActions.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/panel/panelActions.ts#L1499-L1578) registers `workbench.action.toggleMaximizedPanel` (“Toggle Maximized Panel”), exposes it to the Command Palette, uses “Maximize Panel” / “Restore Panel” tooltips, and adds it to the Panel title menu. If the Panel is hidden, the command reveals and maximizes it; otherwise it toggles maximization. The action is available with center alignment or a side position; non-center alignment while the Panel is Top/Bottom is rejected with a warning.
- The pinned [`layout.ts` runtime state](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/layout.ts#L3353-L3383) keeps maximized-part IDs in an in-memory `Set`, separate from persisted layout state. The pinned [`layoutActions.ts` editor visibility action](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/actions/layoutActions.ts#L2570-L2607) delegates to the same `toggleMaximizedPanel` layout operation.
- Matrix requirement: `LAY-05 / parity-lay-05` in `docs/11-VSCode功能对照矩阵.md`; this slice implements Panel maximize/restore only.

## Registered scope

- Register the fixed command ID and title in the View category and Command Palette. Add an accessible maximize/restore action to the Panel tab header, with its label and icon reflecting the transient maximized state.
- Keep maximization as runtime-only `WorkbenchLayout` state. Do not write it to root layout JSON or alter canonical `WbSplit` topology, child order, weights, minimums, or collapsed state.
- When invoked while Panel is collapsed, reveal Panel and maximize it. Invoking again restores the existing layout and leaves Panel visible. Preserve editor, Side Bar, Activity Bar, Panel content state, focus, and all saved layout sizes across both transitions.
- Match the upstream eligibility rule: center-aligned Panel is supported in every position; non-center alignment is supported when Panel is docked Left/Right. Do not expose an enabled title action for non-center Top/Bottom. A direct unsupported invocation must safely leave the layout unchanged.
- Keep the existing editor state mounted while the Panel occupies the available workbench content area. Reuse the current stable region identity and test that editor and Panel state survive hide/show of the underlying workbench projection.

## Explicit exclusions

- Panel position/alignment commands and persistence (completed in P05.22–P05.24); Panel view movement/grouping, drag/drop, sash reset/double-click/minimum-size, floating Panels, editor-group maximize, window maximize, and unrelated side-bar work.
- No Rust, FFI, ABI, or serialized layout schema changes. No GUI/manual desktop acceptance in this slice; CI/headless widget and model checks are the available verification surface.
