# P05.24 / LAY-05c: Panel Alignment Commands and Persistence

Status: registered; pre-edit GitNexus review is complete and no P05.24 product code has been edited. This is a bounded alignment slice and does not close LAY-05 or P05.

## Fixed upstream

- Code-OSS `1.145.0-dev`, commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- [`panelActions.ts` alignment command IDs, labels, View category, Command Palette exposure, and checked submenu state](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/panel/panelActions.ts#L1258-L1456) defines `workbench.action.alignPanelLeft`, `workbench.action.alignPanelRight`, `workbench.action.alignPanelCenter`, and `workbench.action.alignPanelJustify`; the labels are “Set Panel Alignment to Left/Right/Center/Justify”. Each action calls `setPanelAlignment`, and View > Appearance > Align Panel shows the current value as checked.
- [`layout.ts` alignment and reflow behavior](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/layout.ts#L1997-L2085) preserves focus and the visible Panel/Sidebar extents while rearranging regions. Alignment applies only when Panel is Top/Bottom; calling an alignment command while Panel is Left/Right first moves it to Bottom, then applies the alignment. [`layout.ts` state restore](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/layout.ts#L3302-L3335) reapplies persisted `PANEL_ALIGNMENT` changes through `setPanelAlignment`.
- Matrix requirement: `LAY-05 / parity-lay-05` in `docs/11-VSCode功能对照矩阵.md` covers Panel alignment and the related position, maximize/restore, drag/drop, and minimum-size behaviors. This slice covers only alignment state, commands, menus, and persistence.

## Registered scope

- Register the four fixed command IDs and titles in the View category and Command Palette. Add the `View > Appearance > Align Panel` submenu with Left/Right/Center/Justify entries and update its live checked state in Flutter and macOS native menus.
- Represent `left`, `right`, `center`, and `justify` as Panel alignment state in the existing workbench layout model and root layout JSON. Selecting an alignment while Panel is Left/Right must first move it to Bottom, matching Code-OSS; alignment is visually applied only at Top/Bottom. Moving the Panel to a side later preserves the selected alignment for a later return to Top/Bottom.
- At Top/Bottom, arrange the Panel row relative to the Activity Bar, Primary Side Bar, editor, and Secondary Side Bar as fixed Code-OSS does. Preserve existing node identity and contents, Panel visibility/collapse and size state, side-bar widths and focus, root metadata, Activity Bar preferences, and editor groups. Update the Panel position model as needed so position commands continue to work after alignment reflow.
- Confirm the visible Panel geometry follows each alignment at Top and Bottom, and that selecting the active alignment is idempotent. Verify command-palette routing, menu check state, persistence notification, root JSON restore/remount, each alignment action from Left/Right, and subsequent Panel position changes.

## Explicit exclusions

- Maximize/restore behavior and the Panel title menu; Panel view movement/grouping and drag/drop; sash and minimum-size behavior; floating Panels; unrelated sidebar/editor-group work; any FFI/ABI change.
- These remain separate LAY-05 work. P05 remains in-progress.
