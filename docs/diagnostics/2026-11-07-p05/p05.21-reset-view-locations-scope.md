## Registered scope

- Register the exact command ID `workbench.action.resetViewLocations`, display title “Reset View Locations”, in the View category and Command Palette. Invoking the command performs the reset immediately; there is no confirmation or second step.
- For Alula's four built-in Activity Bar views (`explorer`, `search`, `outline`, `git`), restore the default location assignment to the Primary Side Bar and set the default Primary selection to Explorer. Clear the Secondary selection because no built-in view remains assigned there. Normalize legacy layouts that have no explicit location map to this same canonical default.
- Persist the reset through the existing root layout store. Repeated invocation is idempotent and does not create duplicate views, lose an Activity Bar item, or mutate unrelated state.
- Preserve Activity Bar order, pins, badges, Accounts visibility, bar position/size/visibility; Primary/Secondary Side Bar positions, visibility, widths and collapsed state; Panel contents/state; and the editor split tree. A visible Secondary Side Bar may show its existing empty state after its views return to Primary.
- Model tests cover resetting views moved in either direction, old-layout migration, already-default no-op, selection normalization and unrelated-layout preservation. Workbench integration invokes the real Command Palette entry, checks the root JSON persistence boundary, and verifies the state after save/remount.

## Explicit exclusions

- Moving views to Panel, creating or grouping view containers, container/pane collapse, pointer drag/drop, view ordering, reset of Activity Bar pins/order, extension-contributed views, settings/profiles, and sash sizing.
- No Rust/FFI/ABI changes are expected. If implementation requires changing those boundaries, stop and register a revised scope before proceeding.
