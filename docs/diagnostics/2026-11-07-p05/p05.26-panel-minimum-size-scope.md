# P05.26 / LAY-05e: Panel minimum size and split constraints

Status: registered and in progress on 2026-11-07. This bounded slice does not close LAY-05 or P05.

## Fixed upstream and matrix requirement

- Code-OSS `1.145.0-dev`, commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- The pinned [`PanelPart`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/panel/panelPart.ts#L689-L728) declares `minimumWidth = 300` and `minimumHeight = 77`. The Panel minimum is therefore 300 logical pixels when docked Left/Right and 77 logical pixels when docked Top/Bottom. This slice addresses the minimum-size clause in `LAY-05 / parity-lay-05` from `docs/11-VSCode功能对照矩阵.md`.

## Registered scope

- Make the existing weighted split allocator enforce recursive minimum extents during normal layout and viewport resize, as well as during sash drag. A leaf's minimum is interpreted on the current split axis; a nested split's minimum on the same axis is the sum of child minima, and on the orthogonal axis it is the largest child minimum.
- Give an expanded Panel an axis-aware floor: 300px for a horizontal split (Left/Right), 77px for a vertical split (Top/Bottom). Keep collapsed leaves at zero. Preserve user sash weights while viewport resize clamps geometry; only an explicit sash drag writes new weights.
- When available space can satisfy every visible minimum, preserve every lower bound and distribute remaining space using the existing weights. When the viewport is smaller than the combined minima, deterministically compress minima to fit the available extent without producing negative sizes or overflow. Restoring adequate space must return to the saved weighted proportions.
- The existing default Panel minimum was 120px, and generated layouts already persist it as `min: 120`. Treat this one legacy value as the former built-in default and migrate it to 77px; preserve other explicit Panel minima. New default layouts use 77px. Verify save/remount and side-dock width enforcement without changing user weights.
- Cover Top, Bottom, Left, Right, center-alignment projection, nested splits, viewport resize, sash clamping, collapse/restore, legacy JSON migration, custom minima, and the under-constrained viewport fallback with model/widget tests.

## Explicit exclusions

- Panel view movement/grouping/drag-and-drop, sash double-click reset, window-level minimum dimensions, floating Panel, and unrelated LAY-06 reset/restore behavior.
- No Rust, FFI, or ABI changes. No local desktop GUI or Narrator activation; local Flutter widget/model tests and hosted CI/platform runners are the verification surface.
