# P05.20 / LAY-04c: Move Built-in Views between Side Bars

Status: registered; product implementation not started. This slice follows P05.19 / LAY-04b, covers command-driven movement between the Primary and Secondary Side Bars for Alula's built-in Activity Bar views, and does not close LAY-04 or P05.

## Fixed upstream

- Code-OSS 1.145.0 commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- [`layoutActions.ts` at the pinned commit](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/actions/layoutActions.ts) registers `workbench.action.moveView` and `workbench.action.moveFocusedView`. The first picker selects a movable view; the second presents new-entry and existing-container destinations across Side Bar, Panel, and Secondary Side Bar. Selection of a destination calls the view descriptor service to move the view and then opens it.
- [VS Code custom layout documentation](https://code.visualstudio.com/docs/configure/custom-layout) describes moving views through the keyboard commands and between the Primary/Secondary Side Bar; the pinned source commit is the version authority.

## Registered scope

- Add persisted location assignments for the current built-in view IDs: `explorer`, `search`, `outline`, and `git`. Legacy layouts without assignment metadata keep all four in the Primary Side Bar.
- Register the fixed IDs `workbench.action.moveView` and `workbench.action.moveFocusedView` in the Command Palette. The first Quick Input lists the four movable views with their current side and preselects the focused view when one exists. The focused-view command skips that first picker and offers a destination directly.
- Support movement between the Primary and Secondary Side Bars only. The destination picker must not offer the source as a destination; accepting the current location is a no-op. Cancel/Escape at either stage leaves the exact layout state unchanged.
- Update the rendered regions and selection/focus state after a move. Each side retains its own current view; moving the selected view opens it in the destination, and the source selects a remaining view or shows the existing empty state.
- Persist view assignments and each side's selection in the root layout JSON. Preserve Activity Bar order/pins/badges/accounts, Activity Bar placement, sidebar positions, editor split tree, Panel state, visibility, widths, and collapsed state. Validate both primary-left and primary-right layouts.
- Unit/model and widget integration tests cover each built-in view in both directions, no duplicates/loss, filtering/selection/cancellation, focused-view routing, empty-source behavior, JSON migration/round-trip, and remount restoration.

## Explicit exclusions

- Panel movement and grouping a view into an existing view container; these are additional LAY-04 destination cases.
- Pointer drag/drop, reordering views, `Reset View Locations`, split/collapse inside a view container, arbitrary extension-contributed views, and settings/profile behavior.
- Changing Activity Bar pin/order semantics or adding a new view provider.

## Definition of done

1. Pure model tests prove deterministic assignment, validation of unknown/duplicate IDs, and default-primary migration.
2. Quick Input tests prove movable-view and destination choices, selected/focused routing, filtering, keyboard acceptance, Escape/cancel, and no side effects on cancellation.
3. Workbench integration proves the real registered command IDs move each built-in view between the two live regions, maintain exactly one rendered instance, preserve per-side selection and unrelated layout metadata, and restore after save/remount.
4. Run the complete repository DoD and existing Harness/JSON/diff checks. No Rust/FFI/ABI changes are expected; if implementation changes that boundary, register a revised scope before proceeding.
5. Record fresh pre-edit GitNexus impacts after the scope commit, then run all-scope and compare-to-main graph change analysis before every commit. Keep CRITICAL/UNKNOWN/truncation limits visible; do not treat missing edges as clean.
6. Product commit and evidence commit go separately to draft PR #3. Product-head PR CI and Linux/Windows/macOS Intel x64 Platform Availability must pass before marking this item done. Hosted x64 is not physical-device or Apple Silicon acceptance.
