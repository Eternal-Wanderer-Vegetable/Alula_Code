## Registered scope

- Register the two fixed command IDs and titles in the View category and Command Palette. Add Left/Right to the existing `View > Appearance > Panel Position` submenu and update its live checked state in Flutter and macOS native menus.
- Represent Left/Right with a horizontal root split containing the existing Panel leaf and the existing main-workbench subtree. Preserve the Panel leaf and main subtree objects and their state, root-only layout metadata, and all Activity Bar, primary/secondary Side Bar, and editor-group state. Preserve child weights and minimum extents during orientation changes.
- Support switching between Left/Right and the existing Top/Bottom commands. Top/Bottom requires a vertical root; Left/Right requires a horizontal root. The existing serialized root layout remains the only persistence source; no FFI/ABI or secondary state field is added.
- Verify Left/Right in both directions, active-position no-op, Top/Bottom ↔ Left/Right transitions, collapsed/visible Panel, unsupported root-shape no-op, layout JSON round-trip/remount, live menu check state, and preservation of Activity Bar placement/size/order/pins/badges/Accounts, both Side Bars, and editor groups.

## Explicit exclusions

- Panel alignment (Center/Justify/Left/Right), maximize/restore, title context menu, drag/drop or moving/grouping Panel views, sash/minimum-size behavior beyond preserving existing extents, floating layout, and any unrelated Activity Bar/Side Bar/editor-group behavior.
- These remain separate LAY-05 work. P05 remains in-progress.

### Design decision

Keep the existing root `WbSplit` instance and its direct child nodes. Make its axis mutable so Top/Bottom ↔ Left/Right only changes root orientation and Panel edge order; this preserves root-only metadata, sibling and editor subtree identity, weights, minimum extents, and collapse state without adding a second persistence field. Unsupported nested/middle Panel shapes remain no-ops.
