- Reference: Code-OSS 1.145.0, commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- [`auxiliaryBarPart.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/auxiliarybar/auxiliaryBarPart.ts) implements the Auxiliary Bar as a pane-composite part at `ViewContainerLocation.AuxiliaryBar`, with sidebar dimensions and title/menu infrastructure.

## Registered scope

- Add a `secondarySidebar` region after the editor in the main horizontal layout. It is collapsed by default (not rendered and does not reduce the current default editor width), has a minimum width, and expands to the right of the editor when toggled on.
- Register the upstream command ID `workbench.action.toggleAuxiliaryBar` and Ctrl/Cmd+Alt+B, plus an accessible title-bar layout toggle with checked state. The action must show/hide the region and persist through the existing root layout JSON.
- Render an explicit, keyboard/accessibility-readable empty state while the region has no assigned views. Do not imply that view movement is already available.
- When loading earlier saved layouts without this leaf, insert a collapsed secondary-sidebar leaf adjacent to the editor while preserving the existing Activity Bar, primary sidebar, editor groups, panel, weights, and other metadata.
- Validate default-hidden geometry, explicit show/hide, sizing and collapse memory, serialization/reload, legacy migration, and workbench command/menu integration.

## Excluded from this slice

- Assigning, moving, splitting, or reordering view containers between primary and secondary side bars.
- Moving primary/secondary side bars between left and right, and configurable defaults beyond the fixed default-right secondary position.
- Secondary side bar maximize/restore, multiple view containers, drag/drop, profile separation, or new view providers.
- LAY-04 completion, remaining P05 layout requirements, and P05 completion.
