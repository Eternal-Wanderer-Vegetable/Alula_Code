# P05.18 / LAY-04a: Secondary Side Bar Foundation

Status: implementation, local DoD, product-head PR CI, and Linux/Windows/macOS hosted build/launch/package evidence complete. This slice is one child of LAY-04 and does not close LAY-04 or P05; physical-device validation remains outside this hosted evidence.

## Fixed upstream and source behavior

- Reference: Code-OSS 1.145.0, commit `4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e`.
- [`auxiliaryBarPart.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/auxiliarybar/auxiliaryBarPart.ts) implements the Auxiliary Bar as a pane-composite part at `ViewContainerLocation.AuxiliaryBar`, with sidebar dimensions and title/menu infrastructure.
- [`auxiliaryBarActions.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/parts/auxiliarybar/auxiliaryBarActions.ts) registers `workbench.action.toggleAuxiliaryBar`, gives it Ctrl/Cmd+Alt+B, and exposes the secondary side bar visibility action in the layout/appearance menus.
- [`layoutActions.ts`](https://github.com/microsoft/vscode/blob/4bda7217fc83e8e838b1edd9ebaf21bb9b498c7e/src/vs/workbench/browser/actions/layoutActions.ts) uses the shared side bar location setting to move the primary and secondary side bars to opposite sides.

## Registered scope

- Add a `secondarySidebar` region after the editor in the main horizontal layout. It is collapsed by default (not rendered and does not reduce the current default editor width), has a minimum width, and expands to the right of the editor when toggled on.
- Register the upstream command ID `workbench.action.toggleAuxiliaryBar` and Ctrl/Cmd+Alt+B, plus an accessible title-bar layout toggle with checked state. The action must show/hide the region and persist through the existing root layout JSON.
- Render an explicit, keyboard/accessibility-readable empty state while the region has no assigned views. Do not imply that view movement is already available.
- When loading earlier saved layouts without this leaf, insert a collapsed secondary-sidebar leaf adjacent to the editor while preserving the existing Activity Bar, primary sidebar, editor groups, panel, weights, and other metadata.
- Validate default-hidden geometry, explicit show/hide, sizing and collapse memory, serialization/reload, legacy migration, and workbench command/menu integration.

## Excluded from this slice

- Assigning, moving, splitting, or reordering view containers between primary and secondary side bars.
- Moving primary/secondary side bars between left and right, and configurable defaults beyond the fixed default-right secondary position.
- Secondary side bar maximize/restore, multiple view containers, drag/drop, profile separation, or new view providers.
- LAY-04 completion, remaining P05 layout requirements, and P05 completion.

## Definition of done

1. Model and migration tests prove old layouts gain a hidden secondary region without changing existing state; JSON round-trip preserves visibility and adjusted width.
2. Grid/widget tests prove hidden-by-default geometry, visible region to the editor's right, empty-state content/semantics, and toggle/restore behavior.
3. Command/keybinding/title-bar tests prove `workbench.action.toggleAuxiliaryBar`, Ctrl/Cmd+Alt+B, checked state, and layout persistence.
4. Run the complete repository DoD: `cargo fmt --all -- --check`, `bash scripts/build_core.sh`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `flutter analyze`, `flutter test` from `app/`, and `bash init.sh`; also run Harness/JSON/diff checks used by this branch.
5. Run GitNexus change analysis before each commit. Preserve and report the graph's lower-bound/UNKNOWN limitations. Product and evidence commits go separately to PR #3. Hosted PR CI and Linux/Windows/macOS Intel x64 Platform Availability must pass before this item is marked done; platform x64 hosted evidence is not local device acceptance.
